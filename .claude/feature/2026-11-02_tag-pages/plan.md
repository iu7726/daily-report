## 0. TL;DR

- 보고서 frontmatter의 `tags`로 태그 목록(`/tags`)과 태그별 페이지(`/tags/[slug]`)를 정적으로 만든다.
- 표기가 조금씩 다른 태그(`Node.js`, `node.js`, `NodeJS`)는 같은 주소로 합친다.
- 보고서가 1건뿐인 태그 페이지는 만들되 검색엔진 색인에서는 뺀다(`noindex`). 2건 이상부터 색인하고 sitemap에 넣는다.
- 상세 페이지의 태그를 링크로 바꾸고, 홈에 "자주 다룬 주제"를 둬서 내부 링크를 만든다.

## 2. 결정 사항 (확정, 사용자 2026-11-02)

- **D1. 주소 규칙(slug)**: 소문자로 바꾸고, 점(`.`)과 `&`는 지우고, 공백·`_`·`/`는 `-`로 바꾸고, 글자·숫자·`-`·`+` 외의 문자는 지운다. 한글은 그대로 둔다.
  - `Node.js`, `node.js`, `NodeJS` → `/tags/nodejs`
  - `Claude Code` → `/tags/claude-code`, `미국 국채` → `/tags/미국-국채`
  - `CVE-2026-111497` → `/tags/cve-2026-111497`, `S&P500` → `/tags/sp500`
  - 점을 지우는 이유: `Next.js`/`NextJS` 같은 흔한 표기 차이를 합치고, 주소 끝이 `.js`처럼 파일 확장자로 보이는 문제를 피한다.
- **D2. 표시 이름**: 같은 slug로 합쳐진 표기 중 가장 많이 쓰인 것. 같으면 최근 보고서의 표기.
- **D3. 색인 기준**: 보고서 2건 이상인 태그만 색인하고 sitemap에 넣는다. 1건짜리 태그 페이지는 `noindex, follow`로 만든다(링크는 살리되 검색 결과에는 내지 않음).
- **D4. 화면**
  - `/tags`: 전체 태그와 보고서 수. 많이 쓰인 순.
  - `/tags/[slug]`: 태그 이름, 관련 보고서 목록(최신순, 작업 이름 표시).
  - 상세 페이지 태그 → 태그 페이지 링크
  - 홈: "자주 다룬 주제"(보고서 2건 이상인 태그 상위 12개). 아직 없으면 섹션을 숨긴다.
  - 헤더 메뉴에 "태그" 추가
- **D5. 페이지 메타**: 제목 `{태그} 관련 브리핑`, 설명은 "{작업 이름들}에서 {태그}를 다룬 보고서 N건" + 최신 보고서 headline.
- **D6. 루틴 규칙 보강**: `scheduler/CLAUDE.md`의 `tags` 설명에 "이전 보고서에 같은 대상의 태그가 있으면 그 표기를 그대로 쓴다"를 추가한다. slug로 합치지 못하는 표기 차이(`Postgres`/`PostgreSQL`)를 줄이기 위함이다.
