### 1. Gemini 4 Neon 정식 출시 — $3/$15, Office 파일 직접 입력

Google이 11월 18일(미국 날짜) Gemini 4 Neon을 내놓았습니다. 어려운 장기 작업용 Carbon과 빠른 일상 작업용 Hydrogen 사이에 놓이는 모델로, 복잡한 코딩·분석과 도구를 많이 쓰는 에이전트 작업을 겨냥합니다. Google은 high 설정에서 작업당 비용이 Carbon보다 32% 낮다고 밝혔습니다.

| 항목 | 값 |
|---|---|
| 모델 코드 | `gemini-4-neon` |
| 가격 (100만 토큰, 유료 등급) | 입력 $3 / 캐시 입력 $0.15 / 출력 $15 |
| 컨텍스트 | 1M 토큰 |
| 최대 출력 | 변경 이력 기준 최대 1M 토큰 (모델 문서 표기는 64K / 1M) |

> Gemini Carbon으로 코드 리뷰·리팩터링 에이전트를 돌리는 Node 백엔드라면 모델 이름만 `gemini-4-neon`으로 바꿔 같은 작업의 품질과 비용을 비교해 볼 만합니다. 엑셀 업로드를 받아 요약하는 기능이 있다면 직접 변환하던 단계를 빼고 필요한 시트·셀 범위만 보내도록 줄일 수 있습니다.

### 2. GitHub Copilot — Gemini 4 Neon, MCP 커넥터 8종, 팀 단위 플러그인 기본값

GitHub가 11월 18일 Copilot에 Gemini 4 Neon을 추가했습니다. Pro+, Max, Business, Enterprise에 순차 배포되고, 사용량 기반 요금제에서 제공사 정가로 과금됩니다. Business·Enterprise는 관리자가 막지 않았다면 자동으로 켜집니다.

같은 날 Box, Buildkite, Calendly, ClickUp, Mixpanel, Supabase, Webflow, Wix를 Copilot 커넥터로 연결하는 기능이 모든 요금제에 공개 미리 보기로 나왔습니다. GitHub가 검증한 MCP 서버이고, Copilot CLI에서는 `/mcp`의 Connectors 탭에서 연결합니다. Business·Enterprise는 Editor preview features 정책을 켜야 하고, MCP 허용 목록을 와일드카드 없이 이름으로 관리하는 기업은 새 커넥터를 목록에 추가해야 합니다.

팀 단위 Copilot 맞춤 설정도 Business·Enterprise에 정식 출시됐습니다. 조직 팀 페이지의 "Customize Copilot" 탭에서 승인된 Agent Plugin을 골라 두면 팀의 직접 구성원에게 VS Code, Copilot 앱, Copilot CLI에서 기본으로 켜집니다. 하위 팀에는 상속되지 않습니다.

> Supabase를 쓰는 백엔드 팀이라면 커넥터로 Copilot 에이전트가 DB 스키마·로그를 직접 보게 할 수 있지만, 미리 보기 단계이니 운영 프로젝트 대신 개발 프로젝트에 먼저 연결하세요. NestJS 팀 공통 규칙을 플러그인으로 묶어 두었다면 팀 기본값으로 지정해 새 팀원의 설정을 줄일 수 있습니다.

### 4. LangChain.js `langchain` 1.6.7 — 런타임 모델 교체 기본 차단

11월 19일 07:30 KST(npm 게시)에 `langchain` 1.6.7이 나왔습니다. `initChatModel`에 모델을 지정하고 `configurableFields`를 넘기지 않았거나 `ConfigurableModel`을 직접 만든 경우, 이제 호출 시점의 `configurable.model`·`configurable.modelProvider`로 모델이 바뀌지 않습니다. 문서에 적힌 동작에 맞춘 수정입니다.

`humanInTheLoopMiddleware`가 `reject`·`respond` 결정으로 만든 도구 메시지에는 `lc_source: "hitl_interrupt_decision"`과 결정 내용이 붙습니다.

> 요청마다 `config.configurable.model`로 모델을 바꿔 부르던 NestJS 서비스라면, 1.6.7에서는 오류 없이 처음 지정한 모델만 쓰게 됩니다. 계속 바꿔야 한다면 `configurableFields: ["model", "modelProvider"]`를 명시하세요. 반대로 클라이언트 입력이 `configurable`로 흘러들던 구조라면 이번 변경으로 모델을 임의로 바꾸는 경로가 막힙니다.

- 발표: 2026-11-18(미국 날짜) · [langchain CHANGELOG](https://github.com/langchain-ai/langchainjs/blob/main/libs/langchain/CHANGELOG.md)

## 주목할 Agent Skills

전체 순위 상위권은 영상 제작·마케팅 스킬이 대부분이라, 오늘 `ai` 7.0.177이 패키지에 직접 넣기 시작한 공식 스킬을 골랐습니다. 이전 보고에서 다루지 않았습니다.

### `ai-sdk` (vercel/ai)

에이전트가 Vercel AI SDK 코드를 쓸 때 기억에 의존하지 말고, 설치된 버전의 `node_modules/ai/docs/`와 소스를 먼저 읽게 하는 스킬입니다. `generateText`, `streamText`, `ToolLoopAgent`, 도구 호출, 구조화 출력, `useChat` 같은 키워드에 반응하고, 모델 ID도 AI Gateway 모델 목록을 조회해 고르도록 안내합니다. 작업 뒤에는 타입 검사를 돌리라고 합니다.

| 항목 | 값 |
|---|---|
| 설치 수 | 70.9K (확인 2026-11-19 08:46 KST, skills.sh 표시값) |
| 처음 등록 | 2026-01-23(skills.sh 첫 확인일), 신규 아님. npm 패키지 동봉은 7.0.177부터 |
| 보안 감사 | Gen Agent Trust Hub·Socket Pass, Snyk Warn (경고 내용은 확인 불가) |

- 원문: [skills.sh](https://skills.sh/vercel/ai/ai-sdk) · [ai CHANGELOG](https://github.com/vercel/ai/blob/main/packages/ai/CHANGELOG.md)
- 설치: `npx skills add https://github.com/vercel/ai --skill ai-sdk`

> AI SDK는 버전마다 API 이름이 자주 바뀌어, 에이전트가 예전 문법으로 NestJS 서비스 코드를 쓰는 일이 잦습니다. 이 스킬은 그 실수를 줄여 주지만, `ai`가 없으면 패키지를 설치하고 `curl`로 외부 모델 목록을 조회하라고 지시하니 설치·네트워크 명령은 권한 확인을 거치게 두세요. AI Gateway를 쓰지 않는 팀이라면 Gateway 사용을 권하는 부분은 무시하도록 프로젝트 지시문에 적어 두는 편이 좋습니다.
