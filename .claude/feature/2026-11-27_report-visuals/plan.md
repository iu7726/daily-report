# 보고서 그림과 추이 차트 — 기획서

> 상태: **구현 중 (2026-11-27)**. 사이트·작업 파일·검사 스크립트 수정과 로컬 검증 완료
> 남은 것: 배포 다음 날 아침 보고서 확인
>
> 구현 변경점 (계획 대비):
> - 숫자 추이는 P1·P2·P3를 한 차트에 쌓지 않고 지표마다 따로 그렸다. 상태 색(빨강·주황·노랑, 빨강·주황·회색)을 계열 구분에 쓰면 dataviz 검증에서 정상 시각 구분 하한(ΔE 15)과 밝기 범위를 넘지 못했다. 상태 색은 수준 띠와 배지처럼 글자가 함께 붙는 곳에만 쓴다.
> - 우선순위 배지는 사이트의 수준 배지와 같은 방식으로 P1 빨강, P2 주황, P3 회색이다. "이상 없음"은 배지 없이 글자로 둔다.
> - 자주 나온 태그는 기간 안에 2편 이상 나온 것만 상위 8개를 그린다.
> - 검사 스크립트는 timeline·flow 블록 글자를 분량에 넣고 명령 코드 블록만 뺀다. 이 컴퓨터의 Python 3.9에서 `str | None` 표기가 오류를 내서 `from __future__ import annotations`를 넣었다.
> - 문체 기획서의 보안 샘플에 `metrics`, `trend`, `timeline`, `flow`를 넣었다. ① 항목은 흐름도로 바꾸면서 같은 내용을 설명하던 문장을 덜어 냈다.
> - 시험 실행에서 휴장일 S&P500 보고서가 값 없는 지표 타일 세 개를 만들어서, 값이 없는 지표는 타일을 빼고 모두 비면 한 줄 안내만 보여 주게 했다. `trend` 차트가 비어 있는 동안에는 판단 근거가 된 흐름을 문장으로 써도 되게 했다.

## 0. TL;DR

보고서가 글과 표로만 되어 있다. md 형식은 그대로 두고 세 가지를 더한다.

1. **보고서 안 그림**: 루틴이 데이터만 담은 코드 블록(`timeline`, `flow`, `trend`)을 쓰면 사이트가 그림으로 그린다. 표와 소제목의 P1·P2·P3는 색 배지로 보여 준다.
2. **작업별 추이**: 목록 페이지에 최근 30일 수준 띠, 자주 나온 태그, 숫자 추이를 그린다. 수준과 태그는 지금까지 쌓인 117편으로 바로 그린다.
3. **숫자 기록**: 루틴이 frontmatter `metrics`에 그날 확인한 숫자를 남긴다(보안 P1·P2·P3 건수, S&P500 지수·금리·환율). 추이는 이 값으로만 그려서 AI가 과거 수치를 다시 쓰거나 지어낼 일이 없다.

## 1. 범위

- 포함: 사이트 렌더링(블록, 배지, 차트), 작업별 목록 페이지의 추이, frontmatter `metrics`, 작업 파일의 블록·`metrics` 규칙, 검사 스크립트의 블록·`metrics` 검사
- 제외
  - 지난 보고서의 숫자를 뽑아 `metrics`를 채우는 일: S&P500 보고서는 날마다 숫자를 쓰는 문장 형식이 달라서 자동으로 뽑으면 틀린 값이 섞인다. 추이는 배포한 날부터 쌓는다.
  - 클라이언트 차트 라이브러리: 정적 생성 SVG로 그리고, 마우스를 올리면 SVG `<title>`로 값을 보여 준다.

## 2. 현재 (사실 확인, 2026-11-27)

- 보고서 본문은 `react-markdown` + `remark-gfm`으로 그리고, 원시 HTML은 렌더링하지 않는다(보고서 사이트 기획서 D4). 코드 블록은 `<pre><code class="language-…">`로 나온다.
- 모든 보고서(117편)에 `level`과 `tags`가 있다. 보안 35편 중 `urgent` 25편, AI 39편 중 16편, S&P500 43편 중 7편이다.
- 자주 나온 태그: 보안은 Node.js 14, AWS 14, npm 12, GitLab 11, GitHub Actions 10편, AI는 Agent Skills 26, Claude Code 25, MCP 16, Gemini CLI 14편이다.
- 작업별 목록 페이지(`app/[task]/page.tsx`)에는 제목, 설명, 보고서 목록만 있다. 홈 달력은 날짜마다 수준을 점으로 보여 준다.
- 다크 모드는 `prefers-color-scheme`으로 `:root` 색 변수를 바꾼다.
- 색 검증(dataviz 검증 스크립트): 파란색 단일 계열(밝은 화면 `#257de0`, 어두운 화면 `#338ced`)은 모두 통과한다. 상태 색(빨강·주황·노랑 또는 빨강·주황·회색)을 누적 막대 계열 구분에 쓰면 정상 시각 구분 하한(ΔE 15)과 밝기 범위에서 실패한다.

## 3. 결정 사항

### 확정 (사용자 2026-11-27)

- D1. md를 유지하고 그림은 사이트가 그린다. AI가 쓴 HTML은 렌더링하지 않는다.
- D2. 쌓인 보고서로 추이 차트를 그린다.
- D3. 금융만이 아니라 보안·AI 보고서에도 그림을 넣는다("차트 그림은 금융 쪽밖에 넣을 게 없나?").
- D4. 사용자가 퇴근하며 끝까지 작업해 main까지 병합하라고 했다. 이 기획서는 따로 확인받지 않고 진행한다.

### 구현 방향

- R1. **그림 블록**: 코드 블록 언어로 구분한다. GitHub에서는 글자 그대로 보여도 읽을 수 있는 줄 형식으로 정한다. 형식이 틀리면 사이트는 원래 코드 블록을 그대로 보여 준다.
  - `timeline`: 한 줄에 사건 하나, `- <시각> | <내용> | <수준>`. 수준은 `urgent`·`notice`·`normal` 중 하나이고 생략할 수 있다. 세로 줄과 점으로 그린다.
  - `flow`: 한 줄에 단계 하나(2~7단계). 번호를 단 상자를 화살표로 잇는다.
  - `trend`: 쉼표로 구분한 `metrics` 키(예: `sp500, us10y`). 같은 작업의 최근 30일 값으로 지표마다 작은 차트를 그린다. 값이 둘 미만이면 "쌓이는 중"과 지금 값만 보여 준다.
- R2. **상태 배지**: 표 칸의 글자가 `P1`·`P2`·`P3`이거나 소제목이 `① [P1]`처럼 시작하면 배지로 보여 준다. 지난 보고서에도 같이 적용된다.
- R3. **작업별 추이** (목록 페이지 위)
  - 최근 30일 수준 띠: 날짜마다 칸 하나, 칸 색은 수준(긴급 빨강, 주의 노랑, 보통 회색). 범례와 칸마다 날짜·수준 툴팁을 붙인다.
  - 자주 나온 태그: 최근 30일 상위 8개를 가로 막대로 그리고 막대 끝에 건수를 적는다. 태그 이름은 태그 페이지로 이어진다.
  - 숫자 추이: 그 작업에 `metrics` 값이 있으면 지표마다 작은 차트를 그린다.
  - 차트 아래 "숫자로 보기"에 같은 값을 표로 둔다.
- R4. **`metrics`**: frontmatter에 한 줄 흐름 형식으로 쓴다. 예: `metrics: {p1: 0, p2: 2, p3: 7}`. 확인한 값만 숫자로 쓰고, 확인하지 못한 값은 키를 뺀다(0으로 쓰지 않는다).

  | 작업 | 키 |
  |---|---|
  | 보안 | `p1`, `p2`, `p3`(주요 항목·참고 건수, 다시 쓴 긴급 감시 포함), `malicious_npm`(OSV npm 악성 패키지 신규 건수), `kev_added`(조사 기간 KEV 신규 등재 건수) |
  | S&P500 | `sp500`(종가), `sp500_change_pct`(등락률 %), `vix`, `us2y`·`us10y`(%), `usdkrw`(원). 휴장 다음 날에는 시장 값을 넣지 않는다. |
  | AI 브리핑 | 없음. 추이는 수준과 태그로 그린다. |

- R5. **차트 표기** (dataviz 지침)
  - 숫자 추이는 지표마다 단일 계열 차트로 나눈다(작은 여러 개). 축 두 개를 겹치지 않는다.
  - 단일 계열 색은 파란색 하나다(밝은 화면 `#257de0`, 어두운 화면 `#338ced`). 상태 색은 수준 띠와 배지처럼 글자 라벨이 함께 붙는 곳에만 쓴다.
  - 선은 2px, 막대 끝은 둥글게 4px, 격자와 축은 옅게 둔다. 값은 마지막 값과 툴팁으로 보여 주고 점마다 숫자를 적지 않는다.
- R6. **작업 파일**
  - 공통 규칙에 `metrics` 정의와 '그림' 절(언제 어떤 블록을 쓰는지)을 넣는다. 그림은 글보다 빨리 읽힐 때만 쓰고, 그림과 같은 내용을 글로 다시 쓰지 않는다.
  - 보안(03): 긴급 감시·후속 확인으로 다시 쓰는 사건이 있으면 '주요 항목' 맨 위에 `timeline`을 넣는다. 공격 단계가 셋 이상인 사건(공급망 공격 등)은 항목 안에 `flow`를 넣는다. '한눈에 보기' 표 아래에 `trend`(`p1, p2`)를 넣는다.
  - S&P500(02): '숫자' 표 아래에 `trend`(`sp500, vix, us10y, usdkrw`)를 넣는다.
  - AI(01): 동작이 단계로 바뀐 변경을 설명할 때만 `flow`를 쓴다.
- R7. **검사 스크립트**: `timeline` 줄 형식, `flow` 단계 수, `trend` 키, `metrics` 형식과 필수 키(보안은 `p1`·`p2`·`p3`)를 검사한다.

## 5. 케이스

- C1. 형식이 틀린 블록: 원래 코드 블록을 그대로 보여 준다. 검사 스크립트는 '고칠 것'으로 알린다.
- C2. `trend` 키가 정의에 없음: 그 키만 빼고 그린다. 하나도 없으면 원래 코드 블록을 보여 준다.
- C3. `metrics` 값이 하나뿐(배포 첫날): 작은 차트 자리에 지금 값과 "쌓이는 중"을 보여 준다.
- C4. 지난 보고서: 블록이 없어 그대로다. 표의 P1·P2·P3와 소제목의 `[P1]`은 배지로 보인다.
- C5. 휴장일 S&P500: 시장 값 키가 없어 그날 점이 빠진다. 선은 앞뒤 값을 잇는다.
- C6. 다크 모드: 색 변수를 어두운 화면 값으로 바꾼다.
- C7. 휴대폰 화면: 작은 차트는 두 칸씩 놓고, 수준 띠는 화면 폭에 맞게 칸 크기를 줄인다.
