# 보고서 누락 알림 — 기획서

> 상태: **구현 중**
> 남은 것: 시험 실행
>
> 구현 변경점 (계획 대비):
> - 루틴에 저장된 프롬프트가 "바뀐 것이 없으면 커밋도 알림도 하지 말라"고 해서, 저장소를 바꾸지 않고 알림만 보내는 C와 맞지 않았다. 프롬프트를 "커밋·알림은 작업 파일의 기준을 따른다"로 바꿨다.

## 0. TL;DR

아침 루틴이 중간에 실패하면 보고서가 올라오지 않고 알림도 오지 않는다. 매일 09:15 KST에 도는 04 루틴 회차가 오늘 보고서 3개가 사이트에 올라왔는지 확인하고, 빠진 것이 있으면 휴대폰으로 알린다. 다 있으면 아무것도 하지 않는다(커밋·알림 없음).

## 1. 범위

- 포함: 아침 보고서 3개(보안, AI, S&P500)가 빠졌거나 사이트에 배포되지 않은 경우의 알림
- 제외
  - 보고서 내용 품질 점검(직접 읽어서 확인한다)
  - 04 루틴 자신의 실패(스스로 알릴 수 없다)
  - 빠진 루틴 다시 실행. 알림을 받으면 사용자가 루틴 화면(https://claude.ai/code/routines)에서 직접 Run now 한다.
  - 사이트 의존성(Next.js 등) 보안 업데이트 알림. 따로 다룬다.

## 2. 현재 (2026-11-03)

- 아침 루틴: 보안 08:25, AI 08:42, S&P500 08:55 KST. 서버가 예정보다 8~9분 늦게 시작한다.
- 11-03 실제 커밋 시각(옛 일정 08:30·09:00·09:30): 모두 예정 시각 12~13분 뒤. 새 일정이면 보안 08:40, AI 08:55, S&P500 09:08 전후로 본다. 보안은 분야별 확대 뒤 실행 시간이 약 5분으로 늘어 조금 더 늦을 수 있다.
- 11-04 실측(새 일정 첫날): 커밋 보안 08:30, AI 08:44, S&P500 08:58. 시작 지연이 거의 없었다. 04 루틴의 09:15 회차는 09:15:49에 시작해 40초 만에 끝났다. S&P500 커밋과 17분 차이다.
- 04 루틴: 3시간마다 15분(UTC `15 */3 * * *`). 11-03 ~ 11-04 회차 9번의 시작 지연은 0 ~ 3분이었다.
- 아침 루틴은 성공하면 마지막에 푸시 알림을 보낸다(공통 규칙 '결과 저장' 5단계). 하지만 세션이 중간에 끝나면 알림이 없고, 알림이 안 온 것은 알아채기 어렵다.
- push 뒤 Vercel 배포 반영까지 약 70~80초(11-03 `v0.0.11` 배포 때 확인).
- S&P500 루틴은 주말·미국 휴장일에도 보고서를 쓴다(새 거래 데이터가 없다고 밝힌다). 그래서 매일 3개를 기대할 수 있다.
- 보고서 날짜는 실행일의 KST 날짜이고 저장 경로와 같다(공통 규칙).

## 3. 결정 사항

### 확정 (사용자 2026-11-03)

- **D1. 04 루틴의 09시 회차에 붙인다.** 새 루틴을 만들지 않는다(제안 수락).
- **D2. 오늘은 기획서만 쓰고 구현은 11-04에 한다.**
- **D7. 루틴 이름은 그대로 둔다**(U1, 사용자 2026-11-04 "진행해").

### 구현 방향

- **D3. 확인하는 회차**: 실행 시각(KST)이 09:00~11:59인 회차만 확인한다. 보통 09:15 회차 하나고, 시작이 늦어져도 잡힌다. 하루 한 번이라 "이미 알렸는지"를 저장할 필요가 없다.
- **D4. 확인 방법**: 작업마다 사이트 주소 `https://daily-report-ashy-nine.vercel.app/<작업 ID>/<YYYY-MM-DD>`를 `curl`로 열어 200인지 본다. 200이 아니면 저장소(`origin/main`)의 `reports/<작업 ID>/YYYY/MM/DD.md`로 원인을 나눈다.
  - 파일 없음 → 루틴 실패(누락)
  - 파일 있음, 사이트에 없음 → 배포 실패·지연
  - 사이트 접속 자체가 안 됨(네트워크) → 파일 존재로만 판단한다.
- **D5. 알림**: 빠진 것을 모아 PushNotification 한 번으로 보낸다. 저장소는 바꾸지 않는다(커밋 없음).
  - `[보고서 누락] AI·개발 도구 브리핑, S&P500 · 11-04 보고서가 아직 없습니다`
  - `[배포 지연] IT 보안 이슈 데일리 리포트 · 11-04 보고서는 저장됐지만 사이트에 없습니다`
  - 같은 회차에 긴급 감시·후속 확인 알림이 있으면 따로 보낸다(성격이 다르다).
- **D6. 작업 파일**: `04-security-watch.md`에 'C. 보고서 누락 확인' 절을 넣고, '커밋·알림' 절에 알림 형식을 더한다. 루틴 프롬프트는 작업 파일을 가리키므로 루틴 설정은 바꿀 필요가 없다(이름은 U1).

### 확인 필요

- U1(루틴 이름)은 D7로 정했다. 작업 파일 맨 위 작업 ID 줄에 "09시 회차는 보고서 누락 확인도 함께 한다"고 적었다.
- **U2. 오탐 가능성**: S&P500 루틴이 평소보다 오래 걸려 09:23까지 끝나지 않으면 누락으로 잘못 알린다. 오탐이 나오면 S&P500만 12시 회차에서 확인하도록 바꾼다.
- **U3. 루틴 환경의 접속**: 루틴 세션에서 `github.com`은 `curl`이 막혀 있었다. `vercel.app` 주소는 되는지 시험 실행으로 확인한다. 안 되면 WebFetch로 열거나 파일 존재로만 판단한다.

## 5. 케이스

- M1. 3개 모두 사이트에 있음 → 아무것도 하지 않음
- M2. AI 보고서 파일이 없음 → `[보고서 누락] AI·개발 도구 브리핑`
- M3. 파일은 있는데 사이트에 없음 → `[배포 지연]`
- M4. 09시 회차가 늦게 시작해 10시대에 돎 → 그래도 확인(D3)
- M5. 09시 회차 자체가 실패 → 그날은 확인하지 못함(한계)
- M6. 같은 날 보고서를 다시 실행해 덮어씀 → 파일과 페이지가 있으니 정상
- M7. 09시 회차가 아닌 다른 회차 → 확인하지 않음

## 6. 작업 순서

1. `04-security-watch.md`에 C절과 알림 형식 추가
2. `scheduler/README.md`의 '보안 후속 확인·긴급 감시' 절과 루트 README 문구 반영
3. 시험 실행 (11-04 09:00~11:59 사이)
   - 정상 확인: 그날 보고서 3개가 있으면 알림 없음(M1)
   - 누락 시험: 루틴 프롬프트에 "이번 실행은 시험이다. C의 확인 날짜를 다음 날로 바꾸고 A·B는 건너뛴다"를 잠깐 덧붙여 실행하고, 실행이 시작되면 바로 원래 프롬프트로 되돌린다. 3개 모두 누락 → 알림 1건(M2)
4. 커밋·병합(사용자 요청 시). 루틴 파일만 바뀌어 태그 없음
