### 2. Claude Code v2.1.314 — 작업 디렉터리 밖 쓰기 차단 옵션
- 발표일: GitHub 릴리스 게시 10-30 01:06 (GitHub 표시값, 시간대 미표시)
- 핵심 변경: `permissions.blockWritesOutsideWorkingDirectories` 추가. `claude -p`가 시작에 실패하면 이제 오류를 출력하고 exit 1로 끝난다(이전에는 exit 0이었다). 오래 쉬고 있던 대화를 자동 압축(idle compaction).
- 원문: https://github.com/anthropics/claude-code/releases
- 개발자에게 주는 의미: 헤드리스(`-p`) 실행 결과를 종료 코드로 판단하는 파이프라인은 동작이 달라진다.
- 실무 적용 포인트: `claude -p`를 쓰는 CI 단계가 이제 실패로 잡힐 수 있으니 재시도·알림 로직을 확인한다. 공유 개발 서버에서는 쓰기 차단 옵션을 켜 두는 것을 검토한다.

### 3. MCP TypeScript SDK v2.4.0 — Skills over MCP와 breaking 변경
- 발표일: GitHub 릴리스 게시 10-23 18:32 (GitHub 표시값, 시간대 미표시)
- 핵심 변경: Skills 확장(SEP-2640, `SkillsClient`, `ext/skills` 서브패스) 추가. `x-mcp-header`를 `number` 파라미터에 쓰면 거부된다(`z.int()` 사용 필요). 2025-11-25 연결에서 `.meta({ id })` output schema 결과를 더 이상 `{ result }`로 감싸지 않는다. Ajv가 잘못된 URI 스킴의 `$id`/`$ref`를 거부한다. v1 라인은 `v1.32.2`로 백포트.
- 원문: https://github.com/modelcontextprotocol/typescript-sdk/releases
- 개발자에게 주는 의미: Node.js로 MCP 서버를 운영한다면 2.4.0으로 올릴 때 응답 형태와 스키마 검증 때문에 클라이언트가 깨질 수 있다.
- 실무 적용 포인트: NestJS에 MCP 서버를 붙였다면 zod 스키마의 `number` → `z.int()` 사용처, `$id: "my_tool:output"` 같은 스키마 ID, output 결과를 `result`로 꺼내는 클라이언트 코드를 점검한 뒤 올린다.
