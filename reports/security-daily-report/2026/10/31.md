두 취약점은 기존 인증 우회 취약점 `CVE-2026-104935`와 연계될 수 있다. 보안업체 Volexity는 이 공격 체인을 이용해 외부 공격자가 VPN 장비에서 root 권한까지 확보한 실제 침해 사건을 조사했다.

**중요한 점:** 10월 13일 인증 우회 패치만 적용한 장비는 이번 취약점의 수정이 완료되지 않았을 수 있다.

일반적인 Node.js 서버와는 직접 관련이 없지만, 회사 VPN에 해당 장비를 사용하는 경우 최우선 대응 대상이다.

### ② Nx Maven/Gradle — `nx.json`을 통한 OS 명령어 주입

- **High · CVSS v4.0 7.3**
- GHSA-qm8w-vx34-5j9j · CVE-2026-119282

Nx의 `@nx/maven`, `@nx/gradle` 플러그인이 `nx.json`의 옵션값을 쉘 명령어에 안전하게 전달하지 않는 문제가 발견됐다.

공격자가 악성 저장소의 `nx.json`을 조작하거나, PR에서 해당 파일을 변경한 상태로 CI가 Nx 프로젝트 그래프를 생성하면 **CI Runner 권한으로 명령어가 실행될 수 있다.**

| 패키지 | 영향 계열 | 수정 버전 |
|---|---|---|
| `@nx/gradle` | 21.0.0~22.7.8, 23.0.0~23.1.1 | 22.7.9 / 23.1.2 |
| `@nx/maven` | 22.0.2~22.7.8, 23.0.0~23.1.1 | 22.7.9 / 23.1.2 |

**패치 시에는 플러그인뿐 아니라 `nx` 본체도 같은 수정 계열로 업데이트해야 한다.** 플러그인만 업그레이드하면 수정이 완성되지 않는다.

실제 공격에 악용됐다는 근거는 공식 권고문에서 확인되지 않았다. 또한 Maven·Gradle 플러그인을 등록하지 않은 일반적인 Nx 모노레포에는 해당하지 않는다.

최초 프로젝트 공지는 9월 11일이었으며, **10월 30일 NVD/GitHub Advisory Database 등록·검토가 갱신**된 사안이다. 신규 발견으로 분류하지 않았다.

공식 원문: [Nx 보안 권고문](https://github.com/advisories/GHSA-qm8w-vx34-5j9j)

`pypa/gh-action-pypi-publish`가 Trusted Publishing·Digital Attestations에 사용하는 인증서 검증 체인에, 문제가 보고된 emSign 계열 인증기관이 포함되어 있었던 사안이다.

이 취약점은 10월 21일 프로젝트에서 최초 공개했고, **10월 30일 GitHub 보안 DB에 등록**됐다.

Python 패키지를 GitHub Actions로 배포한다면 `pypa/gh-action-pypi-publish@v1.14.3` 이상에 해당하는 릴리스 또는 안전한 고정 커밋으로 변경해야 한다. Node.js 패키지를 npm에 배포하는 일반 워크플로에는 직접 해당하지 않는다.

공식 원문: [PyPI Publish 보안 권고문](https://github.com/advisories/GHSA-5xjx-3w67-w9x9)

### ⑤ AWS FreeRTOS — MPU 보호 경계 손상

- 2026년 10월 30일 10:30 PDT 공개 = 한국 시간 10월 31일 02:30
- **CVE-2026-119086 / AWS Security Bulletin 2026-158**

FreeRTOS 커널의 `xQueueSelectFromSet`에서 객체 유형을 충분히 확인하지 않는 문제다.

MPU 보호를 사용하는 FreeRTOS 빌드에서 낮은 권한의 태스크가 잘못된 객체를 전달하면 특권 컨텍스트에서 의도하지 않은 메모리 쓰기가 발생할 수 있다.

| 항목 | 내용 |
|---|---|
| 영향 버전 | FreeRTOS Kernel V7.4.0~V11.3.2 |
| 필요 조건 | MPU 지원 포트 및 `configUSE_QUEUE_SETS=1` |
| 수정 버전 | **V11.3.3** |
| 대응 | 커널 업데이트, 펌웨어 재빌드·재플래시 |
| 실제 악용 | 확인되지 않음 |

Queue Set 기능을 사용하지 않는 빌드에는 영향을 주지 않는다.

흥미로운 부분은 AWS 공식 공지에 **Anthropic의 Claude와 Ada Logics가 취약점 발견·공개 과정에 기여했다고 명시**되어 있다는 점이다. 이것은 Claude Code의 취약점이 아니라 AI가 보안 결함 발견에 관여한 사례다.

공식 원문: [AWS Security Bulletin 2026-158](https://aws.amazon.com/security/security-bulletins/2026-158-aws/)

GitLab의 `CVE-2026-97229`는 10월 29일 CISA KEV에 등재된 기존 실제 악용 취약점이다. 자체 호스팅 GitLab을 운영하고 있다면 미완료 패치·침해 조사를 여전히 우선해야 한다. 같은 공식 카탈로그에서 Brotli `CVE-2026-111497`도 실제 악용 취약점으로 확인된다.

## 5. 최종 판단

현재 주로 사용하는 **Node.js·NestJS·PostgreSQL·Redis·AWS 인프라**에 대한 실질적 대응 가치를 기준으로 보면 다음과 같이 정리된다.

**첫째, 자체 호스팅 GitLab과 Node.js Brotli 패치가 아직 미완료라면 신규 취약점보다 먼저 처리해야 한다.** 두 문제는 기존에 공개됐지만 CISA가 실제 악용 근거를 인정한 상태다.

**둘째, Nx를 사용하는 저장소에서는 Maven/Gradle 플러그인 등록 여부를 확인할 가치가 있다.** PR 기반 CI 실행이나 외부 저장소 분석에 연계되므로 개발 워크플로의 신뢰 경계 문제다.

**셋째, AWS의 신규 취약점은 Nitro Enclaves·FreeRTOS라는 특수 환경에 국한된다.** 일반적인 NestJS 서버가 EC2·ALB·S3·ECR을 사용한다는 이유만으로 해당 취약점의 영향을 받는 것은 아니다.

**오늘의 핵심 요약:** 실제 악용 측면에서는 **Ivanti VPN 공격 체인**, 개발 생태계에서는 **Nx 명령어 주입 및 npm 악성 패키지**, 클라우드에서는 **AWS Nitro Enclaves SDK의 입력 검증·메모리 문제**가 주요 변화다.

이번 리포트는 공식 공개 자료를 기준으로 검증했다. 운영 서버나 Git 저장소에 직접 접속해 실제 취약 버전의 설치·침해 여부까지 확인한 결과는 아니다.
