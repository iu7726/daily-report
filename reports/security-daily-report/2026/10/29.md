### ① Linux 커널 — 신규 KEV 등재 및 PHP 공격 연계 위험

- **실제 악용 확인**
- 2026-10-28 KEV 등록
- **CVE-2026-46300**

CISA가 10월 28일 Linux 커널의 메모리 처리 취약점을 Known Exploited Vulnerabilities(KEV)에 신규 등재했다.

문제는 커널의 네트워크 버퍼 처리 과정에서 공유 프래그먼트 표시가 유지되지 않아, ESP(IPsec) 입력 처리 중 공유된 데이터가 잘못 수정될 수 있다는 것이다.

CISA는 해당 취약점이 기존 PHP 취약점인 `CVE-2026-109618`, `CVE-2026-109619`와 결합되면 PHP 웹셸 설치 및 root 권한 명령 실행으로 이어질 수 있다고 설명한다.

| 제품 | Linux Kernel |

| CISA 조치 기한 | 2026-10-31 (미국 연방기관 기준) |

| 패치 | Linux 배포판별 보안 커널 업데이트 적용 |

**실무 영향:** EC2의 Linux 인스턴스, Docker 호스트, 자체 관리 Kubernetes 노드라면 커널 버전을 확인할 필요가 있다.

단, Docker 이미지 내부의 Node.js 패치와 **호스트 Linux 커널 패치는 서로 다른 작업**이다. 이미지 재빌드만으로 호스트 커널 문제가 해결되지 않는다.

특정 PHP 취약점과의 결합 가능성은 공식적으로 설명돼 있지만, 모든 Node.js 서버에서 원격 root 권한 탈취가 가능하다고 일반화할 수는 없다.

**권장 조치:** 운영체제 공급자의 해당 CVE 수정 커널을 적용하고 필요 시 재부팅한다. 노출이 의심되는 호스트에서는 커널 로그·비정상 프로세스·권한 상승 흔적을 조사한다.

### ② AWS — Brotli RCE에 대한 서비스별 공식 대응 발표

- **High · 실제 악용 근거 존재**
- 2026-10-28 15:00 PDT / 10-29 07:00 KST
- **CVE-2026-111497 / AWS Security Bulletin 2026-155**

기존에 보고한 Brotli 메모리 손상 취약점 자체는 새로운 사건이 아니다. 그러나 **AWS가 오늘 새벽 각 서비스의 영향 범위와 패치 완료·예정 일정을 구체적으로 공개했다**는 점이 중요하다.

공격자가 조작한 Brotli 압축 데이터를 애플리케이션이 해제하면 메모리 손상, 정보 노출 또는 원격 코드 실행이 발생할 수 있다.

**AWS 서비스별 대응 현황**

| 서비스 | AWS 공식 현황 | 사용자 조치 |
|---|---|---|
| Lambda Node.js 컨테이너 | 수정 베이스 이미지 제공 | 재빌드·재배포 |
| Lambda Node.js ZIP | 단계적 배포, 10/30 완료 목표 | 런타임 갱신 확인 |
| AWS CodeBuild | 수정 이미지 10/30 완료 목표 | 이미지 고정 여부 확인 |
| AWS App Runner | 10/26 수정 런타임 배포 | 기존 서비스 재배포 |
| Elastic Beanstalk | 6.11.12 수정 플랫폼 제공 | 플랫폼 업데이트 |
| EC2 / ECS / EKS 자체 관리 | AWS 자동 수정 대상 아님 | 런타임·라이브러리 직접 패치 |
| Amplify SSR(Node 22·24) | 자동 업데이트 대상 | 별도 조치 불필요 |

특히 AWS는 Lambda의 Node.js 24 런타임에 대해 **Node.js 24.22.1의 알려진 회귀 문제 때문에 보안 수정 사항을 현재 안정 릴리스에 선택적으로 반영한다**고 설명했다.

따라서 Lambda에서 `process.version`만 검사해 해당 보안 패치 적용을 판단해서는 안 된다.

공식 공지는 Lambda `INIT_START` 로그의 패치 버전을 확인하도록 안내하며, Node.js 22는 `nodejs:22.mainline.v157` 이상, Node.js 24는 `nodejs:24.mainline.v114` 이상을 기준으로 제시한다.

**임시 완화:** 직접 패치가 어려운 경우 Brotli 요청 디코딩을 비활성화할 수 있다. AWS WAF에서 `Content-Encoding: br` 요청을 차단하는 방식도 가능하지만, 외부 API 응답처럼 애플리케이션이 수신하는 모든 Brotli 데이터를 보호하지는 않는다.

공식 원문: [AWS Security Bulletin 2026-155](https://aws.amazon.com/security/security-bulletins/2026-155-aws/)

## 5. 오늘 실무 점검 명령어

**Node.js·Linux 호스트·npm 검사**

```bash
# Node.js 버전
node -v

# Linux 호스트 커널·배포판
uname -r
cat /etc/os-release

# 신규 권고 대상 의존성
npm ls --all mcp-sanitizer highcharts \
@highcharts/dashboards black-spindle

# 일반 취약점 검사
npm audit
```

**AWS Lambda 설정·런타임**

```bash
aws lambda get-function-configuration \
--function-name YOUR_FUNCTION_NAME \
--query '{Runtime:Runtime, PackageType:PackageType, LastModified:LastModified, RuntimeVersionConfig:RuntimeVersionConfig}'
```

실제 보안 수정 적용 여부는 배포 이미지 또는 Lambda 실행 로그의 런타임 패치 버전까지 확인해야 함

Docker 베이스 이미지를 수정하려면 이미지를 새로 받아 재빌드·재배포해야 한다. Linux 커널은 호스트 운영체제 패치 및 필요한 재부팅까지 별도로 처리해야 한다.

두 번째 취약점은 가상화 호스트를 관리하는 환경에서 중요하지만, AWS EC2를 이용하는 일반적인 Node.js 애플리케이션이 직접 취약해진다는 뜻은 아니다.

CISA 공식 데이터의 버전은 `2026.10.28`이며, 10월 28일 19:00 UTC(한국 시간 29일 04:00)에 배포된 것으로 확인된다.

## 7. 최종 판단

현재 사용 중인 Node.js·NestJS·AWS 기반 개발 환경을 기준으로, 오늘의 우선순위는 다음과 같다.

1. **EC2·Docker 호스트의 Linux 커널 패치 여부 확인.** 이번 KEV 신규 등재로 실제 악용 위험을 반영해야 한다.
2. **Brotli 보안 수정 적용 확인.** EC2 자체 관리 Node.js와 Lambda·CodeBuild의 패치 방식이 다르므로 구분해서 검증한다.
3. **AWS CloudFront·ALB 인증서 체인 확인.** CA 신뢰 목록 변경으로 인한 연결 실패 가능성을 점검한다.
4. **MCP·npm 공급망 검사.** `mcp-sanitizer`, Highcharts 등 사용 중인 프로젝트가 있으면 해당 보안 권고문을 적용한다.

**핵심 요약:** 오늘은 Node.js 코드 자체의 신규 취약점보다 **실제 악용 중인 Linux 커널 취약점과 AWS의 Brotli 보안 패치 배포 상태**가 더 중요하다. 기존의 보안 패치가 애플리케이션뿐 아니라 운영 서버와 배포 이미지에도 반영됐는지를 확인하는 날이다.

현재 리포트는 공개 자료 검증 결과이며, 운영 서버 또는 저장소에 직접 접속해 버전·패치·침해 여부를 검사한 결과는 아니다.
