### ③ OpenAI — API 프롬프트 캐싱 12시간 지원
**발표: 10월 20일 | 중요도: 높음 | 백엔드 관련**

OpenAI가 Responses API에 **12시간 프롬프트 캐싱**을 추가했습니다.

기존 기본 캐시 유지 시간은 최소 30분이었지만, 이제 장시간 재사용하는 시스템 프롬프트와 도구 정의를 12시간 동안 캐싱하도록 설정할 수 있습니다.

| 항목 | 30분 캐시 | 12시간 캐시 |
|---|---|---|
| 최소 유지 시간 | 30분 | 12시간 |
| 캐시 쓰기 비용 | 일반 입력의 1.25배 | 2.5배 |
| 캐시 읽기 비용 | 일반 입력의 0.1배 | 0.1배 |
| 주요 용도 | 짧은 대화·연속 호출 | 장시간 에이전트 |

GPT-6.1 Sol은 캐시 읽기 비용이 일반 입력의 0.05배입니다.

**NestJS 활용:** AI 에이전트가 공통 정책, 시스템 프롬프트, MCP 도구 정의를 여러 시간에 걸쳐 반복 사용하는 경우 비용을 절감할 수 있습니다. 다만 캐시 쓰기 비용이 높으므로 실제 적중률을 측정해야 합니다.

새 모델 출시는 아니며 GPT-5.6 이상 모델의 Responses API 기능 확장입니다. ([OpenAI Developers](https://developers.openai.com/api/docs/changelog))

[OpenAI 공식 캐싱 가이드](https://developers.openai.com/api/docs/guides/prompt-caching)

### ④ Claude Code — v2.1.305 출시
**릴리스: 10월 21일 05:46 KST | 중요도: 높음**

전날 소개한 v2.1.304의 후속 업데이트입니다.

주요 변경 사항은 다음과 같습니다.

- **Tool Search 호환성 수정:** Vertex AI, Bedrock 등의 게이트웨이에서 Tool Search를 거부할 때 전체 요청이 실패하던 회귀 버그 수정.
- **MCP 설정 충돌 수정:** SDK에서 전달한 MCP 서버가 동일한 이름의 로컬 설정으로 덮어씌워지는 문제 수정.
- **Worktree 개선:** 새 Worktree가 잘못된 브랜치에서 시작하거나 사용하지 않는 Worktree가 정리되지 않는 문제 수정.
- **워크플로 재개:** 완료된 병렬 에이전트 작업을 다시 실행하던 문제 수정.
- **Linux 샌드박스 옵션 추가:** 중첩 User Namespace를 허용하는 설정 제공.

마지막 옵션인 `sandbox.allowNestedUserNamespaces`는 Chromium이나 Rootless Podman 구동에 유용하지만, 샌드박스의 파일 보호를 우회할 수 있으므로 보안상 주의가 필요합니다.

**실무 적용:** Claude Code를 AWS Bedrock이나 별도 AI 게이트웨이에서 운영한다면 이번 버전을 확인할 가치가 큽니다. ([GitHub](https://github.com/anthropics/claude-code/releases))
