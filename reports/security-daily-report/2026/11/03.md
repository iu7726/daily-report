## 1. 긴급 조치 요약

**조건부 P1 1건**

- **Cursor에서 Claude Code 확장을 쓰는 경우**: 2026-10-29 02:27~13:35 PT(**10-29 18:27 ~ 10-30 05:35 KST**)에 Cursor 마켓플레이스에서 Claude Code 확장(`anthropic.claude-code`) **2.1.312 또는 2.1.313**을 macOS나 Windows에 설치·업데이트했다면 백도어가 설치됐을 수 있다. 아래 명령으로 `svc-telemetry` SSH 키가 있는지 바로 확인한다. 키가 있으면 확장 삭제만으로는 부족하므로 Cursor의 복구 스크립트를 실행하고, 그 기기에서 접근할 수 있던 비밀번호·API 키·세션을 다른 신뢰할 수 있는 기기에서 교체한다.

  - VS Code(Microsoft 마켓플레이스), Open VSX, npm `@anthropic-ai/claude-code`로 설치한 경우는 영향 없음(Cursor·StepSecurity 발표 기준).

## 2. 오늘의 핵심 보안 이슈

### ① [P1, 해당 시] Claude Code 확장 — Cursor 마켓플레이스에서 변조 빌드가 배포돼 SSH 백도어 설치 시도

- **영향 기술·버전**: Cursor의 VS Code 확장 마켓플레이스로 받은 `anthropic.claude-code` **2.1.312, 2.1.313** (macOS, Windows). Cursor는 처음에 2.1.313만 언급했다가 2026-10-30 11:30 PT 갱신에서 영향 버전을 2.1.312·2.1.313으로 정정했다. Anthropic이 만든 빌드가 아니며, 다른 버전과 공식 배포 채널은 영향이 없다고 Cursor가 밝혔다.
- **식별 정보**: CVE/GHSA 해당 없음(공급망 변조) / CVSS 해당 없음 / KEV 해당 없음 / **실제 악성 배포 확인**(Cursor 공식 공지)
- **공격 방식·영향**: 확장의 `extension.js` 앞부분에 로더가 추가됐다. 설치되면 `~/.ssh/authorized_keys`에 주석이 `svc-telemetry`인 공격자 SSH 키를 넣고, 공격자 서버(134.209.82.225)로 역방향 SSH 터널을 연다. macOS LaunchAgent `com.apple.sysmond`, Windows 예약 작업 `SysMon`, `@reboot` cron으로 지속성을 확보하고, 호스트·사용자 정보, Git 이메일, 공인 IP, 환경 변수 이름을 수집한다(StepSecurity 분석). 노출 규모는 Cursor 초기 추정 최대 5,000명으로 보도됐다.
- **현재 상태**: Cursor는 10-29 13:35 PT에 해당 빌드를 내리고 마켓플레이스를 잠시 닫은 뒤 다른 확장을 감사하고 키를 교체했다. 공격자 서버는 10-30에 내려갔지만, Cursor는 감염된 호스트를 그래도 복구해야 한다고 밝혔다.
- **임시 완화책·복구**:
  1. 감염 흔적이 있는 기기를 네트워크에서 분리한다.
  2. 무단 SSH 키, 지속성 항목, 실행 중인 터널 프로세스를 지운다. 확장 삭제만으로는 지속성 스크립트가 남을 수 있다. 재설치(재구축) 여부를 판단한다.
  3. 그 기기에서 접근할 수 있던 자격 증명과 세션을 **다른 신뢰할 수 있는 기기에서** 교체한다.
  4. Cursor가 제공한 `remediate-macos.sh`(해당 사용자로 실행, root 아님) 또는 `remediate-windows.ps1`(관리자 PowerShell)을 실행한다. 남은 항목이 있으면 0이 아닌 종료 코드로 끝난다.
- **내 조치**:
  - Cursor에서 Claude Code 확장 사용 시: 위 노출 시간에 설치·업데이트했는지와 관계없이 `svc-telemetry` 검사 명령을 한 번 돌린다(Windows는 Cursor 공지의 PowerShell 명령). 방화벽·프록시 로그에서 134.209.82.225 통신을 찾는다.
  - VS Code, 터미널 CLI(npm), Open VSX만 사용 시: 조치할 필요 없음.
  - 공통: 업무용 기기라면 `~/.ssh/authorized_keys`에 모르는 키가 없는지 이번 기회에 점검한다.

  - StepSecurity 분석 (2026-10-30, 갱신 2026-11-01): https://www.stepsecurity.io/blog/claude-code-extension-trojanized
  - BleepingComputer 보도 (2026-10-30): https://www.bleepingcomputer.com/news/security/malicious-claude-code-extension-on-cursor-planted-ssh-backdoors/

### ③ [P3] GitLab CE/EE — 키가 유출된 eMudhra 중간 CA 8개 신뢰 제거 패치 (CVE-2026-111943)

- **영향 기술·버전**: GitLab CE/EE 18.11.14 미만, 19.0~19.5 계열의 19.0.11 / 19.1.10 / 19.2.10 / 19.3.7 / 19.4.5 / 19.5.3 미만. GitLab이 함께 배포하는 인증서 저장소가 대상이다.
- **식별 정보**: CVE-2026-111943 / CVSS 확인 불가(GitLab 공지에 점수 없음) / KEV 미등재 / 이 CA로 발급한 인증서를 실제로 악용했는지는 확인 불가
- **배경**: eMudhra 중간 CA 8개의 개인 키가 약한 키 생성 때문에 노출돼 Mozilla·Chrome 루트 프로그램이 2026-10-20에 확인했다(이전 보고 10/26~10/29에서 다룸). 이번 항목은 GitLab이 2026-10-29 패치 릴리스에서 자체 인증서 저장소의 신뢰를 제거한 변화다.
- **패치**: 위 버전 이상. GitLab.com은 패치 완료.
- **내 조치**:
  - self-managed GitLab 운영 시: 해당 계열의 패치 버전으로 올린다. GitLab 업그레이드로는 Runner가 갱신되지 않으므로 **self-hosted GitLab Runner를 19.5.1로** 올리고, 자체 `ca-certificates`를 담은 CI 작업 이미지도 다시 빌드한다. self-hosted AI Gateway를 쓰면 함께 올린다.
  - 19.5.3, 19.4.5는 일반 마이그레이션이 포함돼 단일 노드는 다운타임이 생긴다.
  - Docker 이미지 공통: CA 번들은 빌드 시점에 고정되므로, 오래된 베이스 이미지는 다시 빌드해야 이 CA들을 더 이상 신뢰하지 않는다.
- **출처**:
  - GitLab 패치 릴리스 19.5.3 외 (2026-10-29): https://docs.gitlab.com/releases/patches/patch-release-gitlab-19-5-3-released/

## 4. 미확인 보도·루머

- **변조 Claude Code 확장의 노출 규모와 유입 경로**: "최대 5,000명"은 Cursor의 초기 추정으로 보도된 수치이며, 확인한 Cursor 공지 본문에서는 이 수치를 직접 확인하지 못했다. 공격자가 어떻게 Anthropic 이름으로 Cursor 마켓플레이스에 빌드를 올렸는지는 공식적으로 설명되지 않았다(BleepingComputer, 2026-10-30).
- **초기 보도의 Open VSX 언급**: 일부 초기 보도는 Open VSX도 배포 경로로 지목했으나, StepSecurity는 Open VSX의 2.1.312 빌드가 정상이라고 확인했다. 현재 공식 발표 기준 배포 경로는 Cursor 마켓플레이스뿐이다.
- **PAN-OS 공격 주체**: 중국 연계 그룹이 방화벽 약 25대를 장악했다는 내용은 2차 보도(CyberHub Podcast, SecurityWeek 등)로만 확인된다.
