## 0. TL;DR

1. 실행 시각을 정각에서 피해 08:25 / 08:42 / 08:55(KST)로 촘촘하게.
2. 순서를 보안 → AI → 경제(S&P500)로. 사이트 메뉴·카드·목록 순서도 같이.
3. 보안 리포트가 "곧 나올 것"(예정된 보안 릴리스 등)을 발견하면 대기 목록에 올리고, 3시간마다 도는 후속 확인 루틴이 확인해 나오면 그날 리포트에 덧붙이고 휴대폰으로 알린다.
4. 어미를 "~습니다"로 통일하고 번역투를 금지한다. AI 브리핑의 "개발자에게 주는 의미" 항목을 "적용점"으로 합친다.
5. 문단을 짧게, 굵은 라벨 나열을 줄이는 글쓰기 규칙을 공통 규칙에 넣는다.

## 2. 결정 사항 (확정, 사용자 2026-11-03)

- **D1. 시각**: 보안 08:25(`25 23 * * *` UTC), AI 08:42(`42 23 * * *`), S&P500 08:55(`55 23 * * *`). 루틴 설정은 바꿨다(2026-11-03).
- **D2. 순서**: 보안 → AI → S&P500. `web/lib/tasks.ts` 배열 순서, 사이트 소개 문구, README 표. 작업 파일 번호(01~03)는 루틴 프롬프트가 파일 이름을 가리키므로 그대로 둔다.
- **D3. 어미 "~습니다"로 통일**: 본문 문장은 "~습니다/~합니다". 표 칸, 짧은 목록, `headline`은 명사형도 된다.
- **D4. 글쓰기 규칙**(`scheduler/CLAUDE.md` '글쓰기' 절): 번역투 금지 표(예: "조용히 바뀐다" → "오류 없이 바뀐다"), 문단 2~3문장, 굵은 라벨 나열 대신 핵심 문장 먼저 쓰고 비교할 값만 표로, 목록은 2단계까지, 항목 예시.
- **D5. AI 브리핑 항목**: "개발자에게 주는 의미"와 "실무 적용 포인트"를 합쳐, 라벨 없이 **인용 블록(`>`) 한두 문장**으로 강조한다("적용점"이라는 라벨은 어색하다, 사용자 2026-11-03). 인용은 항목당 한 번, 강조에만 쓴다. 보안 리포트 항목은 핵심 문장 → 값 표 → 조치 순서로 바꾼다.
- **D9. 인용 블록 스타일**: 지금은 회색 글씨 + 옅은 선이라 흐리게 보인다. 본문색 글씨, 진한 왼쪽 선, 옅은 바탕으로 바꿔 강조 상자로 쓴다(무채색 유지). 기존 보고서의 안내 인용(ChatGPT에서 옮겨 온 보고서 표시 등)도 같은 모양이 된다.
- **D6. 보안 후속 확인 = 대기 목록 + 3시간마다 도는 조건부 알림 루틴**
  - 보안 루틴은 "예정된 보안 릴리스, 패치 예고, 공개 대기 중인 권고"처럼 정해진 시점에 나올 것을 `watch/watchlist.json`에 올린다(기한 최대 7일, 열린 항목 최대 5개, 중복 금지).
  - 후속 확인 루틴(`scheduler/04-security-watch.md`, 작업 ID `security-watch`, 조건부 알림형)은 3시간마다(`15 */3 * * *` UTC = KST 00:15·03:15·…·21:15) 돈다. 아침 루틴과 겹치지 않게 15분에 맞췄다.
  - 열린 항목이 없으면 아무것도 하지 않고 끝낸다(커밋·알림 없음).
  - 조건이 충족되면 가장 최근 보안 리포트의 본문 맨 앞(기준 시각 줄 다음)에 `## 후속 확인 (MM-DD HH:mm KST)` 절을 넣고, 휴대폰으로 알리고, 항목을 `done`으로 바꾼다. 기한이 지나면 `expired`로 바꾼다.
  - 상태가 바뀌지 않은 확인은 커밋하지 않는다(3시간마다 빈 커밋이 쌓이지 않게).
  - 모델은 Sonnet 5.5(D6, 사용자). 확인만 하는 일이고 자주 돈다.
  - `watch/`는 `web/`·`reports/` 밖이라 목록만 바뀐 커밋은 사이트를 다시 빌드하지 않는다. 리포트에 절이 추가되면 다시 빌드된다.
- **D7. 공통 규칙 예외**: "보고서 파일 외 수정 금지"에 `watch/watchlist.json`(보안 루틴, 후속 확인 루틴)과 후속 확인 루틴의 "최근 보안 리포트에 후속 확인 절 추가"를 예외로 둔다.
- **D8. 첫 대기 항목은 직접 넣는다**: 오늘 리포트의 "Next.js 11월 3일 보안 릴리스"를 첫 항목으로 넣어 후속 확인 루틴을 바로 시험한다.

## 3. 케이스

- W1. 대기 목록 파일이 없거나 열린 항목이 0개 → 즉시 종료, 커밋 없음

- W3. 아직 → 아무것도 바꾸지 않음(커밋 없음)
- W4. 기한 지남 → `expired`, 알림 없음
- W5. 출처에 접속 실패 → 그 항목은 이번 회차를 건너뜀(상태 유지)
- W6. 같은 시각에 아침 보안 루틴과 겹침 → 15분 오프셋으로 피하고, 그래도 겹치면 push 거부 시 rebase 후 재시도(공통 규칙)
