## 0. TL;DR

문서 사이트처럼 보고서 페이지를 세 칸으로 나눈다. 왼쪽은 같은 작업의 날짜 목록, 가운데는 본문, 오른쪽은 소제목 목차다. 휴대폰에서는 목차를 접힌 상자로 본문 위에 둔다.

## 1. 범위

- 대상: 보고서 상세 페이지(`/[task]/[date]`)
- 사이트 전체 폭을 1024px에서 1152px(`max-w-6xl`)로 넓힌다. 헤더·본문·푸터가 같은 폭을 쓰므로 다른 페이지도 조금 넓어진다.
- 보고서 파일과 루틴 규칙은 바꾸지 않는다.

## 2. 현재 (2026-11-03)

- 사이트 폭 `max-w-5xl`(1024px), 보고서 본문 `max-w-3xl`(768px) 가운데 정렬
- 소제목에 id가 없어 특정 절로 바로 가는 링크를 만들 수 없다.
- 11-03 보고서의 소제목 수: 보안 `##` 4 + `###` 4, AI 5 + 7, S&P500 5 + 6
- 같은 작업의 다른 날짜로는 본문 아래 이전/다음 카드와 홈 캘린더로만 이동한다.

## 3. 결정 사항

### 확정 (사용자 2026-11-03)

- **D1. 왼쪽 = 같은 작업의 날짜 목록.** 문서 사이트의 페이지 목록에 해당한다.
- **D2. 목차 깊이 = 큰 절(`##`) + 항목(`###`).** 항목은 들여 쓰고, 긴 제목은 두 줄까지 보이고 자른다.
- **D3. 휴대폰에서는 접힌 "목차" 상자.** 태그 아래에 두고, 눌러야 펼쳐진다.

### 구현 방향 (Claude 제안)

- **D4. 화면 폭별 배치**
  - 1280px 이상(`xl`): 왼쪽 날짜 목록(10rem) | 본문 | 오른쪽 목차(13rem). 본문은 약 660px로, 한국어 한 줄 40자 안팎이라 지금(768px, 48자 안팎)보다 읽기 편하다.
  - 1024~1279px(`lg`): 본문 | 오른쪽 목차. 날짜 목록은 숨긴다(이전/다음 카드가 있다).
  - 1024px 미만: 본문 한 칸, 목차는 접힌 상자.
  - 왼쪽·오른쪽 칸은 스크롤해도 화면에 붙어 있고(sticky), 길면 칸 안에서 스크롤한다.
- **D5. 날짜 목록**: 이 보고서를 가운데 두고 앞뒤 최대 15개 날짜를 보여 준다. 날짜 앞에 level 점(색은 level에만 쓰는 디자인 규칙 그대로)을 찍고, 지금 보고 있는 날짜는 굵게 표시한다. 맨 위는 작업 이름(작업 목록 링크), 맨 아래는 "전체 보기 →".
- **D6. 소제목 id**: Markdown을 파싱해 소제목마다 GitHub 방식 slug(`1-긴급-조치-요약`)를 붙인다. 같은 이름이 또 나오면 `-1`, `-2`를 붙인다. 목차와 본문이 같은 함수로 id를 만들어 어긋나지 않게 한다. 새 패키지는 들이지 않는다(react-markdown이 이미 쓰는 `unified`·`remark-parse` 등을 직접 의존성으로 적기만 한다).
- **D7. 현재 위치 표시**: 스크롤하면 지금 읽는 절을 목차에서 진하게 표시한다(클라이언트 컴포넌트). 자바스크립트가 없어도 목차 링크는 동작한다.
- **D8. 앵커 위치**: 상단 헤더(sticky)에 소제목이 가리지 않게 `scroll-margin-top`을 준다.
- **D9.** 소제목이 2개 미만이면 목차를 표시하지 않는다.

## 5. 케이스

- T1. 같은 이름의 소제목 두 개 → `요약`, `요약-1`
- T2. 소제목에 코드·링크·굵게가 섞임 → 글자만 뽑아 목차에 표시
- T3. 본문의 `#` 제목(h1) → 화면에서는 h2로 낮추므로 목차에서도 큰 절로 취급
- T4. 코드 블록 안의 `#` 줄 → 소제목이 아니다(Markdown 파서가 구분)
- T5. 소제목이 기호뿐이라 slug가 비면 → `section-N`
- T6. 첫 보고서·최근 보고서처럼 앞이나 뒤에 날짜가 모자라면 → 있는 만큼만
