- AI 에이전트의 외부 네트워크 접근 제한

주요 내용은 다음과 같습니다.

- AI 에이전트를 이용해 기존 샌드박스의 취약점 탐색
- 여러 취약점을 조합한 VM 탈출 경로 발견

**Node.js·Docker 개발자 관점**

이 사례는 컨테이너 격리만으로 AI 에이전트의 실행 안전성을 완전히 보장할 수 없다는 점을 보여줍니다.

AI 에이전트에 Shell 실행 권한을 부여한다면 파일시스템 격리뿐 아니라 네트워크 접근 정책, 클라우드 IAM, 실행 로그까지 독립적으로 통제해야 합니다.

단, 이는 OpenAI의 내부 훈련 환경에 관한 연구이며 일반 사용자의 Codex가 동일한 취약점을 가지고 있다는 발표는 아닙니다.

### ⑤ GitHub — Microsoft Teams에서 Copilot에 개발 작업 위임
**발표: 10월 23일 | 중요도: 높음 | 개발 자동화**

GitHub가 Microsoft Teams와 GitHub Copilot의 연동 기능을 확대했습니다.

이제 Teams에서 GitHub Issue 알림을 받은 다음, 해당 대화에서 `@GitHub`를 호출해 개발 작업을 위임할 수 있습니다.

**작업 흐름**

1. GitHub Issue가 Teams 채널에 전달됩니다.
2. 개발자가 `@GitHub`를 통해 버그 조사를 요청합니다.
3. Copilot이 Issue와 대화 내용을 분석합니다.
4. 버그 재현, 테스트 및 코드 수정을 수행합니다.
5. Pull Request를 생성해 개발자에게 검토를 요청합니다.

기능 구현, 테스트 커버리지 확대, 문서 수정에도 활용할 수 있습니다.

**제공 조건:** 유료 GitHub Copilot 플랜과 Cloud Sandbox 설정이 필요합니다. 조직에서는 관리자의 기능 활성화가 필요할 수 있습니다.

**개발자 관점**

단순한 챗봇 연동이 아니라 **이슈 접수 → 개발 작업 → PR 생성**을 하나의 흐름으로 연결한다는 점이 의미 있습니다.

개발자가 모든 작업을 직접 실행하기보다는 AI가 제안한 변경 사항을 검토하는 형태로 워크플로가 발전하고 있습니다.

**원문:** [GitHub 공식 발표](https://github.blog/changelog/2026-10-23-turn-notifications-into-code-with-github-copilot-in-teams) ([The GitHub Blog](https://github.blog/changelog/2026-10-23-turn-notifications-into-code-with-github-copilot-in-teams))

또한 기존에 종료가 예고됐던 `deep-research-pro-preview-12-2025`의 종료 예정일이 **10월 23일**이었습니다. 이는 신규 발표가 아니라 이전에 공지된 일정이며, 실제 API 차단 여부는 별도 검증하지 않았습니다. 해당 모델을 사용한다면 지원 모델로의 마이그레이션을 확인해야 합니다. ([Google AI for Developers](https://ai.google.dev/gemini-api/docs/changelog))

## 3. 오늘 시도해 볼 만한 것

### 추천 1 — Codex `/presets`로 코드 검증 워크플로 만들기

오늘 공개된 기능 중 가장 직접적으로 적용할 만한 것은 Codex의 `/presets`입니다.

예를 들어 NestJS 프로젝트의 반복적인 코드 검토 기준을 다음과 같이 정의해 볼 수 있습니다.

```text
NestJS Service Review

1. 트랜잭션 경계가 적절한가?
2. 동시 요청으로 상태 불일치가 발생할 수 있는가?
3. API 호출에 멱등성이 필요한가?
4. 예외 처리 시 데이터 정합성이 유지되는가?
5. 인증·인가 검증이 누락되지 않았는가?
6. E2E 테스트가 핵심 예외를 검증하는가?

코드를 수정하지 말고 문제점과 근거만 보고한다.
```

이런 프롬프트를 Preset으로 저장하면 서비스 구현 이후 검토 과정을 반복하기 편해집니다.

### 추천 2 — AI 에이전트 실행 권한 점검

OpenAI와 Anthropic이 같은 날 공개한 보안 연구는 공통된 문제를 보여줍니다.

**AI 에이전트가 실행 환경을 이해하고 스스로 문제 해결 방법을 찾아내는 능력이 향상되면서, 소프트웨어적인 접근 제한만으로 충분하지 않을 수 있다는 것**입니다.

실제 개발 환경에서 AI에게 Shell 권한을 제공한다면 다음 사항을 우선 확인하는 것을 권장합니다.

- 클라우드 접근키와 프로덕션 비밀정보에 대한 접근 제한
- GitHub 쓰기 권한 및 배포 권한 분리
- 외부 네트워크 접근 정책
- 중요한 명령 실행에 대한 승인 절차
