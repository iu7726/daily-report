### 1. Vercel AI SDK `ai` 7.0.178 — 자동 거부된 도구 호출 승인 우회 수정

11월 21일 01:52 KST(npm 게시)에 `ai` 7.0.178이 나왔습니다. `experimental_toolApprovalSecret`을 설정하면 도구 승인 요청에 서명이 붙는데, 승인 정책이 자동으로 거부한 도구 호출의 요청에도 서명이 붙고 있었습니다. 메시지 기록을 조작할 수 있는 클라이언트가 이 요청을 "승인" 응답과 함께 돌려보내면 거부된 도구가 실행됐습니다.

이제 자동 거부된 요청에는 서명이 붙지 않아 그런 응답은 `AI_InvalidToolApprovalSignatureError`로 거부됩니다. 다만 이전 버전이 자동 거부에 발급한 서명은 계속 유효하므로, 무효화하려면 비밀값을 바꿔야 합니다. 비밀값을 바꾸면 사용자 결정을 기다리던 승인 요청은 다시 받아야 합니다.

같은 버전에서 `prepareStep`이 같은 메시지 배열을 여러 단계에 돌려줄 때 승인 함수가 응답별 도구 호출을 구분하지 못하던 문제, `streamText`가 미리 보기 도구 결과를 최종 결과로 기록하던 문제, 다운로드 오류의 파일 URL이 텔레메트리로 나가던 문제도 고쳤습니다. 08:21 KST에 나온 7.0.179는 AI Gateway에서 `openai/gpt-live-1`·`gpt-live-1.1` Live 모델을 WebSocket으로 쓰는 `gateway.experimental_realtime()`을 추가했습니다. 6.x 쪽에는 5.0.292도 함께 게시됐지만 내용은 확인하지 않았습니다.

> 결제·삭제처럼 위험한 도구를 승인 정책으로 자동 거부하던 Node 서비스라면 오늘 7.0.178 이상으로 올리고, 대화 기록을 클라이언트가 그대로 보내는 구조라면 `experimental_toolApprovalSecret` 값도 바꾸세요.

- 발표: 2026-11-20(미국 날짜) · [ai CHANGELOG](https://github.com/vercel/ai/blob/main/packages/ai/CHANGELOG.md)

### 2. NestJS 12.6.0 — 어댑터로 앱 타입 추론, 기본 동작 변경 다수

11월 20일 21:47 KST(npm 게시)에 NestJS 12.6.0이 나왔습니다. `NestFactory.create(AppModule, new FastifyAdapter())`가 타입 인자 없이 `NestFastifyApplication`을 돌려주고(#18623), `WsAdapter`와 gRPC 서버에 `gracePeriod`(기본 10,000ms)를 둔 정상 종료 옵션이 생겼습니다(#18589, #18566).

릴리스 노트는 호환성을 깨는 변경으로 분류하지 않았지만 "새 기본값과 동작 변경"으로 아래 항목을 따로 적었습니다.

| 변경 | 영향 |
|---|---|
| gRPC 정상 종료 시 `gracePeriod`가 지나도 남은 호출은 취소 (#18566) | 긴 스트리밍 RPC가 배포 중 끊길 수 있음 |
| 응답 객체를 돌려주는 사용자 정의 파라미터 데코레이터는 파이프를 건너뜀 (#18600) | Fastify에서는 이전에 핸들러가 아예 실행되지 않았음 |
| `@Res({ passthrough: true })` 핸들러를 `@Res()`로 재정의하면 `passthrough`를 상속하지 않음 (#18617) | 상속한 컨트롤러의 응답이 멈출 수 있음 |
| 문자열 `host`를 패턴으로 보고 라우트 충돌 검사 (#18609) | 시작 시 충돌 보고가 새로 나올 수 있음 |
| 테스트 모듈 `logger: true`가 로그를 끄지 않고 유지 (#18618) | 테스트 출력이 늘어날 수 있음 |
| Fastify는 `/`로 시작하지 않는 요청 대상에 400 반환 (#18569) | |
| 연결 전에 닫힌 NATS·MQTT 서버는 `listen()`이 "Connection closed"로 실패, 일부 클라이언트는 대기 요청을 실패 처리 (#18602, #18603, #18583 ~ #18585) | |
| 애플리케이션 종료가 시작되면 게이트웨이가 새 클라이언트를 거부 (#18588) | |

> NestJS 12.x를 쓰는 서비스는 12.6.0으로 올리기 전에 e2e 테스트를 돌리고, 특히 `@Res()`를 쓰는 컨트롤러 상속, 호스트 기반 라우팅, gRPC 스트리밍 종료 처리를 확인하세요. Fastify 앱이라면 `create<NestFastifyApplication>()` 타입 인자를 지워도 됩니다.

- 발표: 2026-11-20 · [NestJS 릴리스](https://github.com/nestjs/nest/releases)

### 3. Claude Code 2.1.330 — 동시 저장 설정 유실, 압축 뒤 멈춤 수정

11월 21일 04:16 KST에 2.1.330(Agent SDK 0.3.330)이 게시됐습니다. 여러 Claude Code 프로세스가 동시에 사용자 설정을 저장할 때 변경이 사라지던 문제와, 매우 긴 대화를 압축한 직후 몇 분씩 멈추던 문제를 고쳤습니다. 어제 다룬 2.1.329의 `~/.claude.json` 초기화 수정에 이어, 디스크가 가득 찼을 때 불완전한 백업이 정상 백업을 밀어내던 문제도 고쳐졌습니다.

| 구분 | 변경 |
|---|---|
| 기능 | Enterprise Admin Console이 관리하는 조직 로그인: `claude auth login` 뒤 조직 설정과 클라우드 제공자·게이트웨이를 적용 |
| 기능 | 차트를 그리는 내장 모드 easel (macOS·Linux, `/config`에서 자동 차트 끄기) |
| 수정 | API가 거부하는 입력 스키마를 가진 MCP 도구가 많을 때 "JSON schema is invalid"로 턴이 실패하고 세션 파일이 커지던 문제 |
| 수정 | 하위 에이전트가 선언한 MCP 서버가 한 하위 에이전트가 끝날 때 종료되던 문제 |
| 수정 | Linux에서 `node_modules`처럼 큰 무시 폴더가 있는 저장소의 Bash 명령 지연 |
| 수정 | `claude -p`가 출력 파일 디스크가 가득 찼을 때 메시지 없이 0으로 끝나던 문제 (이제 1로 종료) |
| 수정 | `claude -p --continue`에서 SessionStart 훅이 쓴 환경 변수 유실 |
| 수정 | `/mcp`가 플러그인 서버를 내장 서버로 표시하던 문제 ("Plugin MCPs"로 분리) |

> CI에서 `claude -p` 종료 코드로 성공 여부를 판단한다면 2.1.330부터 디스크 부족이 실패로 잡힙니다. 사내 MCP 서버를 하위 에이전트에서 선언해 쓰고 있었다면 중간에 연결이 끊기던 증상이 사라졌는지 확인해 보세요.

### `prototype` (mattpocock/skills)

설계 질문 하나에 답하려고 버릴 코드를 만드는 스킬입니다. 상태 모델이나 로직을 확인할 때는 버튼과 단계별 시나리오로 상태 기계를 직접 돌려 보는 HTML 파일 하나를 만들고, 화면을 고민할 때는 한 라우트에 여러 UI 변형을 URL 파라미터로 바꿔 보게 만듭니다. 상태는 기본으로 메모리에만 두고, 동작할 때마다 전체 상태를 보여 줍니다.

끝나면 검증된 결정만 실제 코드에 반영하고, 프로토타입은 main이 아닌 버릴 브랜치에 커밋한 뒤 이슈에 그 브랜치를 남기도록 안내합니다.
