## 3. 신규·업데이트 취약점 상세

### ① AWS API MCP Server — OAuth 토큰 대상 검증 우회

- **높음 · 신규 공식 공지**
- 2026-10-27 11:00 PDT / 10-28 03:00 KST
- **CVE-2026-115413 / GHSA-4prq-p2x5-w9fh**

AWS API MCP Server가 OAuth 토큰의 서명, 발급자, 만료 시각은 검증하면서도 해당 토큰이 **어떤 애플리케이션을 위해 발급됐는지(audience)** 확인하지 않는 문제다.

공격자가 같은 인증 테넌트 내 다른 애플리케이션용 정상 토큰을 확보하면, 이를 MCP Server에 제시하여 서버 호스트에 설정된 AWS 자격 증명으로 API 호출을 수행할 수 있다.

| 항목 | 내용 |
|---|---|
| 영향 제품 | `awslabs.aws-api-mcp-server` |
| 취약 버전 | 1.3.0 이상, 1.6.0 미만 |
| 수정 버전 | **1.6.0** |
| 공격 조건 | Streamable HTTP + OAuth 인증 구성 |
| 임시 완화책 | HTTP 대신 기본 `stdio` 전송 사용 |
| 실제 악용 | 확인되지 않음 |

업데이트 후 `AUTH_TYPE=oauth`를 사용하는 운영자는 `AUTH_AUDIENCE`를 설정해야 한다. Amazon Cognito처럼 액세스 토큰에 audience 클레임이 없는 경우에는 공식 지침에 따라 `AUTH_CLIENT_ID`를 사용한다.

이 취약점은 AWS IAM 서비스 자체가 뚫렸다는 의미는 아니다. **MCP Server의 인증 검증 계층이 잘못된 토큰을 허용하는 문제**다.

공식 원문: [AWS Security Bulletin 2026-152](https://aws.amazon.com/security/security-bulletins/2026-152-aws/)

캐시 오염 취약점(CVE-2026-109829)은 7.x·8.x에 해당한다. 이 문제는 originless `Agent`에 `compose(redirect(), cache())`와 공유 캐시를 함께 사용하는 경우에 한정된다.

**실무 판단:** 외부 API를 호출하는 NestJS 서버에서 위험성을 평가할 가치가 있다. 다만 일반적인 `fetch()` 호출이 곧바로 세 취약점 모두에 노출되는 것은 아니다.

Node.js 런타임 내장 `undici`와 npm에 별도로 설치한 `undici`는 패치 확인 경로가 다르다. 10월 21일 Node.js 보안 릴리스에도 `undici` 업데이트가 포함됐다.

### ③ Datadog dd-trace — URL 쿼리 문자열 ReDoS

- **High · CVSS v4.0 8.7**
- GitHub DB 10월 27일 등록
- **CVE-2026-116693 / GHSA-x94g-w73q-hpcw**

`dd-trace`가 URL 쿼리 문자열에 포함된 비밀번호·토큰 등을 마스킹할 때 사용하는 정규식이 특정 입력에서 과도한 백트래킹을 유발할 수 있다.

HTTP 요청 추적 중 이 정규식이 동기적으로 실행되기 때문에, 공격자가 조작한 URL이 Node.js 프로세스의 CPU를 장시간 점유하게 할 수 있다.

- **영향 버전:** 2.0.0 이상 5.131.1 미만, 6.0.0 이상 6.20.1 미만
- **수정 버전:** **5.131.1 / 6.20.1**
- **실제 악용:** 확인되지 않음

즉시 업그레이드가 어렵다면 공식 권고문에 제시된 수정된 `DD_TRACE_OBFUSCATION_QUERY_STRING_REGEXP` 설정을 임시 적용할 수 있다. 단순히 민감정보 마스킹을 해제하는 것은 권장하지 않는다.

Datadog APM을 사용하지 않는 환경에는 직접적인 영향이 없다.

공식 원문: [dd-trace 보안 권고문](https://github.com/advisories/GHSA-x94g-w73q-hpcw)

## 6. 최종 판단

오늘의 실제 업무 우선순위는 다음과 같다.

1. **Node.js·Docker의 Brotli 패치 확인:** CISA KEV 신규 등재로 위험 평가가 달라졌다.
2. **`undici` 및 `dd-trace` 확인:** 외부 API 호출·APM 사용 환경의 TLS 검증과 가용성 보호.
3. **AWS MCP 인증 검증 확인:** MCP Server를 HTTP/OAuth로 운영할 때만 해당.
4. **npm 공급망 점검:** 설치 이력이 있는 악성 패키지는 즉시 별도 사고 대응.
5. **기존 중요 패치 완료 확인:** React/Next.js, Claude Code, GitLab, PHP 등.

**오늘 가장 중요한 변화는 Brotli 취약점의 CISA KEV 신규 등재다.** 며칠 전에는 잠재적인 메모리 손상·RCE 위험으로 보고했지만, 이제는 실제 악용 근거가 존재하는 취약점으로 우선순위를 높여야 한다.

다만 현재 서버·저장소의 버전과 사용 경로를 직접 검사한 것은 아니다. **공식 취약점의 존재는 확인됐지만, 사용 중인 시스템의 실제 노출 또는 침해 여부는 별도 검증이 필요하다.**
