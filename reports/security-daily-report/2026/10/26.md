### ① [높음] AWS — TLS 인증서 신뢰 체계 취약점

- **CVE-2026-111943 | AWS 보안 공지 2026-150-AWS**

- 공식 공개: 2026년 10월 24일 20:00 PDT
- 한국 시간: **10월 25일 12:00 KST**
- 실제 악용: 공식 공지에서 확인되지 않음
- 영향: 인증서 검증 우회 및 신뢰할 수 없는 엔드포인트와의 TLS 통신 가능성

AWS가 신뢰하던 외부 인증기관 **eMudhra/emSign**의 중간 CA 개인키 8개가 취약하게 생성된 사실이 확인됐다.

P-384 타원곡선 개인키 생성 과정에서 난수 엔트로피가 심각하게 부족해, 해당 개인키를 수학적으로 복구할 수 있는 상태였다.

공격자가 복구된 키를 이용하면 영향을 받는 인증서 체인에서 위조 인증서를 생성할 위험이 있다.

단, 관련 중간 CA는 이미 10월 18~19일 폐기됐다. 인증서 폐기 여부를 엄격하게 검증하는 클라이언트에는 해당 공격이 통하지 않는다.

#### AWS 서비스별 조치 현황

| 서비스 | 조치 상태 | 사용자 조치 |
|---|---|---|
| AWS 공통 Trust Store | 10/21 수정 배포 | 일반적으로 불필요 |
| **CloudFront** | 10/28까지 인증서 신뢰 목록 변경 예정 | Origin 인증서 확인 |
| **ALB** | 10/29~31 OIDC/JWT 인증 관련 변경 예정 | IdP 인증서 확인 |
| EC2 Amazon Linux | 수정 패키지 제공 | `ca-certificates` 업데이트 |
| Amazon Cognito | AWS 측 수정 완료 | 일반적으로 불필요 |
| AWS STS | AWS 측 수정 완료 | 일반적으로 불필요 |
| boto3/botocore | 1.43.117 수정 | 사용 시 업데이트 |
| Bottlerocket | 10/26 수정 AMI 게시 목표 | 사용 시 업데이트 |

AWS는 영향을 받는 인증서 체인을 사용하는 CloudFront 및 ALB 고객에게 AWS Health를 통해 통지하고 있다.

**중요한 기한은 10월 28일이다.** 해당 CA를 사용하는 IdP 인증서는 그전까지 교체해야 하며, CloudFront 원본 인증서 역시 신뢰 목록 변경에 따른 TLS 연결 실패 가능성을 확인해야 한다.

#### 개발 환경에 대한 판단

CloudFront와 ALB를 모두 사용하는 환경이라면 확인할 가치가 높다.

다만 AWS OIDC를 GitHub Actions나 GitLab CI에서 사용하는 것과 **ALB의 OIDC 인증 기능을 사용하는 것은 별개**다.

ALB에서 OIDC/JWT 인증을 사용하지 않는다면 이번 ALB 관련 변경으로 인한 직접적인 영향은 제한적이다.

**권장 조치:** AWS Health 알림을 확인하고 CloudFront Origin 및 ALB IdP 인증서의 발급 체인을 확인한다. 일반적인 ACM 인증서까지 모두 교체할 필요는 없다.

공식 출처: [AWS Security Bulletin 2026-150](https://aws.amazon.com/security/security-bulletins/2026-150-aws/) ([Amazon Web Services, Inc.](https://aws.amazon.com/security/security-bulletins/2026-150-aws/))

**`w-mousekey`**

GitHub 보안 권고문은 이 패키지가 설치되거나 실행된 컴퓨터를 완전히 침해된 것으로 간주하고, 다른 안전한 컴퓨터에서 인증 정보와 키를 교체하도록 권고한다.

패키지 삭제만으로 정상 상태가 회복된다고 보장할 수 없다.

**`@drone-js-ext/core`**

확인된 전송 정보는 다음과 같다.

- 설치 경로
- 현재 작업 디렉터리
- Node.js 버전

즉, `npm install` 과정에서 개발 환경에 대한 정보가 외부로 전달될 수 있다.

**`react-native-bright-sdk`**

`preinstall` 단계에서 실행되는 스크립트가 호스트명과 설치 시각을 외부 HTTPS 엔드포인트로 전송한다.

**권장 조치:** 설치 여부를 먼저 확인한다. 실제 설치 이력이 발견되면 패키지별 악성 행위를 기준으로 개발 PC와 CI Runner의 침해 범위를 조사한다.

### ③ [높음] npm — Dependency Confusion 형태의 신규 악성 패키지

- **GitHub Advisory Database 등록: 2026년 10월 25일**
- **GHSA-79qp-32qv-632x**
- 영향 패키지: `@futurae-public/adaptive-js@99.9.1`

이 패키지의 특징은 `package.json`에 정상적인 npm 레지스트리 의존성 대신 외부 HTTPS 주소의 tarball이 직접 지정되어 있다는 것이다.

```json
{
  "dependencies": {
    "ltidisafe": "https://ltidi.storage.googleapis.com/depenconf/ltidisafe-3.9.2.tgz"
  }
}
```

이 구조는 외부 배포 파일을 패키지 설치 과정으로 끌어들이며, 권고문에 따르면 설치 시 실행되는 코드의 출처와 무결성을 충분히 보장하지 못한다.

또한 비정상적으로 높은 패키지 버전을 사용하는 점은 Dependency Confusion을 의심하게 한다.

공격자가 내부 패키지와 동일한 이름의 공개 패키지를 더 높은 버전으로 등록하면, 잘못 설정된 패키지 해석 과정에서 공격자 패키지가 선택될 수 있다.

**실무 영향:** 사설 npm 레지스트리를 사용하거나 내부 패키지를 혼합 관리하는 CI/CD 환경에서 특히 주의해야 한다.

다만 해당 패키지가 실제로 특정 기업의 내부 패키지를 대체해 침해에 성공했다는 사실까지 확인된 것은 아니다.

**권장 조치:** 사설 패키지 scope에 대한 registry 설정을 고정하고, lockfile의 외부 tarball URL과 출처 불명의 설치 스크립트를 점검한다.

공식 출처: [GitHub GHSA-79qp-32qv-632x](https://github.com/advisories/GHSA-79qp-32qv-632x)

## 6. CISA KEV 및 실제 공격 확인 현황

이번 조사에서 확인 가능한 CISA의 최근 공식 발표는 **10월 23일 신규 KEV 등록 공지**다.

10월 25~26일의 추가 등록 여부는 CISA 원본 페이지 접근 제한으로 직접 검증하지 못했다. 따라서 신규 등재가 없다고 확정하지 않는다. ([CISA](https://www.cisa.gov/news-events/alerts/2026/10/23/cisa-adds-one-known-exploited-vulnerability-catalog))

오늘 신규로 소개한 AWS CA 취약점과 npm 악성 패키지들에 대해서도 실제 침해 발생 규모를 확인할 수 있는 공식 자료는 확보하지 못했다.

**악성 코드가 확인된 것과 실제로 특정 사용자가 침해된 것은 다른 판단이다.**

## 7. 최종 판단

**오늘 우선 처리할 항목은 두 가지다.**

첫째, AWS CloudFront와 ALB에서 이번 인증서 신뢰 목록 변경의 영향 여부를 확인한다. 10월 28일이라는 구체적인 대응 기한이 있다는 점에서 우선순위가 높다.

둘째, npm 공급망을 점검한다. 특히 개발 PC와 CI Runner에서 출처가 불분명한 패키지가 최근 설치됐는지 확인할 필요가 있다.

Node.js·React·Next.js는 오늘 새로운 긴급 패치가 확인되지 않았지만, 이미 발표된 보안 업데이트가 운영 환경에 반영되지 않았다면 여전히 우선 처리 대상이다.

**종합:** 10월 26일 기준 새로운 핵심 위험은 AWS 인증서 신뢰 체계와 npm 공급망에 집중되어 있다. 일반적인 NestJS·PostgreSQL·Redis 애플리케이션에서 지난 24시간 새롭게 공개된 중대 취약점은 확인되지 않았다.

이번 리포트는 공개 자료를 검증한 결과이며, 실제 서버나 저장소에 접속해 버전·설치 이력·침해 여부를 검사한 결과는 아니다.
