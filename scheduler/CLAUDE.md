# 공통 실행 규칙

이 폴더의 작업 파일(`01-*.md` ~ `03-*.md`)을 실행해 보고서를 만들 때 모든 작업에 적용하는 규칙이다.
작업 파일의 지시와 충돌하면 작업 파일을 따른다. 작업 파일을 편집할 때는 이 규칙을 적용하지 않는다.

## 기본

- 시간대: Asia/Seoul(KST, UTC+09:00). 보고서의 날짜와 시각은 모두 KST로 적고, 해외 사건은 필요하면 현지 시각을 함께 적는다.
- 작업 파일의 일정과 Cron 표현식도 KST 기준이다.
- 보고 언어: 한국어
- "직전 24시간"은 실행 시각부터 거슬러 올라간 24시간(KST)을 뜻한다.
- 보고서 첫 줄은 각 작업이 지정한 제목 형식을 따르고, 둘째 줄에 `기준 시각: YYYY-MM-DD HH:mm KST`를 적는다.

## 정확성

- 모든 정보는 실행 시점의 최신 공개 자료를 웹에서 찾아 검증한다.
- 공식 발표, 릴리스 노트, 정부·기업의 1차 자료를 우선한다. 2차 보도로만 확인되는 내용은 "미확인 보도"로 따로 표시한다.
- 확인되지 않은 수치, 날짜, 버전, 사건, 식별번호(CVE 등)를 만들어내지 않는다. 확인할 수 없는 값은 "확인 불가"로 적는다.
- 정보 발표일과 실제 사건 발생일을 구분한다.
- 최신 자료가 없으면 과거 자료를 신규 정보처럼 재사용하지 않는다.
- 모든 항목에 출처 링크와 실제 발표 날짜를 적는다. 링크는 직접 확인한 원문 URL만 쓰고, 검색 결과 페이지나 추정한 URL은 쓰지 않는다.

## 보고 형식

- 결론과 즉시 필요한 조치를 맨 위에 먼저 적는다.
- 작업에 적힌 항목 수(예: 5~8건)는 목표치다. 해당 소식이 적으면 억지로 채우지 않고 있는 만큼만 적는다.
- 이전 보고에서 다룬 사건은 새로운 변화가 있을 때만 다시 다룬다. 이전 보고는 아래 '결과 저장'의 보고서 폴더에서 확인한다.

## 작업 유형

각 작업 파일 상단의 `유형`을 따른다.

- **보고서형**: 새 소식이 없어도 보고서를 반드시 저장한다. 실행 기록만 남기고 본문을 생략하지 않으며, 새 소식이 없으면 그 사실을 밝힌 짧은 보고서를 저장한다.
- **조건부 알림형**: 조건이 성립하지 않으면 보고서 파일을 만들지 않고 커밋도 하지 않는다.

## 결과 저장

보고서는 저장소에 Markdown 파일로 저장하고 커밋한다.

1. **이전 보고 확인**: 작성하기 전에 `reports/<작업 ID>/`에서 가장 최근 보고서 2개를 읽고 이미 다룬 사건을 파악한다. 폴더가 없으면 첫 실행으로 보고 건너뛴다.
2. **저장 경로**: `reports/<작업 ID>/YYYY-MM-DD.md` (실행일의 KST 날짜). `작업 ID`는 각 작업 파일 상단에 있다. 같은 날짜 파일이 이미 있으면 덮어쓴다.
3. **파일 형식**: 맨 앞에 아래 frontmatter를 넣고, 그 다음 줄부터 보고서 본문(제목 줄, 기준 시각 줄, 본문)을 적는다.

   ```yaml
   ---
   title: "[YYYY-MM-DD 작업 제목]"
   task: <작업 ID>
   date: YYYY-MM-DD
   generated_at: YYYY-MM-DDTHH:mm:ss+09:00
   summary: "보고서 결론 한 줄"
   ---
   ```

4. **커밋·푸시**: 보고서 파일만 `git add` 하고 `report(<작업 ID>): YYYY-MM-DD` 메시지로 커밋한 뒤 `main` 브랜치에 push한다. push가 거부되면 `git pull --rebase origin main` 후 다시 push한다.
5. 보고서 파일 외의 파일(작업 파일, 이 규칙, 사이트 코드 등)은 수정하지 않는다.
