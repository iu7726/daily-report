## 5. 런타임·프레임워크

참고

- ① ExcelJS 4.4.0 이하 — 스트리밍 `WorkbookWriter`의 `addImage`에 넘긴 이미지 파일 이름에 `../`를 넣으면 Node.js 프로세스가 읽을 수 있는 아무 파일이나 만든 엑셀 파일 안에 담깁니다(CVE-2026-128347, CVSS 4.0 8.7). 공유 수식 처리의 정규식 서비스 거부도 함께 공개됐습니다(CVE-2026-128345, 6.9). 사용자 입력으로 이미지 경로를 정하는 엑셀 내보내기 기능만 해당합니다. npm 최신 정식판이 2023년의 4.4.0이라 수정 버전은 없고, 이미지 경로를 서버가 정한 폴더 안으로 제한해 막아야 합니다. NVD 공개 2026-11-13 19:18 KST · [NVD CVE-2026-128347](https://nvd.nist.gov/vuln/detail/CVE-2026-128347) · [NVD CVE-2026-128345](https://nvd.nist.gov/vuln/detail/CVE-2026-128345)
- ② `create-ecdh` 4.0.4 이하 — 브라우저 번들용 순수 JavaScript 구현이 상대 공개 키가 곡선 위의 점인지 검사하지 않아, 같은 개인 키를 계속 쓰는 쪽은 개인 키가 노출될 수 있습니다(CVE-2026-129319). 최신 Node.js에서는 내장 `crypto`를 그대로 쓰므로 해당하지 않고, `crypto-browserify`로 브라우저에서 ECDH를 직접 쓰는 경우만 해당합니다. 4.0.5에서 고쳐졌습니다(2026-11-14 15:47 KST 배포). NVD 공개 2026-11-14 16:17 KST · [NVD CVE-2026-129319](https://nvd.nist.gov/vuln/detail/CVE-2026-129319)
- ③ `webpack-dev-middleware` — 9월 권고(CVE-2026-76844, `publicPath`가 `/`로 끝나지 않을 때 개발 서버 밖 파일 읽기)의 GitHub DB 항목이 바뀌어 7.x 줄도 영향 범위에 넣고 수정 버전을 7.4.6으로 표기했습니다. 권고 본문은 여전히 "8.3.0에서만 수정, 7.x 이하 백포트 없음"이라고 적어 서로 엇갈리므로, 개발 서버를 네트워크에 열어 둔다면 8.3.0 이상으로 올리는 편이 확실합니다. DB 변경 2026-11-14 11:57 KST · [OSV GHSA-g84c-rxfj-3j2c](https://osv.dev/vulnerability/GHSA-g84c-rxfj-3j2c)
- 그 밖의 npm 권고 1건: PSD 파서 `ag-psd`의 메모리 고갈(CVE-2026-62297, 31.0.0 수정)이 2026-11-14 08:19 KST에 GitHub DB에 등록됐습니다.

`react`(19.3.1), `next`(16.4.6), `undici`(8.12.4), `express`(5.3.0), `fastify`(5.12.8), `@nestjs/core`(12.5.0), `typescript`(7.0.2), `hono`(4.13.18)는 조사 기간에 새 정식 버전과 OSV 권고가 없습니다.
