### 1. @google/genai 3.0.0 — 기본 API 버전 v1, Node.js 22 이상 필요

Google Gen AI JavaScript SDK 3.0.0이 11월 6일 13:34 KST에 npm `latest`로 올라왔습니다. 호환성을 깨는 변경이 세 가지입니다.

| 변경 | 내용 |
|---|---|
| 기본 API 버전 | Gemini Developer API 클라이언트는 `v1beta` → `v1`. `vertexai: true` 클라이언트는 `v1beta1` 그대로 |
| Node.js | `engines.node`가 `>=22.0.0`. Node.js 20을 써야 하면 `@google/genai@^2`로 고정 |
| 타입 | Interactions API `CodeExecutionResultStep.result`가 `string`에서 `Array<Content> \| string`으로 변경 |

기본 버전은 환경 변수 `GOOGLE_GENAI_API_VERSION`(예: `beta`, `v1beta`)이나 생성자 옵션 `apiVersion`으로 되돌릴 수 있습니다. 기능으로는 `FinishReason`에 `MALFORMED_RESPONSE`가 추가됐고, Gemini API에서 `GenerateVideos`가 비활성화됐습니다.

> `v1beta`에만 있는 기능(미리보기 모델, 베타 필드)을 쓰는 NestJS 서비스는 업그레이드 즉시 요청이 실패할 수 있으니 `new GoogleGenAI({ apiVersion: 'v1beta' })`로 명시한 뒤 올리세요. `finishReason`을 전수 `switch`로 처리한다면 `MALFORMED_RESPONSE` 분기를 넣고, `step.result`를 문자열로 쓰는 코드는 `typeof` 검사가 필요합니다.

- 발표: 2026-11-06 · [CHANGELOG](https://github.com/googleapis/js-genai/blob/main/CHANGELOG.md)

### 2. Claude Code 2.1.319 — 게이트웨이 뒤 auto mode 변경, MCP 작업 백그라운드 처리

11월 6일 09:58 KST에 2.1.319가 `latest`로 나왔습니다. 텔레메트리나 기능 플래그를 끈 환경, LLM 게이트웨이 뒤에서는 서버가 검사하지 못한 auto mode 호출을 내장 분류기로 대신 판단하지 않고 사용자에게 묻거나 거부합니다. 예전 동작은 `CLAUDE_CODE_AUTO_MODE_SERVER=0`으로 유지할 수 있고, Bedrock·Vertex·Foundry는 바뀌지 않습니다.

함께 바뀐 점도 많습니다. 안전 검사를 못 해 거부된 auto mode의 `claude -p`는 이제 종료 코드 1을 반환합니다. 권한 확인을 기다릴 도구 호출을 거부하고 턴을 계속하는 `permissions.denyInsteadOfPrompting` 설정과, MCP 서버가 작업(task)으로 실행한 도구 호출을 바로 백그라운드로 넘기는 기능(끄려면 `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND`)이 추가됐습니다. 이전 핸드셰이크를 쓰는 MCP 서버가 연결에 실패하거나 빈 결과를 돌려주던 문제도 고쳐졌습니다. `@anthropic-ai/claude-agent-sdk` 0.3.319도 같은 시각에 나왔습니다.

> 사내 LLM 게이트웨이를 거쳐 CI에서 auto mode로 `claude -p`를 돌리고 있다면 업그레이드 후 작업이 종료 코드 1로 실패할 수 있습니다. 무인 실행에는 `permissions.denyInsteadOfPrompting`을 켜서 권한 대기로 멈추지 않게 하고, 직접 만든 MCP 서버가 오래 걸리는 작업을 돌려준다면 결과가 나중에 전달되는지 확인하세요.

- 발표: 2026-11-06(npm 게시) · [변경 이력](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

### 3. NestJS 12.4.0 — 핸들러가 `Response`·스트림을 반환하면 그대로 전송

NestJS 12.4.0이 11월 6일(npm 게시 19:13 KST) 나왔습니다. 라우트 핸들러가 웹 `Response`, `ReadableStream`, async generator·Node.js `Readable` 같은 async iterable을 반환하면 `StreamableFile`로 바꿔 모든 어댑터에서 스트리밍합니다. 전에는 Express·Node 어댑터가 이런 값에 빈 객체 `{}`와 200을 보냈습니다.

PR 설명에 따르면 첫 청크 전에 난 오류만 예외 필터를 거치고, 그 뒤 오류는 연결을 끊습니다. 문자열이 아닌 값은 기본으로 NDJSON(`application/x-ndjson`)으로 나가고, 응답을 감싸는 인터셉터는 적용되지 않습니다. 이 밖에 MQTT 와일드카드 구독 응답 처리, `ParseArrayPipe` 오류 필드 보존, 테스트에서 `undefined` 값 프로바이더 오버라이드 적용 등 버그 수정이 들어갔습니다.

> LLM 토큰 스트림을 `async *` 핸들러에서 바로 `yield`해 내보낼 수 있게 됐습니다. 다만 PR이 호환성 변경으로 짚은 대로 MongoDB 커서처럼 `Symbol.asyncIterator`가 있는 객체를 반환하던 핸들러는 JSON 배열 대신 스트림으로 응답하니, 업그레이드 전에 커서를 그대로 반환하는 곳을 `toArray()`로 바꾸세요.

- 발표: 2026-11-06 · [릴리스 노트](https://github.com/nestjs/nest/releases/tag/v12.4.0) · [PR #18427](https://github.com/nestjs/nest/pull/18427)

### 4. openai Node SDK 7.53.0 — 에이전트 세션 오류를 스트림 이벤트로 전달

`openai` 7.53.0(11/6 18:20 KST)은 베타 Agents 스트림의 오류 처리를 바꿨습니다. `beta.agents.sessions.events.stream()`과 스트리밍 `beta.agents.sessions.create()`에서 세션 오류가 예외로 던져지지 않고 일반 이벤트로 전달됩니다. 전에는 예외와 함께 스트림이 닫혀 오류 뒤에 오는 세션 이벤트를 놓칠 수 있었습니다.

HTTP 오류, 네트워크 실패, 잘못된 JSON은 여전히 예외를 던지고, 오류 뒤 스트림이 끝나면 `finalResult()`는 성공 결과를 내지 않습니다.

> `try/catch`로만 에이전트 세션 실패를 잡던 코드는 업그레이드 후 실패를 놓칩니다. `for await` 루프 안에서 오류 이벤트를 확인해 처리하도록 바꾸세요.

- 발표: 2026-11-06(체인지로그 날짜) · [openai-node CHANGELOG](https://github.com/openai/openai-node/blob/master/CHANGELOG.md) · [PR #3120](https://github.com/openai/openai-node/pull/3120)
