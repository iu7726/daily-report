## 2. 오늘의 핵심 보안 이슈

### ① [P1] Node.js 번들 Brotli 디코더 OOB 쓰기, 실제 악용 확인 ("Node2Shell")
- **영향 기술·버전**: Node.js 26.x, 24.x, 22.x 중 패치 이전 버전과 모든 EOL 버전. `node:zlib`의 Brotli 해제 API와 내장 `fetch()`가 Brotli 응답을 풀 때 영향을 받는다(fetch 경로는 2차 보도 기준).
- **식별번호**: CVE-2026-111497. Node.js 공식 심각도 High. CVSS 확인 불가.
- **CISA KEV**: 등재(2026-10-27 추가, 연방기관 조치 기한 2026-11-10).
- **실제 악용**: 확인. KEV 등재를 근거로 한다. 공격 세부 내용은 CISA가 밝히지 않았다.
- **공격 조건·영향**: 원격 공격자가 인증 없이 조작한 Brotli 압축 스트림을 보내면 디코더 메모리가 손상된다. 그 결과 메모리 유출, 서비스 거부(DoS)가 생기고 원격 코드 실행(RCE)도 가능할 수 있다(KEV 설명).
- **패치**: v26.12.1, v24.22.1, v22.23.4. 2026-11-02 기준 nodejs.org 배포 목록에서 v22.23.4(2026-10-20, security 표시), v24.22.2(10-27), v26.13.0(10-28)까지 배포된 것을 확인했다.
- **임시 완화책**: 앱 코드 안에는 확실한 우회책이 없다는 보도가 있다. 당장 패치할 수 없으면 프록시나 WAF에서 Brotli(`Content-Encoding: br`)로 압축된 요청을 차단한다. 미확인 보도에 따르면 `Accept-Encoding: identity`를 지정해도 fetch의 Brotli 해제를 막지 못한다.
- **내 조치**: `node -v`가 위 패치 버전보다 낮으면 즉시 업데이트한다. `node:2x-*` 같은 Docker 베이스 이미지를 다시 받아 빌드하고, AWS Lambda나 ECS 런타임 버전도 확인한다. 같은 버그가 다른 Brotli 사용 제품에도 영향을 줄 수 있으니 OS 패키지 `brotli`도 업스트림 v1.2.1 이상으로 갱신한다.
- **출처**:

### ② [P1] GitLab CE/EE CI/CD 정규식 컴파일러 정수 오버플로, 무인증 RCE
- **영향 기술·버전**: GitLab Community/Enterprise Edition의 Self-managed 설치본. 정확한 영향 범위는 확인 불가. 미확인 보도에 따르면 GitLab.com은 이미 패치됐고 Dedicated 고객은 따로 조치할 필요가 없다.
- **식별번호**: CVE-2026-97229. CVSS 10.0(GitLab 평가, 2차 보도 기준이며 원문 미열람).
- **CISA KEV**: 등재(2026-10-29 추가, 기한 2026-11-01, 포렌식 분류(triage) 요구 대상).
- **실제 악용**: 확인(KEV). 공개 PoC가 있다는 보도도 있다(미확인 보도).
- **공격 조건·영향**: 인증 없이 CI/CD 설정에 조작한 정규식을 넣으면 GitLab 서버에서 임의 코드가 실행된다. KEV에 따르면 근본 원인은 Ruby/Onigmo 정규식 엔진이라 다른 제품에도 영향을 줄 수 있다.
- **패치**: 19.4.2, 19.2.8. 19.3 라인은 보도마다 19.3.4와 19.3.5로 갈려 확인 불가이니 19.3.5 이상을 권장한다. 패치는 2026-10-12에 배포됐다(2차 보도).
- **임시 완화책**: 확인 불가. 패치 전까지 인터넷 노출을 제한한다(VPN이나 IP 허용 목록).
- **내 조치**: Self-managed GitLab 19.x를 쓰고 있고 위 버전보다 낮으면 즉시 패치한다. 인터넷에 노출돼 있었다면 Runner 토큰, CI 변수, 배포 키를 교체하고 서버의 비정상 프로세스와 웹셸을 점검한다. 별도로 Ruby를 쓰는 서비스는 Ruby의 정규식 수정 공지를 확인한다.

  - KEV 항목에 적힌 벤더 공지(이 세션에서 접근 차단으로 직접 열람 불가): https://docs.gitlab.com/releases/patches/patch-release-gitlab-19-4-2-released/ , https://www.ruby-lang.org/en/news/2026/10/23/regexp-fixes-for-gitlab-cves

### ③ [P1] Next.js 10월 보안 릴리스: 무인증 RCE 2건과 DoS 1건
- **영향 기술·버전**:
  - GHSA-673q-mjm6-r5xr(CVE 없음): `next` 16.0.0 이상 16.4.1 미만. App Router와 Cache Components 환경에서 `use cache` 함수가 typed array를 반환할 때 발생한다.
  - GHSA-2464-fhr4-w9xw / CVE-2026-96889: `next` 10.0.0 이상 15.5.28 미만, 16.0.0 이상 16.4.1 미만. Image Optimization API에서 SVG를 처리할 때 발생한다(원인은 sharp라는 보도가 있다).
  - GHSA-p3m5-59mp-jv5r / CVE-2026-94482: `next` 13.0.0 이상 15.5.28 미만, 16.0.0 이상 16.4.1 미만. Server Actions를 이용한 DoS다.
- **CVSS**: 앞의 두 건은 CVSS v4 기준 Critical(벡터 `AV:N/AC:L/AT:P/PR:N/UI:N`), DoS는 High. 정확한 점수는 GHSA에 없어 확인 불가. 보도에 나온 9.5는 미확인이다.
- **CISA KEV**: 미등재(2026-10-30 카탈로그 기준).
- **실제 악용**: 확인 불가. `use cache` RCE의 PoC 저장소가 공개됐다는 보도가 있다(미확인 보도).
- **공격 조건·영향**: 인증 없이 원격으로 서버 코드를 실행할 수 있다. 단, 공격이 성립하려면 특정 기능 사용 같은 전제 조건(AT:P)이 있다.
- **패치**: Next.js **16.4.1**, **15.5.28**. React 측 수정(19.2.9)은 미확인 보도라 확인 불가.
- **임시 완화책**: GHSA에는 없다. SVG 건은 `images.dangerouslyAllowSVG`를 끄고 이미지 최적화 대상 도메인을 제한하면 노출을 줄일 수 있다(일반 권고이며 공식 완화책은 아니다).
- **내 조치**: Next.js 16.x가 16.4.1보다 낮으면 즉시 업데이트한다. 13~15.x가 15.5.28보다 낮으면 업데이트한다. 12 이하처럼 지원이 끝난 버전이면 지원 버전으로 옮긴다. Vercel이 아닌 셀프호스팅(EC2, ECS, 컨테이너) 환경은 다시 배포해야 반영된다. `npm audit`이 CVE 없는 GHSA를 놓칠 수 있으니 버전을 직접 확인한다.

### ④ [P1 · 미확인 보도 기반] Cursor Marketplace에 배포된 Claude Code 확장 2.1.313에 SSH 백도어
- **영향 기술·버전**: Cursor IDE 확장 마켓플레이스로 받은 Claude Code VS Code 확장 **2.1.313**(일부 보도는 2.1.312도 언급). 배포 시간은 2026-10-29 약 02:27~13:35 PT(KST 10-29 18:27 ~ 10-30 05:35)이고, 최대 5,000명이 영향을 받았다고 Cursor가 밝혔다(보도 인용).
- **영향 없음으로 보도된 것**: Microsoft VS Code Marketplace와 Open VSX 배포판, npm `@anthropic-ai/claude-code` CLI.
- **CVE/GHSA·CVSS·KEV**: 해당 없음 또는 확인 불가.
- **실제 악용**: 악성 빌드가 실제로 배포됐다(보도). Anthropic 측은 자사 시스템 침해가 아니라고 밝혔다고 보도됐다.
- **영향**: 공격자 SSH 공개키(라벨 `svc-telemetry`)를 `~/.ssh/authorized_keys`에 추가하고, 자동 실행(persistence)을 설치하고, 호스트 정보를 외부로 보낸다. macOS와 Windows에서는 SSH 활성화에 관리자 권한이 필요해 일부 단계가 실패할 수 있지만, 키 추가와 정보 유출은 수행된다고 한다.
- **패치**: 2.1.314(보도 기준).
- **내 조치**: 해당 기간에 Cursor를 쓰면서 Claude Code 확장을 업데이트했다면 다음을 한다. ① 확장 버전 확인 후 2.1.314 이상으로 교체 ② `authorized_keys`에서 모르는 키 삭제 ③ LaunchAgents, 작업 스케줄러, crontab 점검 ④ 해당 PC에 있던 SSH 키, 클라우드(AWS) 자격증명, API 토큰 교체 ⑤ 의심되면 장비 격리. Cursor를 쓰지 않으면 해당 없다.
- **출처**: Cursor와 Anthropic의 공식 원문은 이 세션에서 직접 열람하지 못해 확인 불가. 2차 보도(검색으로 확인):

## 4. 미확인 보도·루머

- **Redis CVE-2026-25243 실제 악용 보도**: 캐나다 사이버보안센터 공지 AV26-423이 2026-10-19 갱신되면서 "오픈소스 보고에 따르면 악용 중"이라고 적었다는 검색 결과가 있으나 원문은 열람하지 못했다. KEV에는 미등재다. 2026-05 Redis 공지의 수정 버전(6.2.22, 7.2.14, 7.4.9, 8.2.6, 8.4.3, 8.6.3)이 불완전했고 더 높은 버전이 필요하다는 보도도 있다(확인 불가). Redis를 직접 운영한다면 redis.io 보안 공지에서 최신 패치판을 확인하고 적용하고, 인증과 네트워크 격리 상태를 점검할 것을 권장한다.
- **nginx 1.31.7 / 1.30.6 (2026-10-14) 보안 수정**: CVE 5건, 그중 3건이 CVSS v4 9.2라는 벤더 블로그(HeroDevs) 보도가 있다. nginx 공식 보안 공지는 직접 확인하지 못했다. nginx를 직접 운영하면 공식 공지를 확인하고 최신 안정판을 적용하기를 권장한다.
