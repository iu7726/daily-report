## 3. 클라우드 (AWS)

### ① [P2] Amazon SSM Agent — Windows AMI 인스턴스가 같은 등록 키를 공유

2026-09-09 이전에 나온 AWS 제공 Windows Server AMI에서는, 같은 AMI로 띄운 인스턴스가 모두 하나의 SSM Agent 등록 키를 나눠 썼습니다. 그래서 DHMC로 관리되는 인스턴스에서 관리자 권한이 없는 로컬 사용자가 그 인스턴스의 DHMC 역할 자격 증명을 얻을 수 있습니다.

에이전트를 제자리에서 3.3.5226.0으로 올려도 공유 키는 그대로 남습니다. AWS는 새 AMI로 인스턴스를 다시 띄우라고 안내했고, 에이전트 Vault를 지우는 방법은 DHMC 관리를 망가뜨린다고 밝혔습니다.

Windows EC2 중 영향 AMI로 띄웠고 DHMC를 켠 경우만 해당합니다. Linux 인스턴스나, DHMC 대신 인스턴스 프로필로 SSM을 쓰는 경우는 공지 범위에 없습니다.

| 영향 버전 | 수정 버전 | 식별번호 | CVSS | KEV·실제 악용 |
|---|---|---|---|---|
| SSM Agent 3.3.5226.0 미만 · 2026-09-09 이전 AWS Windows Server AMI | SSM Agent 3.3.5226.0 (2026-09-09 이후 AMI에 포함) | CVE-2026-134069 · GHSA-rfpp-9v45-jjv4 | 7.3 (CVSS 3.1) · 8.2 (CVSS 4.0) | 미등재 · 확인 불가 |

> 에이전트 업데이트로는 고쳐지지 않습니다. 영향 AMI로 띄운 Windows 인스턴스는 새 AMI로 교체해야 합니다.

- DHMC를 켜 두었고 2026-09-09 이전 Windows AMI로 띄운 인스턴스가 있다면, 2026-09-09 이후 AMI로 다시 띄워 교체합니다.
- 바로 교체할 수 없다면 그 인스턴스의 관리자 아닌 로컬 계정 접근을 줄입니다. DHMC 역할에 붙은 권한이 최소한인지도 함께 봅니다.

## 6. 데이터베이스

### ④ [P2] Elasticsearch — 인증 없이 전송 계층에서 다른 요청의 메모리 읽기

Elasticsearch 전송 계층의 LZ4 압축 해제가 선언된 블록 밖의 공유 네트워크 버퍼까지 읽습니다. 그래서 전송 포트에 닿을 수 있는 공격자가 조작한 압축 요청을 보내 다른 요청의 데이터를 받아 갈 수 있습니다. 원격 클러스터(remote-cluster) 전송 인터페이스가 열려 있으면 인증도 필요 없습니다.

자체 운영(self-managed) Elasticsearch의 노드 간 전송 포트나 원격 클러스터 포트가 신뢰할 수 없는 네트워크에 닿는 경우가 해당합니다. Elastic Cloud Hosted에는 공개 전에 프록시 쪽 완화가 들어갔지만 자체 운영 환경은 직접 올려야 합니다.

| 영향 버전 | 수정 버전 | 식별번호 | CVSS | KEV·실제 악용 |
|---|---|---|---|---|
| 7.14.0 ~ 7.17.29, 8.0.0 ~ 8.19.23, 9.0.0 ~ 9.4.8, 9.5.0 ~ 9.5.5 | 8.19.24, 9.4.9, 9.5.6 | CVE-2026-82303 · ESA-2026-cg7q-c6wj | 7.5 (CVSS 3.1) | 미등재 · 확인 불가 |

- 자체 운영 중이라면 8.19.24 / 9.4.9 / 9.5.6 이상으로 올립니다. 7.x 수정판은 공지에 없습니다.
