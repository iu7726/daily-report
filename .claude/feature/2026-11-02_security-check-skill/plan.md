# 보안 점검 스킬 — 기획서

> 상태: **구현·로컬 검증 완료 (2026-11-02)**. `.claude/skills/security-check/` (SKILL.md, collect.py, 단위 테스트 17건).
> 남은 것: 사용자가 새 세션에서 "보안 점검해 줘"로 점검 대상·audit 질문까지 한 번 실행해 보기.
>
> 구현 변경점 (계획 대비):
> - **리포트는 기본 최근 3건** (계획은 7일치): 리포트마다 "최근 7일 미해결 이슈"를 이미 담고 있고, 7건이면 대화에 넣기에 너무 길다. `--count`로 늘릴 수 있다.
> - **판정 규칙은 `이름:범위` 형식, 판정은 스크립트가 한다**: Claude가 리포트에서 `next:>=16.0.0 <16.4.1 || …` 규칙을 뽑고, 버전 비교는 `collect.py`가 한다(사람·모델이 버전 비교를 틀리기 쉬움). `node:24` 같은 일부 버전은 구간으로 보고 취약/안전/불명확을 가른다.
> - **이 컴퓨터의 Node 버전(`node -v`)도 단서에 넣었다**: 첫 실행에서 개발 PC의 Node가 리포트 기준 취약 범위였는데 수집 대상에 없었다.
> - **같은 단서 중복 제거**: 멀티 스테이지 Dockerfile의 `FROM node:…`이 여러 번 찍혔다.
> - `| head`처럼 출력을 끊어도 BrokenPipe 오류 없이 끝나게 했다.
> - **점검 대상 선택(D13) 추가**: 처음 구현은 "저장소 상위 폴더 자동" 한 가지였다. `config` 하위 명령과 `resolve_scope()`로 자동/지정을 고르고 저장하게 했다. 깊이 기준을 점검 루트가 아니라 프로젝트 폴더로 바꿨다(기본 3, 이전 4와 같은 범위).
> - skill-creator의 정식 평가(하위 에이전트 비교 실행·뷰어)는 생략했다. 실제 점검 대상이 사용자의 로컬 프로젝트라 평가 결과물을 따로 만들기보다, 결정적인 부분(파서·판정·경로 거부)은 단위 테스트로, 흐름은 실제 환경 실행으로 확인했다.

## 0. TL;DR

- 매일 쌓이는 IT 보안 리포트를 **내 컴퓨터의 프로젝트**에 대 보는 스킬. 클라우드 루틴은 로컬 프로젝트를 볼 수 없어서, 이 연결은 로컬 스킬이 맡는다.
- 프로젝트 스킬(`.claude/skills/security-check/`)로 저장소에 넣어, fork한 사람도 자기 리포트로 그대로 쓴다.
- 흐름: 최신 보안 리포트 읽기 → 영향 패키지·런타임과 수정 버전 뽑기(Claude) → 로컬 프로젝트의 실제 설치 버전 수집(스크립트) → 대조 (+ 사용자가 고르면 `npm`/`pnpm audit`의 high·critical) → 프로젝트별 🔴 즉시 조치 / 🟠 확인 필요 / ✅ 해당 없음 + 업데이트 명령 제안.
- **읽기 전용.** 설치·업데이트·커밋·push를 하지 않는다. 결과는 화면과 저장소 밖 파일에만 남긴다.

## 1. 범위

**포함**: Node.js 프로젝트(npm·pnpm·yarn lockfile), Node 런타임 버전 단서, Dockerfile·compose의 이미지 태그, 최근 보안 리포트 대조, audit(high·critical)

**제외**: 자동 수정(`audit fix`, 버전 올리기), Node 외 언어 생태계(필요해지면 추가), 정기 자동 실행

## 2. 결정 사항

### 확정 (사용자 2026-11-02)

- **D1. 대상**: 점검 루트 아래 모든 프로젝트(모노레포 하위 포함)
- **D2. 범위**: 보안 리포트 항목 대조는 항상. `npm audit`·`pnpm audit`(high·critical)는 **실행할 때마다 안내 문구를 보여 주고 사용자에게 묻는다**(의존성 목록이 레지스트리로 전송되므로 사용자가 판단).
- **D3. 결과**: 화면 요약 + 로컬 파일
- **D4. 실행**: 직접 실행("보안 점검", "내 프로젝트 취약점 확인", `/security-check`)
- **D5. 위치**: 이 저장소의 프로젝트 스킬. fork한 사람도 쓸 수 있게 한다.

### 확정 (사용자 2026-11-02, 제안 승인)

- **D6. 리포트 출처**: 이 저장소에서 `git fetch` 후 `origin/<기본 브랜치>`의 `reports/security-daily-report/` 최근 7일치를 `git show`로 읽는다. 작업 트리를 바꾸지 않고, fork한 사람은 자기 fork의 리포트를 읽는다. 예전 경로(`YYYY-MM-DD.md`)도 읽는다. fetch가 실패하면 로컬 작업 트리의 리포트를 쓴다.
- **D7. 점검 루트**: 기본은 이 저장소의 상위 폴더(프로젝트를 나란히 clone해 두는 경우). `--root` 또는 환경 변수 `SECURITY_CHECK_ROOT`로 바꾼다. `node_modules`, `.git`, 빌드 산출물 폴더는 건너뛴다.
- **D8. 결과 파일**: 기본 `<점검 루트>/security-check/YYYY-MM-DD.md`, `--out`으로 변경. **이 저장소 안 경로는 거부한다**(결과에 프로젝트의 취약 버전이 들어가므로 공개 저장소에 올라가면 안 된다).
- **D9. 수집기는 Python 표준 라이브러리만**: 설치 없이 돈다. `pnpm-lock.yaml`·`yarn.lock`은 필요한 부분(패키지 이름·버전)만 정규식으로 읽는다.
- **D10. audit는 묻고 나서, 로컬 설정 그대로 실행한다**: 실행 전에 "각 프로젝트의 의존성 이름·버전 목록이 npm 레지스트리(사설 레지스트리를 쓰면 그곳)로 전송된다"는 안내와 함께 실행 여부를 묻는다. 거절하면 리포트 대조만 한다. 프로젝트의 `.npmrc`를 따른다. 실패(네트워크, 인증)는 "audit 실패"로 표시하고 다음 프로젝트로 넘어간다. 프로젝트당 60초 제한.
- **D11. 판정 기준**
  - 🔴 즉시 조치: 리포트 P1(실제 악용, KEV, 무인증 RCE) 대상이 설치돼 있고 수정 버전 미만, 또는 audit critical
  - 🟠 확인 필요: 리포트 P2 대상이 취약 버전, audit high, 영향 범위가 "확인 불가"인 리포트 항목에 해당, 설치 버전을 알 수 없음(lockfile 없음)
  - ✅ 해당 없음
- **D13. 점검 대상은 처음 실행할 때 고른다 (사용자 2026-11-02)**: 사람마다 프로젝트를 두는 방식이 달라서 자동 한 가지로는 부족하다.
  - 자동: 폴더 하나 아래의 폴더들을 프로젝트로 본다. 건너뛸 이름(`exclude`)을 받는다. 그 폴더 자체가 프로젝트면 그것 하나만 본다.
  - 지정: 흩어진 프로젝트 폴더 목록. 지정한 폴더 자체가 프로젝트여도 찾는다.
  - 스킬 폴더의 `config.local.json`(git 제외)에 저장한다. 이후에는 한 줄로 보여 주고 진행하고, "점검 대상 바꿔 줘"나 `--reset`으로 바꾼다.
  - 우선순위: 명령 옵션(`--root`, `--path`) > 환경 변수 `SECURITY_CHECK_ROOT` > 설정 파일 > 기본값(이 저장소의 상위 폴더, 자동). D7을 대체한다.
- **D14. 사이트에 안내 (사용자 2026-11-02)**: fork하는 사람이 스킬을 알 수 있게 홈 하단에 "직접 써 보기" 카드(GitHub, 스킬 설명 링크), IT 보안 목록 위에 한 줄 안내를 둔다.
- **D12. 클라우드 루틴 세션에서는 쓰지 않는다**: SKILL.md에 로컬 전용이라고 적는다(클라우드에는 점검할 로컬 프로젝트가 없다).

## 3. 케이스

- S1. 리포트를 못 받음(fetch 실패, 리포트 없음) → 로컬 작업 트리 → 그래도 없으면 audit만 하고 그 사실을 표시
- S2. lockfile 없음 → `package.json` 범위만 보여 주고 🟠 "설치 버전 불명"
- S3. 모노레포·workspaces → 하위 `package.json`도 프로젝트로 보되, 버전은 가장 가까운 상위 lockfile에서 찾는다
- S4. 같은 패키지가 여러 버전으로 설치됨(중첩 의존성) → 모두 보여 주고 가장 낮은 버전으로 판정
- S5. Node 버전 단서가 여러 곳(Dockerfile, `engines`, CI) → 모두 보여 주고 가장 낮은 것으로 판정
- S6. audit 실패 → 프로젝트별 "audit 실패(이유)" 표시, 전체 점검은 계속
- S7. 결과 경로가 이 저장소 안 → 거부하고 기본 경로를 안내

## 4. 구조

```
.claude/skills/security-check/
├── SKILL.md           # 절차, 판정 기준, 출력 형식, 지켜야 할 것
├── collect.py         # reports / inventory / audit 하위 명령
└── tests/             # lockfile 파서·판정 보조 함수 테스트 (표준 라이브러리 unittest)
```

- `collect.py reports [--days 7]`: 최근 보안 리포트 본문 출력
- `collect.py inventory --packages next,undici,...`: 프로젝트별 패키지 설치 버전, Node·이미지 버전 단서
- `collect.py audit`: 프로젝트별 audit 결과(high·critical 요약)
