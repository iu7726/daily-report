## 주요 항목

### ① [P1] Drupal core — 설치 프로그램으로 사이트 탈취, 실제 악용으로 KEV 등재

Drupal 설치 파일 `install.php`가 원격에서 열려 있고 사이트가 설치를 덜 마친 상태라면, 인증 없이 사이트를 빼앗을 수 있습니다. 11월 18일 SA-CORE-2026-017로 고친 설치 프로그램 취약점의 후속이고, Drupal은 이미 실제 공격이 일어나고 있다고 밝혔습니다. CISA가 11월 27일 KEV에 올렸습니다.

Drupal 사이트를 운영하는 경우만 해당합니다. 취약한 상태는 관리 화면에 보이지 않고, 이미 탈취된 사이트는 오히려 취약하지 않게 보일 수 있습니다. 설치 프로그램을 막아 둔 사이트는 해당하지 않습니다.

| 영향 버전 | 수정 버전 | 식별번호 | CVSS | KEV·실제 악용 |
|---|---|---|---|---|
| 10.6.23 미만, 11.0.0 ~ 11.3.22, 11.4.0 ~ 11.4.13 | 11.4.14, 11.3.23, 10.6.23 | CVE-2026-136716 (SA-CORE-2026-019) | 9.8 (NVD 보조 평가) | 2026-11-27 등재, 실제 악용 확인 |

> 업데이트만으로 끝나지 않습니다. `update.php`를 실행해야 기존 사이트의 취약한 상태가 고쳐지고, 관리자 계정(user 1)이 바뀌지 않았는지 확인해야 합니다.

- Drupal 사이트를 운영한다면 수정 버전으로 올리고 `update.php`를 실행해야 합니다. 11.2.x 이하와 10.5.x 이하는 지원이 끝나 수정판이 없습니다.
- 웹 서버 설정에서 `install.php` 접근을 막아야 합니다.
- 접근 기록에서 user 1 계정 변경을 확인하고, user 1 이메일을 내가 관리하는 주소로 맞춘 뒤 비밀번호를 바꾸면 됩니다.

- 원문: [Drupal SA-CORE-2026-019](https://www.drupal.org/sa-core-2026-019) (2026-11-25 · KEV 등재 2026-11-27)

## 참고

- ② Hono 4.13.22 이하 — `TrieRouter`가 일부 경로에서 `except()`로 건 미들웨어를 건너뛰고, 조작한 HTTP 메서드 이름 하나로 `Object.prototype`을 오염시켜 프로세스가 재시작될 때까지 오류를 냅니다. Bun에서 `getPath()`가 경로 첫 부분을 잃는 문제도 함께 고쳐져 4.13.23으로 올리면 됩니다. · [GHSA-586x-c76g-h528](https://github.com/honojs/hono/security/advisories/GHSA-586x-c76g-h528) (2026-11-26)
- ③ Convex의 Claude Code 플러그인 — `quickstart` 스킬이 사용자가 말한 앱 아이디어를 Convex 서버로 보내고, 다른 스킬은 고정되지 않은 원격 스크립트를 내려받아 `bash`로 실행합니다. 이 플러그인을 설치한 경우만 해당하며, 전송은 `CONVEX_PLUGIN_TELEMETRY=0`으로 끌 수 있습니다. · [이슈 #64](https://github.com/convex/convex-backend-skill/issues/64) (2026-10-26)
- ④ npm 악성 패키지 33건 — `agentkeepalive`를 흉내 낸 `agentkpalive`, Bun 타입을 흉내 낸 `bun-types-loader`·`bun-definitions`, PostCSS·Next.js를 흉내 낸 `postcsskit`·`@nextlayers/nextcsskit`이 있습니다. 기존 패키지 `@omnitron-dev/omnitron` 0.4.18과 `@pyraio/cli-win32-x64` 0.2.13도 지정됐습니다. 둘 다 주간 다운로드가 1천 회 미만입니다. · [GHSA-v8mr-2vmh-3xp3](https://github.com/advisories/GHSA-v8mr-2vmh-3xp3) (2026-11-27)
