# IT 보안 이슈 데일리 리포트

- 작업 ID: `security-daily-report`
- 유형: 보고서형
- 일정: 매일 09:30 KST (Cron `30 9 * * *`)

## 실행 프롬프트

첫 줄은 `[YYYY-MM-DD IT 보안 이슈 리포트]`로 작성해. 날짜는 실행일의 KST 날짜야.

직전 24시간 동안 새로 공개됐거나 중대한 변화(실제 악용 확인, KEV 등재, 패치 배포 등)가 생긴 보안 이슈를 우선 조사해. 파급력이 큰 경우에는 최근 7일 동안 해결되지 않은 중요 이슈도 포함해.

### 점검 대상

**핵심 기술 (상태표에 항상 한 행씩 포함)**

- Node.js
- TypeScript
- PostgreSQL
- Redis
- AWS (EC2, S3, CloudFront, ALB, ECR, IAM 포함)
- React
- Next.js
- Claude Code
- OpenAI Codex

**추가 모니터링 대상**

- NestJS
- npm 패키지 및 JavaScript/TypeScript 생태계의 소프트웨어 공급망
- GitLab 및 GitHub Actions CI/CD
- Docker
- MySQL, MongoDB
- Nginx

### 우선순위 기준

- **P1 (즉시 조치)**: 실제 악용이 확인됐거나, CISA KEV에 등재됐거나, 인증 없이 원격 코드 실행이 가능한 경우 등
- **P2 (이번 주 내 조치)**: CVSS 7.0 이상이거나 널리 쓰이는 기본 구성에 영향을 주는 경우
- **P3 (참고)**: 영향 범위가 제한적이거나 특정 조건에서만 발생하는 경우

### 보고서 구성

1. **긴급 조치 요약**: P1 이슈와 내가 즉시 해야 할 조치를 맨 위에 간결하고 구체적으로 적어. 해당 이슈가 없으면 "즉시 조치가 필요한 이슈 없음"이라고 적어.
2. **오늘의 핵심 보안 이슈**: 3~7개를 우선순위 순으로 정리하고, 항목마다 다음을 포함해.
   - 우선순위(P1/P2/P3)
   - 영향받는 기술과 버전
   - CVE/GHSA 번호, CVSS 점수, CISA KEV 등재 여부, 실제 악용 여부. 확인된 값만 적고 나머지는 "확인 불가"로 적어.
   - 공격 조건, 영향, 악용 가능성
   - 패치 버전과 임시 완화책
   - 내가 취할 조치. 내가 쓰는 버전을 모르니 "○○ 버전 사용 시"처럼 조건을 붙여.
   - 공식 원문 링크와 공개 날짜
3. **기술 스택별 상태표**: 핵심 기술은 모두 한 행씩 넣고, 추가 모니터링 대상은 이슈가 있을 때만 행을 추가해. 이슈가 없는 항목은 반드시 "확인된 신규 주요 이슈 없음"으로 표시해 누락과 무소식을 구별해. 추가 모니터링 대상 전체에 이슈가 없으면 표 아래에 한 줄로 밝혀.
4. **미확인 보도·루머**: 사실 확인이 안 된 내용은 이 섹션에 따로 적어.

상태표 형식 예시:

| 기술 | 상태 | 관련 이슈 | 조치 |
|---|---|---|---|
| Node.js | 확인된 신규 주요 이슈 없음 | - | - |
| Next.js | P1 | CVE-YYYY-NNNNN | 15.x.y 이상으로 업데이트 |
