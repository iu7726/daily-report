## 1. 긴급 조치 요약

**P1 이슈 2건**

1. **Node.js (Brotli, CVE-2026-111497)**: CISA KEV 등재(2026-10-27). 실행 중인 Node.js가 **v22.23.4 / v24.22.1 / v26.12.1 미만**이면 바로 업그레이드한다. 외부에서 받은 Brotli 압축 데이터(`Content-Encoding: br` 요청 본문, 업로드 파일 등)를 `node:zlib`로 푸는 서비스를 먼저 처리한다. 컨테이너 베이스 이미지(`node:*`)와 Lambda 런타임 버전도 함께 확인한다.
2. **GitLab self-managed (CVE-2026-97229, CVSS 10.0)**: CISA KEV 등재(2026-10-29), 인증 없이 원격 코드 실행 가능. 직접 운영하는 GitLab이 **19.2.8 / 19.3.5 / 19.4.2 미만**이면 즉시 패치하고, GitLab이 안내한 탐지 규칙으로 침해 흔적을 확인한다. GitLab.com 사용자는 조치할 필요가 없다(이미 패치됨).

**조건부 즉시 조치**

- **Next.js**: **16.4.1 / 15.5.28 미만**이면 2026-10-14에 공개된 Critical RCE 2건에 노출된 상태라 P1이다. 바로 올리고, 2026-11-03(화) 예정 보안 릴리스도 이번 주에 적용할 계획을 세운다.
- **GitHub Actions**: 저장소에 `ci-sync-`로 시작하는 낯선 브랜치나 `sync-check.yml` 워크플로가 보이면 토큰 탈취 캠페인(Gheist)에 감염된 것이다. 즉시 시크릿을 교체하고 토큰을 폐기한다.

## 2. 오늘의 핵심 보안 이슈

### ① [P1] Node.js — 번들 Brotli 디코더 범위 밖 쓰기 (CVE-2026-111497), CISA KEV 등재

- **영향 기술·버전**: Node.js 22.x, 24.x, 26.x의 보안 패치 이전 버전(EOL 버전도 영향받지만 수정되지 않음). 상위 라이브러리 Google Brotli도 영향(수정: Brotli v1.2.1).
- **식별 정보**: CVE-2026-111497 / CVSS 9.8(NVD v3.1), 9.2(Google CNA v4.0) / **CISA KEV 등재 2026-10-27**(연방기관 조치 기한 2026-11-10) / KEV 등재로 실제 악용이 확인됨. 랜섬웨어 연관 여부는 "Unknown"
- **공격 조건·영향**: 인증 없이 조작한 Brotli 스트림을 보내면 된다. 디코더가 잘못된 block switch를 "입력 부족"으로 처리하면서 8바이트 내부 버퍼 뒤에 계속 써서 프로세스 충돌, 메모리 노출, 원격 코드 실행이 가능하다. 신뢰할 수 없는 Brotli 데이터를 `node:zlib`(`brotliDecompress`, `createBrotliDecompress` 등)로 푸는 애플리케이션이 공격 대상이다.
- **패치**: Node.js **v26.12.1, v24.22.1, v22.23.4** 이상(2026-10-21 보안 릴리스)
- **임시 완화책**: 업그레이드 전까지 신뢰할 수 없는 Brotli 데이터를 풀지 않는다. 리버스 프록시에서 `Content-Encoding: br` 요청 본문을 거부하는 방법도 있다.
- **내 조치**:
  - Node.js 22/24/26 사용 시: 위 패치 버전 이상으로 올리고 Docker 이미지를 다시 빌드한다.
  - Node.js 20 이하(EOL) 사용 시: 수정이 제공되지 않으므로 지원 버전으로 옮긴다.
  - 같은 릴리스에 TLS 호스트 이름 검증 우회(CVE-2026-106069, CVE-2026-105483, High), DNS NUL 바이트 처리(CVE-2026-105482, High) 수정도 들어 있다.
- **출처**:

  - CISA KEV 카탈로그(등재 2026-10-27): https://www.cisa.gov/known-exploited-vulnerabilities-catalog

### ② [P1] GitLab CE/EE — CI/CD 정규식 컴파일러 정수 오버플로로 인증 없이 RCE (CVE-2026-97229), CISA KEV 등재

- **영향 기술·버전**: GitLab CE/EE 19.2(19.2.8 미만), 19.3(19.3.5 미만), 19.4(19.4.2 미만)
- **식별 정보**: CVE-2026-97229 / CVSS 10.0(GitLab, v3.1) / **CISA KEV 등재 2026-10-29**(기한 2026-11-01, 포렌식 점검 요구) / 실제 악용 확인(KEV)
- **공격 조건·영향**: 인증되지 않은 사용자가 CI/CD 설정에 조작한 정규식을 넣으면 GitLab 서버에서 임의 코드를 실행할 수 있다. CISA는 근본 원인인 Ruby/Onigmo 정수 오버플로가 다른 제품에도 영향을 줄 수 있다고 적었다(Ruby 측 공지 2026-10-23).
- **패치**: **19.4.2, 19.3.5, 19.2.8** 이상(2026-10-12 패치 릴리스). GitLab.com과 GitLab Dedicated는 이미 패치됐다.
- **임시 완화책**: GitLab은 패치 외 우회책을 제시하지 않았다. 패치 전까지 인터넷 노출을 줄이고, GitLab이 공개한 탐지 규칙("Onigmo native worker crash", "ci regexp guard rejection" 등 6종)으로 공격 시도를 점검한다.
- **내 조치**:
  - self-managed GitLab 운영 시: 즉시 패치하고, 패치 전 기간의 로그를 탐지 규칙으로 확인한다. 침해 흔적이 있으면 Runner 토큰과 CI 변수를 교체한다.
  - GitLab.com만 사용 시: 조치할 필요 없음.
  - Ruby 앱에서 사용자가 입력한 정규식을 컴파일하는 경우: Ruby 공지를 확인한다.
- **출처**:
  - GitLab 19.4.2 패치 릴리스 (2026-10-12): https://docs.gitlab.com/releases/patches/patch-release-gitlab-19-4-2-released/
  - CISA KEV 카탈로그(등재 2026-10-29): https://www.cisa.gov/known-exploited-vulnerabilities-catalog
  - Ruby 공지 (2026-10-23): https://www.ruby-lang.org/en/news/2026/10/23/regexp-fixes-for-gitlab-cves

### ③ [P2] GitHub Actions — 탈취한 GitHub 토큰으로 시크릿을 빼내는 "Gheist" 캠페인 진행 중

- **영향 기술**: GitHub 저장소와 Actions 시크릿(특히 비공개 저장소와 GitHub Enterprise Server). CVE는 없고, 탈취한 토큰을 악용하는 공격이다.
- **식별 정보**: CVE/GHSA 해당 없음 / CVSS 해당 없음 / KEV 해당 없음 / 실제 악용: 공격이 진행 중임을 Wiz가 확인(2026-10-24 기준)
- **공격 방식·영향**: 인포스틸러 로그나 이전 공급망 공격에서 유출된 토큰으로 `ci-sync-XXXXXX` 브랜치에 `.github/workflows/sync-check.yml`을 푸시한다. 이 워크플로가 시크릿을 base32로 인코딩해 마스킹을 피한 채 로그에 출력하면, 공격자는 로그를 내려받은 뒤 실행 기록을 삭제한다. 배포 환경 시크릿과 self-hosted 러너도 노린다. Wiz는 850여 개 계정에서 13,500개가 넘는 브랜치를 확인했다. GitHub의 의심 워크플로 보류 기능(2026-07-28 도입)은 github.com 공개 저장소에만 적용된다.
- **패치/완화**: 패치 대상이 없다. 환경에 리뷰어를 필수로 지정하고, OIDC 신뢰 정책을 보호 브랜치로 제한하고, PAT 대신 GitHub App이나 수명이 짧은 fine-grained 토큰을 쓴다.
- **내 조치**:
  - GitHub Actions 사용 시: `ci-sync-*` 브랜치와 "ci: sync config" 커밋이 있는지, 감사 로그에 1분 안에 삭제된 실행 기록이나 `gheist` user agent가 있는지 점검한다.
  - 흔적이 있으면: 저장소·조직·환경 시크릿을 모두 교체하고, 토큰을 폐기하고, 토큰 소유자 기기의 인포스틸러 감염 여부를 점검한다. 보류된 sync-check 실행은 승인하지 않는다.

  - The Hacker News 보도 (2026-10-26): https://thehackernews.com/2026/10/gheist-uses-stolen-github-tokens-to.html

### ④ [P2] undici — TLS 인증서 검증 우회, 공유 캐시 오염, 프로세스 종료 DoS

- **영향 기술·버전**: npm `undici` 4.x~6.29.0, 7.0.0~7.30.0, 8.0.0~8.12.1(항목별로 다름). Node.js에 내장된 `fetch`도 undici 기반이다.
- **식별 정보**:
  - CVE-2026-109383(GHSA-2m5v-pch6-74hx): `Agent`의 `tls.checkServerIdentity` 콜백이 무시돼 사용자 정의 인증서 검증이 우회된다. CVSS 7.4(GitHub), 9.1(NVD)
  - CVE-2026-109829(GHSA-4w7w-5xrc-9h26): `compose(redirect(), cache())`와 공유 캐시를 함께 쓰면 교차 출처 리다이렉트 응답이 원래 URL 키로 캐시된다. CVSS 7.4(GitHub), 9.1(NVD)
  - CVE-2026-87018(GHSA-qrxm-fqhp-jwvm): TLS 1.2 재협상 중 인증서가 바뀌면 프로세스가 종료된다(DoS). High
  - CVE-2026-109855(GHSA-qq8j-7v2v-3rwp): 8.11.0~8.11.1의 WebSocket 클라이언트가 HTTP/2 핸드셰이크 실패 시 프로세스가 종료된다(DoS). High
  - KEV 미등재, 실제 악용 확인 불가
- **공격 조건**: 악성 서버나 리다이렉트 대상을 공격자가 통제해야 한다. 기본 구성보다는 특정 옵션(사용자 정의 `checkServerIdentity`, 공유 캐시 인터셉터)을 쓸 때 영향이 크다.
- **패치**: undici **6.29.1 / 7.30.1 / 8.12.2** 이상
- **내 조치**:
  - `undici`를 직접 의존하는 경우: `npm ls undici`로 버전을 확인하고 패치 버전으로 올린다.
  - Node.js 내장 `fetch`만 쓰는 경우: 2026-10-21 Node.js 보안 릴리스에 undici 업데이트가 포함됐다. 다만 이번 4건이 그 안에 들어갔는지는 공식 문서로 확인되지 않았다(확인 불가). 다음 Node.js 릴리스 노트를 확인한다.

### ⑥ [P2] Redis — RESTORE 명령 취약점(CVE-2026-25243) 악용 보고

- **영향 기술·버전**: self-managed Redis OSS/CE, Redis Software. 수정 버전은 OSS/CE **6.2.22, 7.2.14, 7.4.9, 8.2.6, 8.4.3, 8.6.3**, Redis Software 8.0.10-64 등이다. Redis Cloud는 패치 완료.
- **식별 정보**: CVE-2026-25243 / CVSS 7.7(GitHub v4.0), 8.8(NVD v3.1) / KEV 미등재 / 실제 악용: 캐나다 사이버보안센터가 2026-10-19 갱신한 공지에서 "공개 출처 보고에 따르면 악용 중"이라고 밝혔다. Redis 공식 공지(2026-05-05)는 악용 증거가 없다고 했고, 이후 갱신은 확인되지 않았다.
- **공격 조건·영향**: **인증된 사용자**가 조작한 직렬화 데이터를 RESTORE 명령으로 보내면 서버에서 코드를 실행할 수 있다.
- **완화책**: 네트워크 접근을 제한하고, 인증을 강제하고, ACL로 `RESTORE` 같은 위험한 명령을 막는다.
- **내 조치**:
  - self-managed Redis를 위 수정 버전 미만으로 사용 시: 이번 주 안에 업그레이드하고 ACL로 RESTORE 권한을 점검한다.
  - ElastiCache 등 관리형 서비스 사용 시: AWS 측 패치 공지는 확인되지 않았다(확인 불가). 엔진 버전을 확인한다.

## 4. 미확인 보도·루머

- **Redis CVE-2026-25243 실제 악용**: 캐나다 사이버보안센터는 "공개 출처 보고"를 근거로 들었다. Redis 공식 확인과 KEV 등재는 확인되지 않았다.
- **Redis 후속 패치(6.2.23, 7.4.10)**: 제3자 사이트(TechJack Solutions)가 2026-07-23 릴리스에서 CVE-2026-25243, CVE-2026-25589가 추가로 수정됐고 6.2.22와 7.4.9는 여전히 취약하다고 보도했다. Redis 공식 공지로는 확인되지 않았다.
- **PostgreSQL 14 지원 종료(2026-11-12)**: 제3자 블로그 보도다. 이 실행에서는 postgresql.org 원문을 확인하지 못했다.
- **GitHub Actions 계정 탈취 규모**: 보도마다 수치가 다르다(GhostAction 관련 500여 개~1,900여 개 계정). 위 ③은 Wiz 원문 수치만 썼다.
