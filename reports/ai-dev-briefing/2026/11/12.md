## 주요 소식

### 1. Gemini Decision 1·Decisions API — 생성 없이 확률만 돌려주는 판단 모델

Gemini API 변경 이력 11월 11일(미국 날짜) 항목에서 `gemini-decision-1`과 Decisions API가 나왔습니다. 입력(텍스트·이미지·오디오·영상·PDF) 하나에 질문을 최대 1,000개까지 붙이면, 질문마다 보정된 확률과 신뢰도(`confidence`)를 돌려줍니다. 글을 생성하지 않아 출력 토큰은 항상 0입니다.

질문 유형은 세 가지입니다. `noul`은 예/아니오 확률, `choice`는 정해진 선택지 중 하나와 선택지별 확률, `score`는 2 ~ 255단계 등급과 단계별 확률을 줍니다. 질문끼리는 서로의 답을 보지 못하므로, 앞 답에 따라 갈리는 판단은 요청을 나누거나 코드에서 처리해야 합니다.

| 항목 | 값 |
|---|---|
| 호출 | JS `ai.decisions.create()`(`apiVersion: "v1beta"`), REST `POST /v1beta/decisions` |
| SDK | `@google/genai` 3.2 이상 (3.2.0, 11/12 02:39 KST 게시) |
| 가격 (입력, 100만 토큰) | 유료 등급 $0.10, 무료 등급 무료(제품 개선에 데이터 사용) |
| 컨텍스트 | 262,144 토큰 (공유 입력과 모든 질문 합계) |
| 미지원 | 대화 기록·도구 호출 입력, 컨텍스트 캐싱, Batch API, Vertex AI |

입력 안전 필터에 걸리면 `answers` 대신 HTTP 400과 `error.code`(`safety` 등)가 옵니다. 캐싱이 없어 같은 긴 입력을 반복해 보내면 매번 전액 과금됩니다. 정식(GA)인지 미리보기인지는 문서에 적혀 있지 않습니다.

> NestJS에서 문의 분류, 리뷰 등급 매기기, 에이전트 요청 라우팅을 LLM 응답 문자열 파싱으로 처리하고 있다면 Decisions API로 바꿔 볼 만합니다. `confidence`가 임계값보다 낮을 때 사람에게 넘기도록 분기하고, 임계값은 라벨 붙인 예시로 먼저 정하세요.

- 발표: 2026-11-11 · [Gemini API 변경 이력](https://aistudio.google.com/docs/changelog) · [Decisions API 문서](https://aistudio.google.com/docs/decisions-api) · [`@google/genai` v3.2.0](https://github.com/googleapis/js-genai/releases/tag/v3.2.0)

### 2. LangChain.js — 결정 모델 인터페이스, 모델 라우터 미들웨어, Zod 4.6.6 요구

11월 12일 07:05 ~ 07:09 KST(npm 게시)에 `@langchain/core` 1.4.0과 `langchain` 1.6.5가 나왔습니다. core에는 `@langchain/core/decisions` 모듈과 `BaseDecisionModel`이 추가됐습니다. 텍스트·메시지·JSON 상태에 대해 Noul·Choice·Score·Box 유형의 질문에 답하는 Runnable이고, 답은 질문에 맞춰 타입이 정해지며 빠진 답이나 잘못된 라벨은 거부합니다.

`langchain` 1.6.5에는 이를 쓰는 미들웨어 두 개가 들어왔습니다. `modelRouterMiddleware`는 결정 모델의 Choice 답으로 실행마다 에이전트 모델을 고르고, `autoModeMiddleware`는 지정한 도구 호출 중 결정 모델이 위험하다고 판단한 것을 막습니다. 어떤 제공사의 결정 모델이 연결되는지는 릴리스 노트에 없습니다.

두 패키지 모두 설치된 Zod가 4.6.6 이상이어야 합니다. 배열 스키마에 큰 배열을 넣으면 오류 수집에 상한이 없어 메모리 부족으로 프로세스가 죽는 GHSA-mrhx-c7xc-m3w5(높음, 10월 1일 공개)를 피하려는 조치입니다. Zod v3 스키마는 `zod/v3` 진입점으로 계속 쓸 수 있습니다.

> LangChain.js를 올리기 전에 `npm ls zod`로 4.6.6 미만이 남았는지 보세요. 요청 본문을 길이 제한(`.max()`) 없는 `z.array()`로 검증하는 NestJS 파이프가 있다면 LangChain과 별개로 Zod부터 올려야 합니다.

### `codebase-design` (mattpocock/skills)

작은 인터페이스 뒤에 많은 동작을 숨기는 "깊은 모듈(deep module)" 설계를 위한 공통 용어와 원칙을 담은 참고 문서 스킬입니다. 모듈·인터페이스·구현·어댑터·깊이·이음매(seam) 같은 용어를 정의하고, "component", "service", "boundary" 같은 모호한 말은 쓰지 않게 합니다.

모듈을 지웠을 때 복잡도가 사라지는지 호출자들에게 퍼지는지 보는 "삭제 테스트", 호출자가 쓰는 이음매에서 테스트하기, 이음매는 어댑터가 둘 이상일 때만 진짜라는 원칙을 제시합니다. 의존성은 직접 만들지 말고 주입받고, 부수 효과 대신 결과를 돌려주라고 권합니다. 함께 딸린 `DESIGN-IT-TWICE.md`는 하위 에이전트 여럿으로 인터페이스를 여러 방식으로 설계해 비교하라고 제안합니다.
