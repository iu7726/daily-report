## 3. 클라우드 (AWS)

### ① [P2] AWS Config 자동 조치 런북 — Session Manager 기본 설정 문서에 명령 주입

AWS가 관리하는 Systems Manager Automation 런북 `AWSConfigRemediation-EnableSystemsManagerSessionManagerAuditLogsToS3`가 `S3KeyPrefix` 값을 제대로 검증하지 않았습니다. 이 런북을 실행할 수 있는 사용자가 조작한 값을 넣으면, 리전의 Session Manager 기본 설정 문서(`SSM-SessionManagerRunShell`)에 의도하지 않은 설정을 심을 수 있습니다. 심은 설정에는 임의 명령도 들어갈 수 있고, 이후 다른 사용자가 Session Manager 세션을 열 때 관리 대상 인스턴스에서 실행됩니다.

그 리전에 `SSM-SessionManagerRunShell` 문서가 아직 없을 때만 주입됩니다. 이 런북을 AWS Config 자동 조치나 직접 실행으로 쓰는 계정이 해당하고, Session Manager를 쓰지 않거나 이 런북을 실행한 적이 없다면 해당하지 않습니다.

| 영향 버전 | 수정 버전 | 식별번호 | CVSS | KEV·실제 악용 |
|---|---|---|---|---|
| 2026-10-22(UTC) 이전에 만든 런북 리비전 | 리전별 최신 리비전 | CVE-2026-134070 | 8.0 (CVSS 3.1) · 7.2 (CVSS 4.0) | 미등재 · 확인 불가 |

> 이전 리비전은 2027년 1월 15일까지 계속 실행할 수 있어서 최신 리비전으로 바꾸는 것만으로는 막히지 않습니다. 이미 심어진 설정도 고친 런북이 지우지 않습니다.

- 이 런북을 쓰고 있다면 Automation 실행, State Manager 연결, AWS Config 자동 조치 설정에서 리비전 고정을 최신으로 바꿉니다. 리전별 최신 리비전은 `aws ssm describe-document ... --query "Document.LatestVersion"`으로 확인합니다.
- 이전 리비전이 사라질 때까지는 믿을 수 있는 `SSM-SessionManagerRunShell` 문서를 모든 리전에 미리 만들어 두거나, 신뢰하지 않는 사용자가 이전 리비전을 못 돌리게 막습니다.
- 이 런북이 문서를 처음 만든 리전이 있다면 `shellProfile`, `runAsEnabled`·`runAsDefaultUser`, 세션 시간, 로그 대상 값을 점검합니다. 주입된 실행은 항상 "DOCUMENT CREATE OR UPDATE FAILED"로 실패하니 실행 기록에서 이 오류를 찾아봅니다.
