### 1. Codex CLI 0.172.0 — stdio MCP 서버 지연 시작, 지출 한도 오류 바로 표시

11월 24일 09:09 KST(npm 게시)에 Codex CLI 0.172.0 정식판이 나왔습니다. 호환성을 깨는 변경은 없다고 적혀 있습니다.

도구 목록이 캐시된 stdio MCP 서버는 이제 세션 시작 때가 아니라 첫 도구 호출 때 뜹니다. 응답 스트림에서 프로바이더 오류가 오면 바로 표시하고, 어느 API 지출 한도에 걸렸는지 이름을 보여 줍니다.

| 변경 | 내용 |
|---|---|
| `codex exec resume` | 저장된 샌드박스 권한, 작업 폴더, 작업 공간 루트를 그대로 복원(옵션으로 덮어쓰기 가능) |
| 앱 도구 승인 | `config.toml`에서 연결된 앱 도구마다 승인 검토자 지정 |
| Amazon Bedrock | 앱 서버 클라이언트가 설정·로그인 단계에서 Bedrock Runtime 선택 |
| 원격 세션 | 클라이언트와 서버 OS가 달라도 작업 폴더와 쓰기 가능 경로 유지 |
| 지원 종료 | Code Mode가 모든 호스트 연결에 gRPC를 쓰면서 `code_mode_host_grpc` 설정 지원 종료 |

> 사내 MCP 서버를 stdio로 붙여 쓰는 경우, 서버가 첫 호출 때 뜨므로 시작 오류(환경 변수 누락, DB 연결 실패)가 세션 시작이 아니라 첫 도구 호출에서 드러납니다. CI에서 `codex exec resume`을 쓰고 있다면 이전 실행의 샌드박스 권한이 따라오니, 다른 권한으로 돌리려면 옵션을 명시하세요.

- 발표: 2026-11-24 · [Codex 0.172.0 릴리스](https://github.com/openai/codex/releases/tag/rust-v0.172.0)

### 2. GitHub Copilot CLI 1.0.115 정식판 — GPT-6.2 Astra, Windows 샌드박스 기본값

11월 24일 22:03 KST(npm 게시)에 Copilot CLI 1.0.115 정식판이 나왔습니다. 변경 이력 날짜는 11월 23일이지만, 어제 보고 시점에는 사전 배포판만 있었습니다.

모델 선택기에 GPT-6.2 Astra, Gemini 4 Hydrogen, MAI-Code-2-Flash가 들어갔고, `/model`에서 직접 등록한 프로바이더 모델을 관리할 수 있습니다. Windows 샌드박스는 패키지 조회를 기본으로 허용합니다.

| 변경 | 내용 |
|---|---|
| Windows 샌드박스 | 패키지 조회 기본 허용. 끄려면 `sandbox.userPolicy.capabilities`를 `[]`로 |
| macOS 샌드박스 | `sandbox.userPolicy.seatbelt.extraMachLookups`로 특정 Mach 서비스만 허용(Keychain 접근은 열리지 않음) |
| 셸 취소 | Unix에서 명령을 취소하면 프로세스 그룹에 남은 자식 프로세스도 종료 |
| 메모리 | 긴 세션에서 쓰이지 않는 과거 이벤트(모델 요청 전체 포함)를 메모리에 쌓지 않음 |
| 정책 폴백 | 허용 모델 정책으로 서브에이전트가 폴백 모델로 바뀌면 이벤트에 실제 폴백 모델 이름 기록 |

> Windows에서 Copilot CLI 샌드박스를 쓰는 팀은 `npm install` 같은 패키지 조회가 기본으로 열린다는 점을 알아 두세요. 사내 정책상 막아야 한다면 사용자 정책에 `capabilities: []`를 넣어야 합니다.

- 발표: 2026-11-23(변경 이력 날짜), npm 정식판 2026-11-24 · [Copilot CLI changelog](https://github.com/github/copilot-cli/blob/main/changelog.md)

### 3. OpenAI Responses API 의료용 모델 구성, `openai` 7.64.0

OpenAI가 11월 24일(미국 날짜) API 변경 이력에 의료용 모델 구성을 올렸습니다. 일부 모델에 임상 질문용 실행 환경(harness)을 묶은 구성이고, 웹 검색을 쓰면 의료 출처 전용 색인을 검색합니다. Responses API에서만 쓸 수 있습니다.

| 모델 ID |
|---|
| `gpt-6.2-astra-healthcare` |
| `gpt-6.2-sol-healthcare` |
| `gpt-6-astra-healthcare` |
| `gpt-6.1-sol-healthcare` |

같은 날 `chat-latest` 스냅샷도 ChatGPT 유료 플랜의 최신 모델로 바뀌었습니다. OpenAI는 운영 API에는 `chat-latest` 대신 GPT-6.2 계열을 권합니다. 11월 25일 04:30 KST(npm 게시)에 나온 `openai` 7.64.0은 이 의료용 모델 ID를 Responses 타입에 추가한 것이 유일한 기능 변경입니다.

> 의료 도메인 서비스가 아니라면 할 일은 없습니다. 다만 `chat-latest`를 운영 코드에 넣어 두었다면 예고 없이 모델이 바뀌니 `gpt-6.2-sol` 같은 고정 ID로 바꾸세요.

- 발표: 2026-11-24 · [OpenAI API 변경 이력](https://developers.openai.com/api/docs/changelog) · [openai-node CHANGELOG](https://github.com/openai/openai-node/blob/master/CHANGELOG.md)

## 주목할 Agent Skills

skills.sh 전체 순위 상위권은 여전히 `find-skills`, 영상(hyperframes)·디자인 스킬과 이미 소개한 mattpocock/skills입니다(트렌딩 탭 데이터는 확인 불가). 오늘 Codex 0.172.0 릴리스 노트가 번들 문서 스킬 갱신을 언급했고, `chat-latest` 교체처럼 OpenAI 모델 선택을 다시 볼 일이 생겨 `openai-docs`를 골랐습니다.

### `openai-docs` (openai/skills)

OpenAI 공식 개발자 문서를 근거로 답하게 하는 스킬입니다. `https://developers.openai.com/mcp`의 `openaiDeveloperDocs` MCP 서버로 문서를 검색·조회하고, API 형태는 OpenAPI 스펙 도구로 확인합니다. 모델 선택, 모델 이전, 프롬프트 개선 질문도 다룹니다.

MCP 서버가 없으면 설치하라고 안내하고, 실패하면 `developers.openai.com`, `platform.openai.com` 공식 도메인으로만 웹 검색을 합니다. 이전 작업은 "범위를 좁게, 동작은 그대로" 바꾸고, 사용자가 지정한 대상 모델을 임의로 바꾸지 말라는 규칙이 있습니다.

| 항목 | 값 |
|---|---|
| 설치 수 | 7.5K (확인 2026-11-25 08:50 KST, skills.sh 표시값) |
| 처음 등록 | 2026-02-01(skills.sh First seen), 신규 아님 |
| 보안 감사 | Gen Agent Trust Hub·Socket Pass, Snyk Warn |

- 원문: [skills.sh](https://skills.sh/openai/skills/openai-docs) · [SKILL.md](https://github.com/openai/skills/blob/main/skills/.system/openai-docs/SKILL.md)
- 설치: `npx skills add https://github.com/openai/skills --skill openai-docs`

Codex 0.172.0 릴리스 노트는 번들된 이 스킬이 GPT-6.2 Astra·Sol 이전을 다룬다고 적었지만, 확인한 저장소 SKILL.md 본문에는 GPT-6.2가 아니라 예시로 GPT-5.4만 나옵니다. 참조 파일(`references/upgrade-guide.md` 등)까지 갱신됐는지는 확인 불가라, 문서 MCP 서버가 붙어 있을 때 결과를 믿는 편이 안전합니다.

> NestJS 서비스의 OpenAI 호출부를 GPT-6.2로 옮기거나 Responses API 요청 형태를 확인할 때, 모델이 기억에 기대지 않고 공식 문서를 인용하게 만드는 데 쓸 만합니다. 다만 Codex 매뉴얼을 받는 `scripts/fetch-codex-manual.mjs`가 네트워크로 파일을 내려받아 임시 폴더에 쓰고, MCP 서버 설치에 권한 상승을 요청할 수 있습니다. Snyk 경고 사유는 페이지에 나와 있지 않으니 설치 전에 `scripts/` 폴더를 읽어 보세요.
