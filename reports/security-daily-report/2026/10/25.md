### ② [긴급] Postiz — 인증 토큰 위조 취약점

- **공개일: 2026-10-24**
- **CVE-2026-115933 / GHSA-9j6f-8rw3-93c4**
- **CVSS v3.1: 9.9**

오픈소스 소셜미디어 관리 플랫폼 Postiz에서 서로 다른 목적의 인증 토큰에 동일한 서명 비밀키를 사용하고, 토큰 용도를 충분히 구별하지 않는 취약점이 발견됐다.

특정 API는 사용자가 제공한 데이터를 서명한 뒤 그 결과를 다시 확인할 수 있게 한다.

공격자는 이를 이용해 자신이 원하는 클레임을 가진 정상 서명 토큰을 생성하고, 세션·초대·비밀번호 재설정 등의 인증 흐름에 악용할 수 있다.

**패치:** Postiz **v2.25.3**. 프로젝트의 10월 24일 릴리스 공지에서 해당 취약점의 수정이 확인됐다.

**공격 조건:** 권고문은 사용자 권한이 필요한 경로를 설명한다. 따라서 모든 비인증 요청에서 곧바로 악용할 수 있다고 단정해서는 안 된다.

Postiz를 직접 사용하지 않는다면 제품 패치는 필요 없다. 다만 NestJS에서 JWT나 초대 토큰을 설계할 때 `aud`, `iss`, 용도 구분 및 검증 경로를 확인할 만한 사례다. ([GitHub](https://github.com/advisories/GHSA-9j6f-8rw3-93c4))

공식 원문: [GitHub 보안 권고문](https://github.com/advisories/GHSA-9j6f-8rw3-93c4) · [Postiz 패치 릴리스](https://github.com/gitroomhq/postiz-app/releases/tag/v2.25.3)

### ⑤ [높음] undici — 악성 HTTP 응답을 통한 Node.js 프로세스 종료

- **최초 공개: 2026-10-15 / GitHub DB 등록: 10-23**
- **CVE-2026-109869 / GHSA-xjj6-f33q-929c**
- **CVSS v3.1: 7.5**

Node.js HTTP 클라이언트 라이브러리 `undici`에서 원격 서비스 거부(DoS) 취약점이 발견됐다.

악성 서버가 과도한 `Content-Encoding` 정보를 포함한 응답을 보내고 특정 시점에 연결을 종료하면, 내부 스트림의 처리되지 않은 오류로 Node.js 프로세스가 종료될 수 있다.

애플리케이션에서 `fetch()` 호출의 예외를 처리하더라도 공격이 가능한 경우가 있다.

| 영향 버전 | 수정 버전 |
|---|---|
| 6.23.0 이상, 6.29.1 미만 | 6.29.1 |
| 7.18.0 이상, 7.30.1 미만 | 7.30.1 |
| 8.0.0 이상, 8.12.2 미만 | 8.12.2 |

관련하여 `EventSource` 파서에서 메모리 사용량이 제한 없이 증가할 수 있는 취약점인 **CVE-2026-109924**도 같은 패치 버전에서 수정됐다.

**공격 조건:** 애플리케이션이 공격자가 제어하거나 침해한 HTTP/SSE 서버에 연결해야 한다.

npm `undici` 패키지 버전 검사와 Node.js 런타임에 내장된 `fetch` 구현 점검은 구분해야 한다. ([GitHub](https://github.com/advisories/GHSA-xjj6-f33q-929c))

공식 원문: [undici 보안 권고문](https://github.com/advisories/GHSA-xjj6-f33q-929c)

### ⑥ [높음] multer — 비동기 파일 필터 처리 중 프로세스 종료

- **공개일: 2026-10-22 / GitHub DB 등록: 10-23**
- **CVE-2026-113872 / GHSA-q7qp-rjg7-q26m**
- **CVSS v3.1: 7.5**

Express 기반 파일 업로드 미들웨어 `multer`에서 비동기 `fileFilter` 처리와 요청 종료가 겹치는 상황에 취약점이 발견됐다.

다른 파일의 `fileFilter` 콜백이 아직 실행 중인 상태에서 요청이 중단되면, 이미 종료된 스트림을 다시 처리하면서 예외가 발생할 수 있다.

해당 예외로 Node.js 프로세스가 종료될 가능성이 있다.

- **영향 버전:** 2.0.0 이상 2.5.0 미만
- **수정 버전:** **2.5.0**

**임시 완화책:** 동기식 `fileFilter` 사용.

이 문제는 단일 비인증 요청으로 악용할 수 있지만, 비동기 `fileFilter`라는 전제조건이 존재한다.

NestJS에서 `FileInterceptor` 등으로 파일 업로드를 구현했다면 실제 사용 중인 `multer` 버전과 필터 구성을 점검해야 한다. ([GitHub](https://github.com/advisories/GHSA-q7qp-rjg7-q26m))

공식 원문: [multer 보안 권고문](https://github.com/advisories/GHSA-q7qp-rjg7-q26m)

PostgreSQL은 8월 13일 발표된 보안 패치가 현재 확인되는 주요 기준이며, **PostgreSQL 14는 2026년 11월 12일 지원 종료 예정**이다. Redis는 기존 TLS 관련 Use-After-Free 취약점의 수정 버전 적용 여부를 확인해야 한다. ([PostgreSQL](https://www.postgresql.org/about/news/postgresql-186-1711-1615-1519-1424-and-19-beta-3-released-3365/))

Claude Code와 Codex의 공식 GitHub Security Advisories 페이지에서도 10월 24~25일 신규 중대 공지는 확인되지 않았다. ([GitHub](https://github.com/anthropics/claude-code/security/advisories))

## 4. 개발 환경에서 즉시 확인할 사항

Node.js·NestJS·Next.js 프로젝트 기준으로 다음 점검이 가장 효율적이다.

```bash
# 런타임 버전
node -v

# 주요 의존성
npm ls undici multer @azure/msal-node

# React / Next.js
npm ls next react \
  react-server-dom-webpack \
  react-server-dom-parcel \
  react-server-dom-turbopack

# 의존성 취약점
npm audit

# Docker 이미지 점검
docker image ls
```

`npm audit`는 잠재적인 의존성 문제를 찾는 보조 수단이다. 실제 노출 여부는 요청 처리 경로, 패키지 사용 방식, 배포 구성과 함께 판단해야 한다.

특히 `multer`의 비동기 파일 필터, `undici`를 통한 외부 서버 호출, Brotli 압축 해제 여부를 함께 확인하는 것이 좋다.

## 5. 최종 판단

**오늘 기준으로 가장 실질적인 대응 가치는 Brotli 관련 런타임 업데이트와 Node.js HTTP·파일 업로드 의존성 점검에 있다.**

Postiz와 Collabora 취약점은 심각하지만 해당 제품을 사용하지 않는다면 직접적인 운영 위험은 없다.

이미 보고했던 Node.js·GitLab·React/Next.js의 고위험 취약점은 공식 패치가 존재한다. 운영 환경에서 패치가 완료되지 않았다면 오늘 새롭게 공개된 상대적으로 낮은 위험의 취약점보다 먼저 처리할 필요가 있다.

**핵심 요약:** 10월 24일에는 Brotli의 광범위한 영향이 추가로 알려졌고, Postiz에서는 CVSS 9점대 취약점 2건이 공개됐다. 실무 환경에서는 기존 런타임 패치와 `undici`·`multer` 의존성 점검을 우선한다.
