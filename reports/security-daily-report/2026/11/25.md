## 4. AI·개발 도구

### ③ [P1] ruflo — 기본 Docker 구성의 MCP 브리지가 인증 없이 셸 실행

ruflo는 여러 AI 에이전트를 묶어 돌리는 npm 도구입니다(주간 다운로드 약 6만 회). 저장소에 들어 있는 `docker-compose.yml`의 MCP 브리지가 `POST /mcp`를 인증 없이 열고, 브리지(3001)와 MongoDB(27017)를 모든 네트워크 인터페이스에 바인딩했습니다. 그래서 네트워크에서 닿는 누구나 `terminal_execute` 도구를 불러 컨테이너 안에서 셸을 얻고, 환경 변수의 AI 제공사 API 키를 가져갈 수 있습니다.

`terminal_execute` 차단 목록은 autopilot 흐름에만 적용돼 `POST /mcp`, `POST /mcp/:group`은 그대로 통과했습니다. 공격자가 AgentDB 패턴 저장소에 오염된 패턴을 심어 두면, 패치판으로 다시 배포해도 이후 AI 출력에 계속 영향을 줍니다.

ruflo를 저장소의 Docker Compose 구성으로 띄웠고 그 포트가 외부에서 닿는 경우만 해당합니다. npm 패키지를 로컬 CLI로만 쓰는 경우는 권고 범위에 없습니다. 같은 버전 번호로 함께 배포되는 `claude-flow` 패키지가 권고에 포함되는지는 확인 불가입니다.

| 영향 버전 | 수정 버전 | 식별번호 | CVSS | KEV·실제 악용 |
|---|---|---|---|---|
| 3.16.3 미만 | 3.16.3 (2026-07-01, 최신 3.80.6) | CVE-2026-59726 · GHSA-c4hm-4h84-2cf3 | 10.0 (CVSS 3.1) | 미등재 · 확인 불가 |

> 수정판은 7월부터 있었지만, 그 전에 띄운 컨테이너를 그대로 두었다면 지금도 누구나 셸을 열 수 있습니다. 노출됐을 가능성이 있다면 키 교체와 패턴 저장소 점검까지 해야 합니다.

- ruflo를 Docker Compose로 띄운 적이 있다면 3001·27017 포트를 방화벽으로 막고, 3.16.3 이상으로 다시 배포합니다. 새 버전은 `MCP_AUTH_TOKEN` 없이 외부 바인딩을 거부하고, `terminal_execute`는 `MCP_ENABLE_TERMINAL=true`일 때만 켭니다.
- 노출 기간이 있었다면 OpenAI·Anthropic·Google·OpenRouter 키를 교체하고, AgentDB의 `agentdb_pattern-store` 항목과 MongoDB 데이터를 점검합니다.
- 원문: [GHSA-c4hm-4h84-2cf3](https://github.com/ruvnet/ruflo/security/advisories/GHSA-c4hm-4h84-2cf3) (저장소 공개 2026-07-01 · NVD 공개 2026-07-10 03:16 KST · GitHub DB 등록 2026-11-25 06:01 KST)

## 6. 데이터베이스

### ⑤ [P2] AWS pgactive — 복제 원점 이름 파싱 스택 버퍼 오버플로

pgactive는 PostgreSQL 데이터베이스 사이에 액티브-액티브 복제를 해 주는 AWS의 오픈소스 확장입니다. 복제 원점(replication origin) 이름을 파싱하는 부분에 스택 버퍼 오버플로가 있어, 특정 권한이 있는 인증된 DB 사용자가 DB 서버의 OS 사용자 권한으로 임의 명령을 실행할 수 있습니다.

pgactive 확장을 설치해 쓰는 PostgreSQL만 해당하고, 일반 PostgreSQL이나 기본 논리 복제만 쓰는 경우는 해당하지 않습니다. RDS for PostgreSQL에서 이 확장을 켠 경우 관리형 쪽 반영 일정은 공지에 없어 확인 불가입니다.

| 영향 버전 | 수정 버전 | 식별번호 | CVSS | KEV·실제 악용 |
|---|---|---|---|---|
| 2.1.0 이상 2.1.10 미만 | 2.1.10 | CVE-2026-134068 | 7.5 (CVSS 3.1) · 7.7 (CVSS 4.0) | 미등재 · 확인 불가 |

> 2.1.9 이하 노드는 2.1.10 노드 그룹에 들어갈 수 없으니, 기존 노드를 먼저 올리는 순서로 업그레이드해야 합니다.

- 직접 운영하는 PostgreSQL에 pgactive 2.1.x를 쓰고 있다면 2.1.10으로 올립니다. 2.1.10은 PostgreSQL 18.7 / 17.12 / 16.16 / 15.20 / 14.25 이상을 요구합니다.
- 올리기 전까지는 복제 관련 권한을 가진 DB 계정을 최소로 줄입니다.
- 원문: [AWS 2026-198-AWS](https://aws.amazon.com/security/security-bulletins/rss/2026-198-aws/) (2026-11-24 10:00 PST = 2026-11-25 03:00 KST) · [pgactive v2.1.10 릴리스](https://github.com/aws/pgactive/releases/tag/v2.1.10) (11월 18일 배포, 릴리스 노트에는 보안 수정 표시 없음)
