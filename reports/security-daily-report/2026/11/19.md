## 7. 공급망·CI/CD·인프라

### ① [P1] NGINX — HTTP/2 취약점으로 인증 없는 원격 코드 실행 확인

11월 18일 나온 NGINX 1.30.7·1.31.9가 고친 10건 중 HTTP/2 흐름 제어 메모리 손상(CVE-2026-123007)에 대해, 발견자 Wiz가 공식 1.31.7·1.31.8 빌드에서 ASLR 우회를 포함한 원격 코드 실행을 확인했다고 밝혔습니다. HTTP/2를 켠 기본 구성에서 인증 없이 공격할 수 있고, HTTP/2 리버스 프록시의 use-after-free(CVE-2026-123633)도 같은 공격 흐름에 쓰입니다. Wiz는 PoC를 공개하지 않았고, 실제 악용과 KEV 등재는 확인되지 않았습니다.

`listen ... http2` 또는 `http2 on`을 쓰는 NGINX가 대상입니다. 앞단 로드밸런서(ALB, CloudFront)만 HTTP/2를 받고 NGINX는 HTTP/1.1만 받는다면 이 두 건은 해당하지 않지만, 같은 릴리스의 HTTP/3·TLS 1.3·메일 프록시 취약점은 구성에 따라 해당합니다.

| 영향 버전 | 수정 버전 | 식별번호 | CVSS | KEV·실제 악용 |
|---|---|---|---|---|
| CVE-2026-123007: 1.9.5 ~ 1.31.8 · CVE-2026-123633: 1.19.7 ~ 1.31.8 | 1.30.7(stable), 1.31.9(mainline) | CVE-2026-123007, CVE-2026-123633 외 8건 | 9.2 (CVSS 4.0) | 미등재 · 실제 악용 확인 불가(발견자가 RCE 재현) |

> 원격 코드 실행이 재현됐고 Hacker News 1위에 오를 만큼 주목받고 있어, 공격 코드가 나오기까지 시간이 길지 않을 수 있습니다. HTTP/2를 켠 NGINX는 오늘 올려야 합니다.

- `nginx -v`로 확인하고 1.30.7 또는 1.31.9로 올립니다. Docker 공식 이미지는 `nginx:1.30.7`·`nginx:1.31.9` 태그(2026-11-19 04:52 KST 이후)로 다시 받습니다.
- 당장 못 올리면 HTTP/2를 끄고(`http2 off;`) HTTP/3·메일 프록시처럼 쓰지 않는 기능도 끕니다. worker 프로세스가 예기치 않게 죽는 기록이 있는지 오류 로그를 봅니다.
- NGINX Plus는 Wiz 글 기준 37.0.8.1 / 37.3.0.1(CVE-2026-123007)과 37.0.7.1 / 37.2.0.1(CVE-2026-123633)이 수정판입니다. F5 공지 원문은 확인하지 못했습니다.
- 원문: [nginx security advisories](https://nginx.org/en/security_advisories.html) · [nginx.org 소식](https://nginx.org/) (2026-11-18) · [Wiz 분석](https://www.wiz.io/blog/nginx-http2-rce-vulnerabilities) (2026-11-18, NVD 공개 2026-11-19 01:18 KST)

새벽 긴급 감시 표에 없던 나머지 4건은 모두 stream 모듈·특수 설정에서만 생깁니다. stream 가상 서버의 클라이언트 인증서 SNI 우회(CVE-2026-120967, medium), `ssl_preread` 검증 부족(CVE-2026-123640, minor), PROXY protocol v2 NULL 포인터(CVE-2026-120993, minor, 1.31.4 ~ 1.31.8만), `alias`와 `try_files` 버퍼 오버플로(CVE-2026-125283, minor)입니다.

### ② [P2] pnpm 단독 실행판 — 유출된 eMudhra 중간 CA를 아직 신뢰

pnpm 단독 실행판(`@pnpm/exe`, 설치 스크립트로 받는 pnpm)은 자체 Node.js 런타임을 품고 있는데, 이 런타임이 10월에 신뢰가 철회된 eMudhra 중간 CA 인증서를 아직 믿습니다. 복구된 중간 CA 키를 가진 공격자가 네트워크 경로에 있으면 레지스트리 응답을 위조해 가짜 패키지 메타데이터나 tarball을 넘길 수 있습니다. 10월 26일 보고에서 다룬 eMudhra 사건의 후속입니다.

npm으로 설치해 Node.js 24.22.1 같은 최신 런타임에서 돌리는 pnpm은 해당하지 않습니다(권고의 검증에서 인증서를 거부함). CI에서 단독 실행판을 쓰거나 저장소가 pnpm 10.x·11.x로 고정돼 pnpm 12가 그 버전을 내려받아 쓰는 경우가 대상입니다.

## 10. 미확인 보도·루머

- Socket과 StepSecurity는 Optimizely가 호스팅하는 스크립트를 통해 178개 조직의 웹사이트에 암호화폐 주소 바꿔치기·카드 정보 탈취 코드가 실렸다고 보고했습니다. npm 패키지가 아니라 외부 CDN 스크립트 건이고 Optimizely 공식 공지는 확인하지 못했습니다. Optimizely 스크립트를 페이지에 넣었다면 벤더 공지를 확인합니다.
- Microsoft `agent-framework` PyPI 패키지 탈취(StepSecurity, Aikido, Socket 보도)는 Python 패키지라 점검 범위 밖입니다. npm 쪽 피해 보고는 없습니다.

Hacker News 상위 글(24시간, 100점 이상 32개) 중 보안 관련 글은 NGINX 원격 코드 실행(①에서 다룸)과 KVM x86 취약점(CVE-2026-99312)입니다. KVM 건은 하이퍼바이저 쪽이라 점검 대상 밖이고, 그 밖에 점검 대상에 닿는 사건은 없습니다.
