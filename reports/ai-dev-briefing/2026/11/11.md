### 1. Gemini 4 Carbon 정식 출시 — 모델 ID만 바꾸면 되지만 제한 시간은 늘려야

Google이 10월 28일 공개한 Gemini 4 Carbon을 11월 10일(미국 날짜) Gemini API에서 정식 출시(GA)했습니다. 10월에는 제한된 접근만 열렸고, 이번에 유료 등급 개발자 누구나 쓸 수 있게 됐습니다. 무료 등급에서는 쓸 수 없습니다.

| 항목 | 값 |
|---|---|
| 모델 ID | `gemini-4-carbon` |
| 컨텍스트 | 1,048,576 토큰, 출력 기본 65,536 토큰 |
| 생각 수준 | `low` / `medium`(기본) / `high` |
| 가격 (입력/출력, 100만 토큰) | 11월 30일까지 $2 / $10, 이후 $4 / $20 |
| 캐시 입력 | $0.10, 이후 $0.20. 명시적 캐싱은 지원 안 함 |
| 미지원 | 오디오·이미지 생성, Live API |

마이그레이션 문서는 Argon에서 옮길 때 요청 스키마 변경이 없다고 밝힙니다. 다만 Carbon은 어려운 작업에서 생각 토큰을 더 쓰고, `max_output_tokens`가 생각과 출력을 합친 상한이라 응답이 잘릴 수 있습니다. 어려운 프롬프트에는 백그라운드 실행이나 15분 이상의 HTTP 제한 시간을 권합니다.

> NestJS에서 `HttpModule`이나 프록시의 제한 시간을 30 ~ 60초로 잡아 두었다면, 모델 ID만 바꾸면 긴 요청이 끊깁니다. 정식 가격이 적용되는 12월 1일 전에 토큰 사용량을 측정해 비용을 다시 계산하세요.

- 발표: 2026-11-10 · [Google 발표](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-carbon-now-available/) · [Gemini API 변경 이력](https://aistudio.google.com/docs/changelog) · [모델 문서](https://aistudio.google.com/docs/models/gemini-4-carbon) · [What's new in Gemini 4 Carbon](https://aistudio.google.com/docs/whats-new-gemini-4-carbon)

### 2. `@google/genai` 3.1.0·Gemini CLI 0.68.0

11월 11일 05:47 KST(npm 게시)에 `@google/genai` 3.1.0이 나왔습니다. Interactions API의 모델 열거형에 `gemini-4-carbon`·`gemini-omni-1.2-flash`가 추가됐고, `ThinkingLevel`에 `xhigh`가 생겼습니다. Live API용 `proactive_video` 설정과 Gemini Enterprise API 임베딩 응답의 `usage_metadata`도 들어갔습니다.

같은 날 06:22 KST에 Gemini CLI 0.68.0이 나왔습니다. 확장 검증 명령, `SubagentStop` 훅 이벤트, 429 속도 제한 대기 시간 표시, 루트리스 Podman 샌드박스(`--userns=keep-id`)가 추가됐습니다. 심볼릭 링크 경로를 정규 경로로 풀고 `.git/info/exclude`를 따르도록 고친 변경도 있지만, 보안 수정으로 표시되지는 않았습니다.

> TypeScript에서 모델 이름을 SDK 열거형으로 검사하고 있다면 3.1.0으로 올려야 `gemini-4-carbon`이 타입 오류 없이 통과합니다. 다만 Carbon 모델 문서는 생각 수준으로 `low`·`medium`·`high`만 적고 있으니 `xhigh`를 쓰기 전에 지원 여부를 확인하세요.

- 발표: 2026-11-10 · [`@google/genai` v3.1.0](https://github.com/googleapis/js-genai/releases/tag/v3.1.0) · [Gemini CLI v0.68.0](https://github.com/google-gemini/gemini-cli/releases/tag/v0.68.0)

### 3. GitHub — 12월 8일부터 비활성 저장소 Dependabot 알림 중단

GitHub가 12월 8일부터 1년 동안 활동이 없는 저장소의 Dependabot 알림을 끈다고 밝혔습니다. 브랜치·태그 푸시, 저장소 생성, Dependabot 알림 켜기만 활동으로 셉니다. 기존 알림은 지우지 않고 보관합니다.

푸시하거나 저장소 설정에서 다시 켜면 보관된 알림이 돌아오고 1년 기간이 다시 시작됩니다. 일반적인 해제 옵션은 없고, 알림을 켜는 보안 구성(security configuration)이 강제 적용된 저장소나 엔터프라이즈 정책으로 알림 설정을 잠근 경우에만 계속 켜집니다. github.com 전체 요금제와 데이터 레지던시 Enterprise Cloud에 적용되고 GitHub Enterprise Server는 제외입니다.

> 오래 손대지 않은 내부 라이브러리나 운영 중인 NestJS 서비스 저장소도 1년간 푸시가 없으면 새 CVE 알림을 받지 못합니다. 이런 저장소가 있으면 조직 보안 구성으로 Dependabot 알림을 강제하세요.

- 발표: 2026-11-10 · [GitHub Changelog](https://github.blog/changelog/2026-11-10-dependabot-alerts-will-pause-on-inactive-repositories)

> LangChain.js 에이전트에서 거절 응답이 빈 결과로 저장되던 문제가 있었다면 `modelRefusalMiddleware`를 붙이고, 예외 필터에서 `ModelRefusalError`를 따로 처리하세요.
