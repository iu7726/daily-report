### ① AWS Private CA Connector for Kubernetes — 인증서 발급 권한 우회

- **높음 · 접근제어 취약점**
- 10월 30일 01:30 KST 공개
- **CVE-2026-119115 / GHSA-hjrh-q6pg-mh829**

AWS가 10월 29일 오전 9:30 PDT에 신규 보안 공지를 게시했다.

`aws-privateca-issuer`는 Kubernetes cert-manager가 AWS Private Certificate Authority를 통해 인증서를 발급할 수 있게 하는 컴포넌트다.

이 컴포넌트에서 Issuer를 선택하는 과정의 권한 검증에 오류가 발견됐다.

**공격 조건:** 네임스페이스 범위 Issuer만 사용할 권한을 가진 인증된 사용자가 특정 조건에서 권한이 없는 클러스터 범위 Issuer를 통해 인증서를 발급받을 수 있다. 여기에는 하위 CA 인증서도 포함될 수 있다.

**영향 및 수정 버전**

| 대상 | 취약 버전 | 수정 버전 |
|---|---|---|
| `aws-privateca-issuer` | 1.10.1 미만 | **1.10.1** |
| AWS EKS Add-on | 1.10.1-eksbuild.1 미만 | **1.10.1-eksbuild.1** |

업데이트가 어렵다면 인증서 승인 정책과 Kubernetes RBAC를 Issuer 이름뿐 아니라 **Issuer 종류(kind)** 까지 제한해야 한다.

**업데이트 전 주의사항:** 수정 버전은 `issuerRef.kind` 일치 여부를 엄격하게 검사한다. 기존에 잘못 설정된 CertificateRequest, Certificate, Ingress가 있다면 패치 후 인증서 갱신에 실패할 수 있으므로 먼저 설정을 검사해야 한다.

실제 악용 사례는 공식 공지에서 확인되지 않았다.

**실무 판단:** 일반적인 AWS EC2·ALB·S3 서비스에는 직접적인 영향이 없다. EKS에서 cert-manager와 AWS Private CA를 연동하는 환경만 우선 점검하면 된다.

공식 원문: [AWS Security Bulletin 2026-156](https://aws.amazon.com/security/security-bulletins/2026-156-aws/)

### ② `decode-uri-component` — Node.js Event Loop 장시간 차단

- **High · CVSS v4.0 8.2**
- 10월 29일 GitHub DB 등록·검토
- **CVE-2026-118664 / GHSA-qr28-fpjm-wq7f**

`decode-uri-component`가 잘못 인코딩된 입력을 복구하는 과정에서 비효율적인 정규식 치환을 반복하는 문제다.

공식 권고문에 따르면 약 224KB의 조작된 입력으로 단일 스레드 Node.js Event Loop가 약 20초 동안 차단되는 사례가 재현됐다.

| 항목 | 내용 |
|---|---|
| 취약 버전 | `decode-uri-component` 0.5.0 이하 |
| 수정 버전 | **0.5.1** |
| 공격 조건 | 외부 입력이 해당 디코더에 전달되어야 함 |
| 위험 | CPU 점유, 요청 처리 지연, 서비스 거부 |
| 실제 운영 환경 악용 | 확인되지 않음 |

`query-string`처럼 이 패키지를 간접적으로 사용하는 라이브러리도 영향 가능성이 있다.

다만 URL 쿼리스트링으로만 입력받는 경우 Node.js의 기본 HTTP 헤더 크기 제한 때문에 대형 페이로드의 영향이 제한될 수 있다. 요청 본문을 디코딩하는 구조는 더 주의해야 한다.

**권장 조치:** `npm ls decode-uri-component query-string`으로 의존성을 확인하고 취약 버전이 있으면 업그레이드한다. 요청 본문 크기 제한도 함께 유지한다.

최초 프로젝트 공개일은 10월 23일이며, 10월 29일 GitHub 보안 DB에 등록됐다.

공식 원문: [GitHub 보안 권고문](https://github.com/advisories/GHSA-qr28-fpjm-wq7f)

### ③ Vite — 개발 서버의 파일 접근 차단 우회

- **Moderate · CVSS v4.0 6.9**
- 10월 29일 GitHub DB 등록
- **CVE-2026-118662 / GHSA-8g5g-mxqh-grgj**

Vite 개발 서버의 `server.fs.deny` 설정으로 차단한 파일을 특정 URL 쿼리 파라미터를 붙여 가져올 수 있는 문제다.

**영향 버전은 Vite 6.4.4이며, 수정 버전은 6.4.5다.**

취약점이 발생하려면 다음 조건이 동시에 필요하다.

- 개발 서버를 `--host` 또는 `server.host`로 네트워크에 노출
- 보호하려는 파일이 `server.fs.allow` 범위에 존재
- 해당 파일을 `server.fs.deny` 패턴으로 차단하는 구성

이때 설정에 따라 `.env` 또는 인증서 파일 등의 내용이 노출될 수 있다.

**실무 영향:** React 또는 Next.js 자체의 취약점은 아니다. Vite 기반 개발 서버를 사내망이나 외부 네트워크에 열어 둔 경우에만 해당한다.

임시 완화책은 개발 서버를 localhost에만 바인딩하고, 민감한 파일을 서비스 가능한 디렉터리 밖으로 이동하는 것이다.

이 문제 역시 최초 공개일은 10월 21일이며 GitHub DB 등록·검토가 10월 29일에 이뤄졌다.

공식 원문: [Vite 보안 권고문](https://github.com/advisories/GHSA-8g5g-mxqh-grgj)

### AWS Brotli — Lambda 패치 배포 상태 갱신

- **CVE-2026-111497 / 10월 29일 AWS 공식 공지 갱신**

AWS는 기존 Brotli 메모리 손상 취약점의 Lambda 대응 현황을 추가로 업데이트했다.

- **Lambda Node.js ZIP:** 수정 런타임의 1단계 배포가 완료됐다. 자동 런타임 업데이트의 다음 단계는 10월 30일 완료 목표이며, 현재 시점에 전체 적용이 끝났다고 단정할 수 없다.
- **Lambda Node.js 컨테이너:** 수정 베이스 이미지를 사용할 수 있다. 기존 이미지는 직접 재빌드·재배포해야 한다.
- **CodeBuild:** AWS 제공 이미지의 수정 배포가 진행 중이다. 커스텀 이미지나 버전 고정 이미지는 별도 점검이 필요하다.
- **EC2·ECS·EKS 자체 관리 런타임:** AWS가 애플리케이션의 Node.js를 자동으로 교체하지 않는다.

특히 Lambda Node.js 24는 회귀 문제로 보안 수정이 선택적으로 백포트돼 `process.version`만으로 패치 완료를 판단하기 어렵다. AWS가 안내하는 `INIT_START` 로그의 런타임 식별자를 확인해야 한다.

실제 악용이 확인된 Brotli 취약점이라는 점은 변하지 않았다. 이번 변경은 **AWS 관리형 런타임의 수정 배포 진행 상황**이다.

공식 원문: [AWS Security Bulletin 2026-155](https://aws.amazon.com/security/security-bulletins/2026-155-aws/)

### PostgreSQL Anonymizer — 개인정보 마스킹·권한 상승 취약점 수정

- **2026년 10월 28일 공식 발표 · PostgreSQL Anonymizer 3.3**

PostgreSQL의 개인정보 익명화 확장인 `PostgreSQL Anonymizer` 3.3이 **12건의 보안 취약점**을 수정했다. 일부는 마스킹된 사용자에게 원본 데이터가 노출되거나 권한 상승으로 이어질 수 있다.

이것은 PostgreSQL 데이터베이스 엔진 전체의 문제가 아니라 **해당 확장을 설치한 환경에 한정된 문제**다.

확장을 사용한다면 3.3으로 업데이트하고 공식 권고에 따라 `anon.salt` 변경 및 마스킹 규칙 재검토가 필요하다. 사용하지 않는다면 이 업데이트로 인한 직접적인 조치는 없다.

공식 원문: [PostgreSQL 공식 사이트 — Anonymizer 3.3 보안 공지](https://www.postgresql.org/about/news/postgresql-anonymizer-33-major-security-update-3423/)

## 8. 최종 판단

오늘 실제 운영 환경 기준의 우선순위는 **자체 호스팅 GitLab의 KEV 취약점 대응, Brotli 패치 완료 검증, 새로 등록된 Node.js 의존성 취약점 확인** 순서다.

GitLab을 자체 운영하지 않는다면 가장 중요한 조치는 Brotli 패치 확인이다. AWS EKS Private CA Connector와 MCP PDF Reader는 특정 제품·구성을 사용할 때만 대응하면 된다.

**오늘의 핵심 변화는 GitLab CVE-2026-97229가 10월 29일 CISA KEV에 새로 등재됐다는 점이다.** 단순한 잠재 RCE가 아니라 실제 악용 근거가 확인된 취약점이므로 기존 리포트보다 대응 우선순위를 높였다.

이번 리포트는 공개 공식 자료를 검증한 결과다. 운영 서버와 저장소의 실제 설치 버전, 패치 완료 여부, 침해 흔적까지 검사한 결과는 아니다.
