### ⑥ [P2] node-forge — RSA 서명 위조, ASN.1 자원 고갈 등 권고 9건

순수 JavaScript TLS·암호 라이브러리 `node-forge`에 권고 9건이 한꺼번에 올라왔습니다. 가장 무거운 것은 RSA PKCS#1 v1.5 서명 검증이 비정규 DigestInfo 인코딩을 받아 주는 문제로, 공개 지수가 3인 RSA 키라면 개인 키 없이 서명을 위조할 수 있습니다(CVE-2026-119192). `asn1.fromDer`의 BIT STRING 처리로 자원을 고갈시키는 서비스 거부(CVE-2026-119191)도 High입니다.

나머지는 CA 인증서의 `pathLenConstraint` 미검사, 인증서 서명을 발급자의 서명 방식으로 검증하는 문제, TLS 클라이언트 비정상 종료 2건, HTTP 헤더 ReDoS, Ed25519 소수 차수 공개 키 수용, PKCS#7 패딩 검증 미흡 같은 Moderate·Low입니다. 1.4.1과 1.4.3에 나뉘어 고쳐졌습니다.

> `node-forge`로 서명·인증서를 검증하거나 외부 DER 데이터를 파싱한다면 1.4.3 이상으로 올려야 합니다.

간접 의존으로 들어온 경우가 많습니다. Node.js 내장 `crypto`만 쓰는 코드는 해당하지 않습니다.

### ⑧ [P2] mongoose — `sanitizeFilter` 미적용, 상속 속성 덮어쓰기 등 권고 5건

MongoDB ODM `mongoose`에 권고 5건이 올라왔습니다. `countDocuments()`에 `sanitizeFilter`가 적용되지 않아 `{ $ne: null }` 같은 선택자 주입을 막지 못했고(CVE-2026-125120, Critical), 연결 단위로 켠 `sanitizeFilter`는 켜진 것으로 보이지만 실제 질의에는 적용되지 않았습니다(CVE-2026-125119, High). 이 경우 비밀번호 자리에 `{ $ne: null }`을 넣어 계정 문서를 가져올 수 있습니다.

문서를 불러오거나 경로를 설정할 때 `toString` 같은 상속 속성을 덮어써 프로세스 전체를 멈추게 하는 문제(CVE-2026-125117, High), `Schema.prototype.virtual()` 프로토타입 오염, 판별자 키 우회도 함께 고쳐졌습니다.

> 요청 본문을 그대로 질의 필터에 넣으면서 `sanitizeFilter`에 기대고 있다면 9.11.4 / 8.24.7 / 7.8.13 / 6.13.12 이상으로 올려야 합니다.

`mongoose.set('sanitizeFilter', true)`로 전역 설정했거나 질의마다 `.sanitizeFilter()`를 붙인 경우는 CVE-2026-125119에 해당하지 않습니다. 다만 `countDocuments()` 문제는 버전으로만 고쳐집니다.

| 영향 버전 | 수정 버전 | 식별번호 | CVSS | KEV·실제 악용 |
|---|---|---|---|---|
| 9.11.4 / 8.24.7 / 7.8.13 / 6.13.12 미만 | 9.11.4 / 8.24.7 / 7.8.13 / 6.13.12 | CVE-2026-125120, CVE-2026-125119, CVE-2026-125117 외 2건 | 9.8 / 7.5 / 8.2 | 미등재 · 확인 불가 |

- `npm ls --all mongoose`로 확인하고 각 계열의 수정 버전으로 올립니다.
- 바로 못 올리면 `mongoose.set('sanitizeFilter', true)`로 전역에 켜고, 권고의 `countDocuments` 전처리 미들웨어를 넣습니다.

### ⑪ [P2] Git — 재귀 clone 원격 코드 실행 등 보안 릴리스 6건

Git이 2.50.2부터 2.56.1까지 유지 보수 버전 7개를 한꺼번에 내고 CVE 6건을 고쳤습니다. 개발자 PC에 가장 직접 닿는 것은 CVE-2026-111760입니다. 악성 저장소를 `--recurse-submodules`로 clone하면 submodule의 gitfile이 심볼릭 링크로 바뀌고, 그 링크가 가리키는 설정이나 훅의 코드가 실행됩니다(GitHub 심각도 High, CVSS 8.0).

나머지는 ⑩의 병합 힙 오버플로, 서버가 알려 준 unborn HEAD 이름의 경로 조작으로 엉뚱한 파일에 ref를 쓰는 문제, 서명이 세 개 이상인 커밋 메시지의 스택 메모리 손상, 압축된 바이너리 패치의 범위 밖 읽기, `fast-import` 옵션의 임의 경로 읽기입니다.

> 모르는 저장소를 `--recurse-submodules`로 받는 일이 있다면 Git을 각 계열의 수정 버전으로 올려야 합니다.

신뢰하는 저장소만 다루면 위험이 작습니다. CI 러너와 개발자 PC의 Git 모두 해당합니다.

## 10. 미확인 보도·루머
