### 1. `@anthropic-ai/sdk` 1.9.0 — 스트리밍 도구 입력 검사 강화, 에이전트 도구 보안 수정

11월 17일 01:53 KST(npm 게시)에 TypeScript SDK 1.9.0이 나왔습니다. 가장 큰 변화는 스트리밍 도구 입력 파서입니다. 지금까지는 주석이나 JSON이 아닌 단어를 건너뛰고 `12 3` 같은 숫자를 이어 붙여, 원문에 없는 값을 돌려줄 수 있었습니다. 이제 이런 입력은 거부하고 스트림이 오류로 끝납니다. 올바른 JSON과 중간에 잘린 JSON은 예전처럼 파싱됩니다.

에이전트 도구 묶음(agent toolset)에는 보안 수정이 여럿 들어갔습니다. 도구가 쓸 수 있는 폴더(`workdir`, `allowedRoots`) 안에 있는 `rg`, `tar`, `unzip`은 더 이상 실행하지 않고, 현재 폴더에서도 찾지 않습니다. 이 실행 파일에는 `ANTHROPIC_*` 환경 변수를 넘기지 않으며, Windows 경로 비교와 깨진 심볼릭 링크 경로 처리도 고쳤습니다. 압축을 푼 스킬 파일 권한은 `0644`(실행 비트가 있으면 `0755`)로 맞춥니다.

API 쪽에는 Claude Tag Bundle 지시문을 바꾸는 Update Bundle과 RBAC Role 조회의 오류 코드가 추가됐습니다.

> NestJS 서비스에서 스트리밍으로 도구 호출을 받는다면, 1.9.0으로 올린 뒤 스트림 오류를 잡아 재시도하거나 사용자에게 알리는 경로가 있는지 확인하세요. 에이전트 도구 묶음으로 `setupSkills`를 쓰는 서버라면 작업 폴더 밖에 `tar`·`unzip`이 설치돼 있어야 스킬을 내려받습니다.

### 2. Claude Code 2.1.326 — 도구 허용 목록 경고, 설정 저장 실패 알림

11월 17일 03:43 KST(npm 게시)에 Claude Code 2.1.326과 Agent SDK 0.3.326이 나왔습니다. `--allowedTools`, `--disallowedTools`, `--tools` 값에 완전한 규칙으로 보이지 않는 항목이 있으면 시작할 때 경고합니다.

권한 관련 수정도 많습니다. `/permissions`나 도구 확인 창에서 추가한 규칙이 설정 파일에 써지지 않았는데 저장된 것처럼 보이던 문제를 고쳐 이제 경고와 파일 이름을 보여 줍니다. 세션 도중 오류가 있는 설정 파일을 저장하면 알림 없이 건너뛰던 것도 경고로 바뀌었습니다. `find -delete`, `cat a > b`, `sort -o`처럼 파일을 지우거나 덮어쓰는 명령이 기록에 검색·읽기로 요약되던 문제와, `Edit` 거부 규칙이 원본에만 걸린 파일의 `cp`가 거부되던 문제도 고쳤습니다.

| 추가 항목 | 내용 |
|---|---|
| `OTEL_RESOURCE_INCLUDE_HOST` | OpenTelemetry 리소스 속성에 `host.name`, `host.id` 포함 (기본 꺼짐) |
| `/status` | 제공자나 `DISABLE_TELEMETRY` 같은 환경 변수가 끈 기능 표시 |
| `managed-mcp.json` | 세션 중 관리자가 추가해 MCP 서버가 멈출 때 이유 안내 |
| 관리형 설정 | 관리형 PreToolUse 훅이 도구 호출을 거부할 때도 `tool_decision` 이벤트·`permission_denials` 기록 |

> CI나 스크립트에서 `--allowedTools "Bash(npm test)"` 같은 값을 넘긴다면 다음 실행 로그에 새 경고가 뜨는지 보세요. 경고가 뜨면 그 규칙은 의도대로 적용되지 않고 있었습니다.

- 발표: 2026-11-16(미국 날짜) · [Claude Code 변경 이력](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

## 주목할 Agent Skills

skills.sh 전체 순위에서 이전 보고에서 다루지 않은 상위 스킬 가운데, 백엔드 개발자가 API·웹 화면 검증에 바로 쓸 만한 브라우저 자동화 스킬을 골랐습니다.

### `agent-browser` (vercel-labs/agent-browser)

AI 에이전트가 Chrome·Chromium을 CDP로 직접 조작하게 해 주는 CLI용 스킬입니다. 페이지를 접근성 트리 스냅샷과 `@eN` 형태의 짧은 요소 참조로 보여 줘, 에이전트가 적은 토큰으로 클릭·입력·스크린샷·데이터 추출을 할 수 있습니다.

`SKILL.md` 자체는 안내용 껍데기입니다. 실제 사용법은 설치한 CLI 버전에 맞춰 `agent-browser skills get core`로 불러오고, Electron 앱, Slack, 탐색형 QA(dogfood), Vercel Sandbox, AWS Bedrock AgentCore용 하위 스킬도 같은 방식으로 불러옵니다. Playwright나 Puppeteer 없이 Rust로 만든 CLI가 동작합니다.

| 항목 | 값 |
|---|---|
| 설치 수 | 1.6M (확인 2026-11-17 08:46 KST, skills.sh 표시값) |
| 처음 등록 | 2026-01-19(skills.sh 첫 확인일), 신규 아님 |
| 보안 감사 | Gen Agent Trust Hub·Socket Pass, Snyk Warn (경고 내용은 확인 불가) |
| CLI 최신 버전 | `agent-browser` 0.43.0 (npm, 2026-11-13 게시) |

- 원문: [skills.sh](https://skills.sh/vercel-labs/agent-browser/agent-browser) · [SKILL.md](https://github.com/vercel-labs/agent-browser/blob/main/skills/agent-browser/SKILL.md)
- 설치: `npx skills add https://github.com/vercel-labs/agent-browser --skill agent-browser`
- CLI 설치(SKILL.md 기준): `npm i -g agent-browser && agent-browser install`

> NestJS 서버를 고친 뒤 관리자 화면이나 Swagger UI에서 실제 흐름을 에이전트가 직접 눌러 확인하게 할 때 쓸 만합니다. `allowed-tools`가 `Bash(agent-browser:*)`라 모든 하위 명령이 허용되고, 인증 저장소·쿠키·JavaScript 실행·Slack 메시지 전송까지 다루니 운영 계정으로 로그인된 브라우저 프로필에는 붙이지 마세요. 설명에 "다른 브라우저 도구보다 우선 쓰라"는 문구가 있어, 이미 Playwright MCP를 쓰는 환경에서는 어느 쪽이 불릴지 정해 두는 편이 좋습니다.
