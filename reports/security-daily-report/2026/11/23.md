## 4. AI·개발 도구

### ② [P2] DBHub — 읽기 전용 모드에서 쓰기·DDL 실행 가능

DBHub는 Bytebase가 만든 DB 연결용 MCP 서버입니다. 읽기 전용 모드에서 `execute_sql`로 들어온 SQL을 검사할 때, 작은따옴표 안의 백슬래시 이스케이프를 잘못 해석했습니다. 그래서 문자열 안에 숨긴 `COMMIT`이나 `transaction_read_only` 해제 같은 문장이 함께 실행돼, MySQL·MariaDB·PostgreSQL 데이터를 고치거나 지울 수 있습니다.

MCP 클라이언트가 보내는 SQL을 조작할 수 있어야 하므로, 에이전트가 읽는 문서·이슈에 섞인 프롬프트 주입이 현실적인 경로입니다. DBHub를 읽기 전용 모드로 쓰는 경우만 해당하고, 처음부터 쓰기를 허용한 설정이라면 이 취약점과 상관없이 같은 위험이 있습니다.

| 영향 버전 | 수정 버전 | 식별번호 | CVSS | KEV·실제 악용 |
|---|---|---|---|---|
| 1.7.0 미만 | 1.7.0 (최신 2.1.0) | CVE-2026-134803 | 8.1 (CVSS 3.1) · 7.2 (CVSS 4.0) | 미등재 · 확인 불가 |

> 읽기 전용 모드만 믿고 운영 DB를 AI 에이전트에 연결했다면, 이 모드가 실제로 막아 주지 못했던 것입니다.

- `@bytebase/dbhub`를 1.7.0 미만으로 쓰고 있다면 올립니다. `npx`로 띄우면 버전을 고정했는지 MCP 설정 파일을 봅니다.
- 바로 못 올리면 DBHub가 쓰는 DB 계정 자체를 읽기 전용 권한(`SELECT`만)으로 바꿉니다. 도구 쪽 제한보다 DB 권한이 더 확실합니다.
