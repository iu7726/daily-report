## 0. TL;DR

아침 보안 리포트는 하루 한 번이라 그 사이 약 24시간이 빈다. 이미 3시간마다 도는 후속 확인 루틴(04)에 **긴급 감시**를 붙여, 핵심 기술의 P1급 새 공지만 확인하고 뜨면 바로 최신 리포트에 덧붙이고 휴대폰으로 알린다. 해당이 없으면 커밋도 알림도 없다.

## 2. 현재 (2026-11-03)

- 04 루틴(Sonnet 5.5, `15 */3 * * *`)은 대기 목록에 예고된 항목만 확인한다. 열린 항목이 없으면 바로 끝난다.
- 아침 리포트 이후 예고 없이 나온 치명적 공지는 다음 날 아침까지 모른다.
- 11-03에 로컬에서 확인한 목록: CISA KEV JSON(`dateAdded`, 날짜 단위), OSV `modified_id.csv`(npm 8.7MB, 최근 수정순이라 앞부분만 받으면 됨)와 `api.osv.dev/v1/vulns/<ID>`(`database_specific.severity`), Node.js 보안 피드(`/en/feed/vulnerability.xml`, 77건, `pubDate`), npm 다운로드 수 API(`api.npmjs.org/downloads/point/last-week/<패키지>`, `next` 주 8,961만, 삭제된 악성 패키지는 not found), AWS Security Bulletins RSS

## 3. 결정 사항

### 확정 (사용자 2026-11-03)

- **D1. 04 루틴에 붙인다.** 새 루틴을 만들지 않는다.
- **D2. 진짜 핵심만 본다**(CVE·KEV, AWS, Node.js 같은 코어). 공지가 뜨면 그 공지만 리포트에 후속으로 덧붙인다.

### 구현 방향

- **D3. 알리는 기준(P1급만)**
  - KEV 신규 등재 중 핵심 제품(Node.js, Next.js, React, DB, GitLab, GitHub, Docker, Kubernetes, nginx, OpenSSL·OpenSSH, Linux 커널, AWS, VS Code, Anthropic·OpenAI 제품)
  - OSV의 `GHSA-` 중 `CRITICAL`이고 최근 2일 안에 공개됐으며, 핵심 npm 패키지(약 30개, 작업 파일 표)나 `actions/*`, 또는 핵심 목록 밖이라도 주간 다운로드 100만 이상인 패키지(사용자와 검토 중 추가, 2026-11-03)
  - OSV의 `MAL-` 중 주간 다운로드 10만 이상인 기존 인기 패키지(계정 탈취·변조 배포). 새로 만든 사칭 패키지는 알리지 않는다(아침 리포트가 다룬다).
  - Node.js 보안 릴리스가 실제로 나왔고 High 이상 포함. 예고 글이면 알리지 않고 대기 목록에 올린다.
  - 핵심 AWS 서비스에 영향이 있고 고객 조치가 필요하거나, 실제 악용이 확인된 AWS 공지
- **D4. 조사 기간 3시간 30분**: 회차 간격 3시간에 시작 지연 여유 30분. 마지막 확인 시각을 저장하지 않는다. 저장하면 3시간마다 커밋이 쌓인다.
- **D5. 중복 방지**: `watch/watchlist.json`에 `alerted` 목록을 새로 두고, 알린 식별번호(CVE, GHSA, MAL, AWS 공지 번호)를 남긴다. `alerted`에 있거나 최근 보안 리포트 두 개에 이미 나온 식별번호는 건너뛴다. 아침 리포트가 다룬 것을 다시 알리지 않는다.
- **D6. 덧붙이는 형식**: 최신 보안 리포트의 `기준 시각:` 줄 다음에 `## 긴급 감시 (MM-DD HH:mm KST) — <제목>` 절(요약, 영향 범위, 값 표, 조치, 원문)을 넣고 `level`을 `urgent`로 올린다. 사이트 목차에 그대로 보인다. 알림은 `[보안 긴급] <제목> · <한 줄 요약>`.
- **D7. 실패 처리**: 목록 조회에 실패하면 그 목록은 건너뛰고, 실패만 있었으면 커밋하지 않는다.
- **D8. 비용**: 해당이 없으면 목록 몇 개를 받아 거르고 끝난다. Sonnet으로 1~2분, 하루 8회로 본다. 시험 실행에서 실제 시간을 적는다.

### 한계 (2026-11-03 사용자와 검토)

- 지연은 길어야 3시간 남짓(회차 간격 + 시작 지연 8~9분 + 출처 반영 지연)이다. 몇 분 단위 실시간은 아니다.
- KEV는 실제 악용 확인 뒤 등재라 벤더 발표보다 몇 시간~며칠 늦다. 같은 사건은 Critical 권고 경로가 먼저 잡는 경우가 많다.
- 목록에 안 올라오는 사고(IDE 확장 변조, CI 토큰 탈취 캠페인)는 긴급 감시 대상이 아니고 다음 날 아침 리포트가 잡는다. 3시간마다 판단시키면 오탐과 비용이 커진다.
- 루틴 실행이 실패한 회차는 알림 없이 지나간다. 다음 회차와 아침 리포트가 다시 본다.

## 5. 케이스

- U1. 아무 일 없음 → 커밋·알림 없음
- U2. 핵심 패키지 Critical 권고 → 최신 리포트에 긴급 감시 절, `alerted` 추가, 알림
- U3. 다음 회차가 같은 권고를 또 봄(조사 기간 겹침) → `alerted`에 있어 건너뜀
- U4. 아침 리포트가 이미 다룬 KEV → 리포트에 식별번호가 있어 건너뜀
- U5. 다음 날 아침 리포트 → 전날 리포트의 긴급 감시 절을 이전 보고로 읽고, 아직 조치 기간이면 긴급 조치 요약에 한 줄로 상기
- U6. Node.js 보안 릴리스 예고 → 알림 없이 대기 목록에 등록, 실제 릴리스 때 후속 확인으로 알림
