# 물결표 취소선 — 기획서

> 상태: **구현·검증 완료 (2026-11-03)**. 배포 `v0.0.11`
> 남은 것: 없음

## 0. TL;DR

시간·날짜 범위의 물결표(`02:27~13:35`)가 한 줄에 두 번 나오면 그 사이가 취소선으로 보였다(사용자 2026-11-03). 사이트는 물결표 하나로는 취소선을 만들지 않게 하고, 루틴은 범위 물결표를 띄어 쓰게 한다.

## 2. 현재 (2026-11-03)

- `remark-gfm`은 기본값(`singleTilde: true`)이 물결표 하나로 감싼 것도 취소선으로 처리한다.
- 빌드된 사이트에서 7개 페이지, 취소선 10개. 보고서 원문에 `~~`는 0건이라 10개 모두 의도하지 않은 것이다(예: `20:35 UTC(18:27~05:35 KST)`).
- GitHub의 Markdown 화면도 물결표 하나를 취소선으로 처리한다.

## 3. 결정 사항

- **D1.** 사이트: `remark-gfm`에 `singleTilde: false`. 본문(`Markdown.tsx`)과 목차(`lib/headings.ts`)가 같은 설정(`lib/markdown.ts`)을 쓴다. 표준 문법인 `~~두 개~~`는 그대로 둔다. 지난 보고서는 고치지 않아도 바로 정상으로 보인다.
- **D2.** 루틴 글쓰기 규칙: 범위 물결표는 앞뒤를 띄어 쓴다(`09:00 ~ 12:00`). 띄어 쓴 `~`는 어떤 Markdown 화면에서도 취소선 기호로 읽히지 않아 GitHub에서도 안전하다. 취소선(`~~`)은 쓰지 않는다.
- **D3.** 지난 보고서 원문은 고치지 않는다(기록 보존). GitHub 화면에서는 여전히 일부가 취소선으로 보인다.
