### 1. OpenAI GPT-6.2 Astra·Sol 출시 — 매개변수 정리 필요, 도구 호출은 Responses API만

OpenAI가 11월 17일(미국 날짜) API 변경 이력에 GPT-6.2 Astra와 GPT-6.2 Sol을 올렸습니다. Astra는 어려운 추론·코딩용, Sol은 일상 코딩과 에이전트 작업용입니다. 둘 다 Responses API와 Chat Completions에서 쓸 수 있지만, 도구 호출은 Responses API에서만 됩니다.

| 항목 | `gpt-6.2-astra` | `gpt-6.2-sol` |
|---|---|---|
| 입력 / 캐시 입력 / 출력 (100만 토큰) | $8 / $0.40 / $40 | $2 / $0.10 / $10 |
| 캐시 쓰기 (30분 보관) | $10 | $2.50 |
| 컨텍스트 / 최대 출력 | 1,050,000 / 128,000 | 1,050,000 / 128,000 |
| 지식 기준일 | 2026-05-18 | 2026-06-01 |

마이그레이션 안내에 따르면 Chat Completions에서는 `temperature`, `top_p`, `logprobs`, `top_logprobs`를, Responses에서는 `temperature`, `top_p`, `top_logprobs`를 빼야 합니다. 추론 강도는 `medium`부터 시작하고, `none`·`minimal`을 쓰던 연동은 `low`로 옮기라고 합니다. GPT-5.5 이하에서 옮긴다면 `prompt_cache_retention`을 `prompt_cache_options.ttl`(`"30m"`)로 바꿔야 합니다.

API는 대화 앞부분이 수정되거나, 더 낮은 모델로 바꾸거나, 최종 사용자·조직이 바뀌면 이전 추론 항목을 버립니다. 그러면 답의 품질이 떨어지고 토큰을 더 씁니다.

같은 날 Responses API 공개 베타에 2시간·8시간 백그라운드 완료 창이 생겼습니다. 표준보다 토큰 단가가 각각 30%, 40% 낮고 GPT-6.2 Astra·Sol, GPT-6.1 Terra, GPT-6 Luna를 지원합니다. `openai` Node SDK 7.58.0(11월 18일 03:31 KST)에 모델 식별자와 이 창이 들어갔고, 7.59.0(07:54 KST)은 Managed Agents 예산 이벤트 타입을 추가했습니다.

> NestJS 서비스에서 Chat Completions로 함수 호출을 쓰고 있다면 모델 이름만 바꿔서는 GPT-6.2로 옮겨지지 않습니다. Responses API로 바꾸고, 요청에서 `temperature`·`top_p`를 지운 뒤 옮기세요. 몇 시간 늦어도 되는 일괄 요약·분류 작업은 8시간 창으로 돌리면 비용을 40% 줄일 수 있습니다.

- 발표: 2026-11-17(미국 날짜) · [API 변경 이력](https://developers.openai.com/api/docs/changelog) · [GPT-6.2 마이그레이션 안내](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6.2-astra) · [GPT-6.2 Sol 모델 문서](https://developers.openai.com/api/docs/models/gpt-6.2-sol) · [openai-node CHANGELOG](https://github.com/openai/openai-node/blob/master/CHANGELOG.md)

### 2. Claude Code 2.1.327 — `.mcp.json`·`.env` 삭제 버그 수정, `mcp add-json` 표준 입력

11월 18일 05:33 KST(npm 게시)에 Claude Code 2.1.327과 Agent SDK 0.3.327이 나왔습니다. 파일을 잃을 수 있던 버그 두 가지가 고쳐졌습니다. 프로젝트 범위의 `claude mcp add`·`remove`가 `.mcp.json`의 `$schema`나 다른 도구의 `servers` 키를 지우던 문제와, Remote Control 워크트리 모드에서 서버를 멈추면 실행 중인 세션의 `.env` 같은 git 무시 파일이 지워지던 문제입니다.

`claude mcp add-json <name> -`로 서버 JSON을 표준 입력에서 읽을 수 있게 돼, 토큰을 명령줄에 남기지 않아도 됩니다. `/status`는 깨진 에이전트·스킬·명령 파일, 무시된 권한 설정, 일치하는 대상이 없는 훅 매처를 목록으로 보여 줍니다.

| 그 밖의 변경 | 내용 |
|---|---|
| `/export` | 기존 파일을 묻지 않고 덮어쓰던 문제 수정 |
| `claude -p` | 모델 설정 조회가 멈추면 10초 뒤 진행 (프록시 환경 멈춤 해결) |
| 프록시 | `HTTPS_PROXY`가 `host:port` 형태이고 터미널이 아닐 때(SDK, cron) 시작이 안 되던 문제 수정 |
| 원격 MCP | VPN 끊김 같은 긴 장애 뒤 하루 정도 백그라운드 재연결 |
| WebFetch | 2,000자가 넘는 URL은 권한 확인 전에 거부 |
| `--disallowedTools` | 괄호가 들어간 일부 규칙 처리 수정 |

> 저장소의 `.mcp.json`에 다른 도구 설정을 함께 두고 `claude mcp add --scope project`를 써 왔다면, 업데이트 후 `git diff`로 지워진 키가 없는지 확인하세요. CI에서 MCP 서버를 등록할 때는 `echo "$JSON" | claude mcp add-json <name> -` 방식으로 바꾸면 토큰이 프로세스 목록에 남지 않습니다.

- 발표: 2026-11-17(미국 날짜) · [Claude Code 변경 이력](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

### 3. `@anthropic-ai/sdk` 1.10.0 — Linked billing 베타, 종료된 세션의 도구 실행 차단

11월 18일 03:35 KST(npm 게시)에 TypeScript SDK 1.10.0이 나왔습니다. 같은 날 Claude Platform이 Linked billing을 베타(`user-profiles-billing-2026-10-01` 헤더)로 열었습니다. 고객이 자기 Claude 조직을 앱에 연결하면, `/v1/messages`나 `/v1/chat/completions` 요청마다 `billing_policy`로 누가 비용을 낼지 정합니다. SDK에는 이 매개변수와 `contract_spend_limit_reached` 같은 결제 관련 오류 코드가 추가됐습니다.

도구 실행 쪽 수정도 있습니다. 세션 도구 러너와 `EnvironmentWorker`가 이미 종료된 세션의 도구 호출을 실행하던 문제를 고쳤고, 종료된 세션에서 `SessionMemoryError`를 던지지 않습니다. 오류 데이터 모델 이름이 바뀌어 예전 이름은 사용 중단(deprecated) 표시가 붙었습니다.

> 고객사별로 Claude 비용을 받는 B2B 백엔드라면 Linked billing으로 정산 구조를 단순하게 만들 수 있는지 검토해 볼 만합니다. 오류 처리 코드가 예전 오류 모델 타입 이름을 직접 가져다 쓰고 있다면 1.10.0에서 사용 중단 경고가 나오니 새 이름으로 바꾸세요.

- 발표: 2026-11-17 · [CHANGELOG](https://github.com/anthropics/anthropic-sdk-typescript/blob/main/CHANGELOG.md) · [Claude Platform 릴리스 노트](https://platform.claude.com/docs/en/release-notes/overview)

### 4. GitHub Copilot — GPT-6.2 추가, 코드 변경 시크릿 검사 미리 보기, MAI-Code-1.1-Flash 12월 종료

Microsoft Ignite에 맞춰 GitHub가 11월 17일 Copilot 소식을 15건 올렸습니다. GPT-6.2 Astra·Sol이 Pro+, Max, Business, Enterprise에 순차 배포되고, 사용량 기반 요금제에서 제공사 정가로 과금됩니다. Business·Enterprise는 관리자가 막지 않았다면 자동으로 켜집니다.

Copilot 보안 리뷰가 GitHub 시크릿 스캐닝 탐지기(500종 넘는 형식)를 함께 돌리는 기능이 공개 미리 보기로 나왔습니다. 기본은 꺼져 있고, Copilot CLI에서는 `/settings aiSecretDetection on`으로 켠 뒤 `/security-review`로 실행합니다. 변경된 코드만 보고 저장소 기록은 검사하지 않으며, AI 크레딧을 씁니다. Copilot 코드 리뷰에는 PR 크기와 위험도에 따라 검토 깊이를 고르는 Adaptive effort가 미리 보기로 들어갔습니다.

MAI-Code-1.1-Flash는 12월 18일 모든 Copilot 환경에서 종료되고, 대체 모델은 MAI Code 2 Flash입니다.

> Copilot 에이전트가 커밋을 만드는 저장소라면 저장소 설정의 Copilot → Code review → Security에서 시크릿 검사를 켜 두면, 에이전트가 `.env` 값을 코드에 붙여 넣는 실수를 병합 전에 잡을 수 있습니다. MAI-Code-1.1-Flash를 지정한 자동화가 있다면 12월 18일 전에 바꾸세요.

### 5. Vercel AI SDK `ai` 7.0.174 — UI 메시지 검증 메모리 소진 수정

11월 18일 03:41 KST(npm 게시)에 `ai` 7.0.174가 나왔습니다. `validateUIMessages`, `safeValidateUIMessages`와 에이전트 UI 스트림 헬퍼가 깊게 중첩된 `providerMetadata`·`toolMetadata`를 검사할 때 값의 몇 배 메모리를 쓰던 문제를 고쳤습니다. 그래서 올바른 형식의 요청 하나로도 모델을 부르기 전에 워커 메모리가 바닥날 수 있었습니다. 이제 한 번에 검사하고 값을 복사하지 않으며, `__proto__` 키만 제거합니다.

`streamText`가 도구가 없을 때 `experimental_transform`에 `tools: undefined`를 넘기던 문제도 고쳤고, `startBatch`에서 `output`을 지원합니다. 6.x는 6.0.333, 5.x는 5.0.291로 같은 날 함께 갱신됐습니다.

> 클라이언트가 보낸 UI 메시지를 서버에서 `validateUIMessages`로 검사하는 Node 백엔드라면 7.0.174 이상으로 올리세요. 업데이트 전에는 요청 본문 크기 제한을 두는 것이 임시 방어책입니다.

|---|---|
| 설치 수 | 4.4M (확인 2026-11-18 08:45 KST, skills.sh 표시값) |
| 처음 등록 | 2026-01-26(skills.sh 첫 확인일), 신규 아님 |
| 보안 감사 | Gen Agent Trust Hub·Socket Pass, Snyk Warn (경고 내용은 확인 불가) |

- 원문: [skills.sh](https://skills.sh/vercel-labs/skills/find-skills) · [SKILL.md](https://github.com/vercel-labs/skills/blob/main/skills/find-skills/SKILL.md)
