## 6. 데이터베이스

### ⑦ [P2] MongoDB Node.js 드라이버 — SRV 응답의 특수 문자로 다른 호스트에 연결

`mongodb+srv://` 연결에서 드라이버는 DNS SRV 응답의 호스트 이름이 연결 문자열의 도메인에 속하는지 확인합니다. 그런데 실제 접속 주소는 원래 이름으로 다시 만들고, 이때 특정 문자에서 호스트 이름이 끊깁니다. SRV 응답을 위조하거나 바꿀 수 있는 공격자는 연결을 원하는 호스트로 돌릴 수 있고, 인증서도 바뀐 호스트 이름으로 검증하므로 TLS로 막히지 않습니다(CVE-2026-126837).

MongoDB는 애플리케이션 데이터와 인증 정보가 새고 쿼리 결과가 바뀔 수 있다고 밝혔습니다. 다만 DNS 응답을 조작할 수 있는 위치에 있어야 합니다. 같은 날 OIDC 인증에서 허용 호스트 제한이 일관되게 적용되지 않아 로그인 콜백의 토큰이 다른 호스트로 갈 수 있는 결함(CVE-2026-126835)도 공개됐습니다.

> Atlas처럼 `mongodb+srv://`로 접속하는 Node.js 앱은 `mongodb` 7.8.0 이상으로 올려야 하고, OIDC 인증을 쓴다면 7.9.0 이상이 필요합니다.

`mongodb://` 연결 문자열을 쓰는 앱은 CVE-2026-126837에 해당하지 않습니다. `mongoose`는 내부에서 `mongodb` 드라이버를 쓰니 함께 확인합니다.

| 영향 버전 | 수정 버전 | 식별번호 | CVSS | KEV·실제 악용 |
|---|---|---|---|---|
| 3.3.3 이상 7.8.0 미만 (SRV) / 6.7.0 이상 7.9.0 미만 (OIDC) | 7.8.0 / 7.9.0 (6.x 이하 수정판 확인 불가) | CVE-2026-126837, CVE-2026-126835 | 9.1 (CVSS 4.0, 3.1은 7.4) / 5.9 | 미등재 · 확인 불가 |

- `npm ls --all mongodb mongoose`로 실제 설치된 드라이버 버전을 확인합니다.
- 6.x를 쓰고 있다면 7.x로 올릴 수 있는지 확인하고, 그 전까지는 신뢰하는 DNS 리졸버만 쓰는지 점검합니다.

### ⑧ [P2] PostgreSQL — 11월 보안 릴리스 CVE 52건 NVD 등록

어젯밤 긴급 감시로 알린 PostgreSQL 11월 12일 릴리스의 CVE가 오늘 00:17 KST에 NVD에 한꺼번에 올라왔습니다. 보안 페이지 기준 52건이고, 그중 32건이 CVSS 8.8입니다. 대부분은 객체를 만들 수 있는 DB 사용자가 타입 혼동이나 해제 후 사용으로 DB를 실행하는 OS 사용자 권한의 코드를 실행하는 결함입니다.

서버 코어가 43건, `pg_dump`·`vacuumdb`·`reindexdb` 같은 클라이언트 도구가 6건, 확장 모듈이 3건입니다. 인증 없이 일으킬 수 있는 것은 시작 처리 중 서버 재시작(CVE-2026-116322, 5.3) 하나이고, `pg_dump`의 SQL 주입(CVE-2026-116318)은 덤프를 복원하는 사람의 권한으로 SQL이 실행됩니다.

> 여러 사용자나 서비스가 객체를 만들 수 있는 PostgreSQL을 운영한다면 이번 주 안에 각 계열의 최신 마이너 버전으로 올려야 합니다.

DB 사용자가 애플리케이션 계정 하나뿐이고 그 계정을 신뢰한다면 위험은 낮습니다. RDS·Aurora는 AWS가 새 마이너 버전을 제공하는 시점을 따로 확인해야 합니다(오늘 아침 기준 AWS 공지 없음).

| 영향 버전 | 수정 버전 | 식별번호 | CVSS | KEV·실제 악용 |

## 7. 공급망·CI/CD·인프라

### ⑨ [P1] GitHub Actions — 탈취한 계정으로 CI 비밀 값 탈취 스크립트를 넣는 wfx 캠페인

11월 10일부터 탈취된 GitHub 계정·봇 토큰으로 쓰기 권한이 있는 저장소에 약 1,500줄짜리 셸 스크립트를 넣는 캠페인이 진행 중입니다. 먼저 `wfx-docs` 브랜치에서 `docs: dependency audit notes` PR을 열어 권한을 확인하고, 기존 워크플로에 단계를 덧붙이거나 `package.json`에 `postinstall` 훅을 넣은 뒤 1분 안에 되돌리고 워크플로 실행 기록까지 지웁니다. GitHub Actions의 버그가 아니라 유효한 토큰을 그대로 쓴 공격입니다.

스크립트는 `toJSON(secrets)`로 저장소 비밀 값 전체, `GITHUB_TOKEN`, 러너 프로세스 메모리, AWS·Azure·GCP·npm·SSH·AI 제공사 자격 증명 파일을 모아 외부 서버나 Telegram으로 보냅니다. GitHub OIDC로 클라우드 세션을 얻어 AWS 역할 신뢰 정책을 모든 주체에 열고 IAM 키를 만들며, Azure에 `wfx-ci-*` 연동 자격 증명을 남깁니다.

GitHub 검색으로 직접 확인하니 `docs: dependency audit notes` 제목의 PR이 68,351건(그중 59,279건 열림), 11월 9일 이후 `ci: refresh build cache` 커밋이 31,070건입니다. Aikido는 계정 4,837개, 페이로드가 실행된 저장소 최소 1,835개로 집계했습니다. GitHub의 공식 발표는 확인하지 못했습니다.

> 내 계정과 조직의 저장소에 아래 흔적이 하나라도 있으면 그 저장소의 Actions 비밀 값과 클라우드 역할을 모두 교체하고, 커밋을 올린 계정의 토큰을 폐기해야 합니다.

흔적이 없는 저장소는 해당하지 않습니다. `postinstall` 변형은 그 저장소를 클론해 `npm install`한 개발자 PC도 침해 대상으로 봐야 합니다. 확인된 패키지 피해는 Packagist `digitalelvis/neuronai-studio` 3.14.3과 Go 모듈 2개이고, npm 패키지 변조는 아직 보고되지 않았습니다.
